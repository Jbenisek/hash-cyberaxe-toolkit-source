# A8: two-block final chunk, h = CV(P) in place of the IV (ANGLES.md section 8). Verdict: CLOSED

Files: a8.py (the test), run_2p25.log (output), a8_result.json (each case). Windows Python 3.14 + numpy, CPU only, 12 min.

## Where h enters (DERIVED, from reading the code)
- The class counter (pkg17\count\count_class.py) takes Y3, Y3B, Y11, Y11B, delta, eta and the class. All of these are
  round-1 G3 values computed from the pins X3, X7, X11, X15, W4, W13 and from W4B. Its Fact P constants are equal to
  outer.py's g(X3, X7, X11, X15, W4/W4B, W13) (checked).
- h reaches the counter through one bit only: W4B = ((W4 + h2 + h6) ^ 55 ^ 63) - h2 - h6 = W4 + 8 when bit 3 of
  W4 + h2 + h6 is 0, and W4 - 8 when it is 1. This held in 100,000 of 100,000 random draws (MEASURED).
- So on that half of h the counter's input is bit-identical to the IV case: the class part has spread 0 (DERIVED).
  The other half is a different round-1 instance (delta -8). That is a re-pin, not a tunable, and it was not tested.
  A draw that fails the bit costs about one extra compression (DERIVED).
- The stage-1 path (outer.py, the lines that reach Y9 and w8: 64 lines) reads h1, h3+h7, h4, h5, h6 and h2+h6
  through K3, K1, K0 and K2 (a and b slots). The c slots stay IV0..IV3. Flags go from 3 to 2. The a-slot words are
  not fully absorbed: for example h1 + h5 moves X0 through w2. So the stage-1 rate could depend on h, and it was measured.

## Test (MEASURED)
a8.py rebuilds outer.LINES from h. Checks: lines_for(IV, 3) == outer.LINES exactly; the vector path against
outer.scalar_outer gives 0 mismatches in 1,000 steps; the table lookups against outer.look give 0 mismatches in 2,000 words.
Each case runs N = 2^25 uniform outer steps. pass = automaton(1) on Y9 AND automaton(2) on omega (S-masked), as in iter_passes.
For 26 of the 64 draws, bit 3 of h2 was flipped so that W4B = W4 + 8, the same round-1 instance as the IV.

| case | pass share / exact (SHARE/2^64) | E share / exact |
|---|---|---|
| IV, flags 3 (baseline) | 0.9993 | 0.9992 |
| IV, flags 2 | 0.9984 | 1.0013 |
| 64 random h, flags 2: min .. max | 0.9889 .. 1.0107 | 0.9986 .. 1.0016 |
| 64 random h: mean, sd | 1.0007, 0.54% | |
| binomial sd expected at N | 0.55% | |

- The spread (max - min over the mean) is 2.18%, below the 10% bar. The sd of the z-scores is 0.986, and
  chi^2 = 62.3 on 64 dof. No h-dependence is visible above sampling noise.
- DERIVED from the chi^2: the h-dependent sd of the rate is below about 0.3% (95%). GUESS, assuming Gaussian tails:
  the best of 2^50 draws of h gains at most about 2-3%, which is about 0.03 bit. That is less than nothing once the
  draws are paid for.

## Not tested
- The bit-flipped half (delta -8): a new round-1 instance. That needs a new eta, class and taus, which is a re-pin.
- Downstream stages (the solver count V_COUNT, the certificate, and the chunk-counter mover of angle 1) with h in place of the IV.
- A k-length pin set (angle 4) that uses h. The round-1 counter cannot see h, so h cannot widen the class.
