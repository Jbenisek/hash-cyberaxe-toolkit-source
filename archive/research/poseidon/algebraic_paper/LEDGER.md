# Poseidon algebraic attack: exact-structure cost ledger (single thread, no run)

Generated by `ledger.py` (this folder). Source of truth: `research/poseidon/orchard/exec_r6mt` (same code as exec_r4mt/exec_r5mt apart from RR, AMAX, ARENA, NT_MAX). Nothing is measured from a run of the r6/r7/r8 program: leaf charges are parsed from `ntt_kern.h` / `ntt_a3.h`, all control flow is ported from `ntt.c, lean.c, line.c, hgcd.c, common.c, single.c`. The only numbers taken from logs are the stage constants H, I and line setup (identical in the r3, r4, r5 logs) and the observed stage F used in the validation.

## 1. Formula (per trial, T = 1, no thread_control)
Sizes: m = (5^(6+r)-1)/2; N = 3*2^a is the smallest 3*2^a >= 2m-1 (powering plan PN), N' = 3*2^a' >= m+1 (PNp); AMAX = a; H = smallest 2^b or 3*2^b >= m+1 (build_g plan).

`trial = A + B + C + D` (each stage_open charges 1000), plus once per run: init (ntt_init(AMAX): (2^(AMAX-1)-1) twiddle multiplications at 5 ops each + 3*2^(AMAX-1) loop ops + 5*2310 + two fp_pow of the roots + the division by 3), line setup 4,910, E + F + G (last trial), H = 5,644, I = 3,384,436, and one plan_invN miss per distinct plan size.

* **A** = 1000 + 6 + one xalloc.
* **B** (build_g) = 1000 + H*(2*C(r) + 7*a_H + 30) + ntt_inv (rows * inverse passes + stage-A inverse of the radix 3) + 1 field inversion + m multiplications + linear charges of m+1 elements + sqrt(theta) and inverse arithmetic (Tonelli-Shanks evaluated on the real field element). C(r) = 216 + 21 r; 2*C(r) is charged per point as perm units.
* **C** (powx_lean) = Newton reciprocal (a conv_mulc_otf pair per doubling of l) + prefix/scale + steps * S_step + (number of set exponent bits below the prefix) * S_mulx, with steps = 253 - (prefix length) (229 at r5), S_step = conv_sq(PN, m, 2m-1) + conv_mulc_otf(PN, m-1, m-1, gamma, m-1) + conv_mulc_otf(PNp, m-1, m+1, 0, m) + FOLD + COPY + SHIFT + SUB loops (7, 4, 4, 7 ops per element + FOR8 control) + 20. conv_* = Good-Thomas radix-3 stage (region drivers over the nonzero patterns, split_regions) + rows * passes of the radix-2 NTT; every pass is the polynomial in (groups, blocks per group) read from the kernel source (section 8).
* **D** = 1000 + 12 + poly_gcd_own: shape simulation of the half-gcd recursion (hgcd, BASEK = 96, k1 = ceil(k/2)) with apply_inv (conv_bilin_otf), mat_mulQ, mat_mul (naive up to length 48, bilinear above), naive divisions. The simulation follows every allocation (sizes, rounding, headers).

## 2. Assumptions (stated, not proved) and what is exact / bounded
* A1 normal Euclid: every quotient of every gcd step has degree 1. A non-normal step needs a vanishing leading coefficient; probability per step about 1/p, over m steps at most m/p (r6: 2^-227, r8: 2^-222). Not proved for the specific polynomial; the r4 trial rows (398,228,799,447 vs 398,228,796,261 for dG = 0 and 1) support it.
* A2 the table charges dG = 0 for every trial including the last (dG >= 1 is cheaper by about 3,000 ops); the last trial adds E, F, G: E <= 1e8 for dG <= 40 (dG = 1: 1,110; probability dG > 40 below 1/40!), F <= 48,100 (observed 43,682 to 45,122), G = 1000 + 10*2*C(r) + 32 (exact).
* A3 allocator: an xalloc is charged 121 + 13*(2L+1) with L = live blocks at that moment (the walk visits every block; at most 2L+1 exist); an xfree 105; a plan_invN hit 7*64, a miss added once per distinct plan size. These are upper bounds, not a simulation of fragmentation, and are the deliberate slack.
* Exact by construction (read from source): every NTT pass, region driver, linear loop, build_g, the powering schedule, matrix and array sizes. Bounded: allocator walk, plan_invN position, E, F, dG, A1.

## 5. Memory rule
heap_peak = max over stages of (twiddle table + g + F + stage-live set), each array counted as 64 + 32*slots rounded up to 64 B (headers included), from the allocation walk of the same simulation; it reproduces the measured heap_peak exactly at r3 and r5 (all four stage peaks) and within 64 B at r4. Arena rule: ARENA >= 1.177 * (heap_peak + 704) rounded up to 64 (r5t ran with 1.177; r4 with 1.144; r3 with 1.185 on the mt build, while a 1.06 arena failed in stage D of the older r3 build). Touched RSS is about 1.135 x live. This is an empirical rule from r3-r5, not a proof that the arena fits at r7/r8 (fragmentation was not simulated).

## 6. r7 and r8 (the existing program, a <= 31)
r7: a = 29, r8: a = 31 (3*2^31 >= 2m-1 = 6.1e9); both are within the 2-adicity 32 of the Pallas field, so the program runs as written with the numbers above (r8 needs about 0.7 TB of memory). They are paper figures, not executed.

## 7. r9 and above (flagged, not filed)
For r >= 9, 2m-1 exceeds 3*2^32 (the largest transform the field supports), so this program cannot be extended by changing RR: the multiplications would have to be split into blocks (or use another transform), which changes every figure and is not modelled here. Continuing the trend r6 to r8 (about +4.3 score points per round) would reach the generic Poseidon score (127.009) near r22-r23, but that extrapolates an invalid program, is a lower bound on cost, and is not part of this ledger.
