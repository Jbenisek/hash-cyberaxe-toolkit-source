Orchard Poseidon, r = 1 (poseidon-orchard-r1-prefix-v1): one deterministic run on the fixed target, executed operation count, complete source in the proof.

What this entry is. A collision finder for the reduced Orchard hash (eight full rounds and one partial round). It is a single deterministic procedure with no selection step: it tries the centres c_i = i in the fixed public order i = 1, 2, 3, ..., runs each trial completely, and stops at the first trial that yields a collision. It was executed once from the start on the fixed target; it stopped after 1 trials, at c = 1. The claim is the executed cost of that one run, every trial charged, failed ones included: success probability 1 (deterministic procedure executed on the fixed target, every executed trial charged). There is no worst-case bound, no probability theorem and no heuristic premise about the mathematics; the time is the executed operation count and the memory is the executed peak (the maximum over the trials). The one declared premise in the claim file is that the stated charging rules describe the shipped program.

The method in plain terms.
1. After the first full round, the state is an affine image of two free field elements (U, V) and one constant. Along a line in the (U, V) plane where one coordinate of the second round's S-box input stays constant, the second round costs no degree: its S-box output is affine in one parameter W. The digest is then a univariate polynomial F(W) of degree 5^7 = 78125. The line contains exactly p inputs, one for each W in F_p. This is the two-round bypass of Bariant, Bouvier, Leurent and Perrin (ToSC 2022/3).
2. For a centre c, write F(c + s) - F(c - s) = 2 s g(s^2). The polynomial g has degree 39062 and a leading coefficient that does not depend on c (nonzero on this line: proof.md section 2.3, and tested by the program). A root S of g that is a nonzero square gives s = sqrt(S) and two different inputs W1 = c + s and W2 = c - s with the same digest. Working with g (half the degree of F) halves every transform length compared with working with F itself.
3. The program evaluates the digest at 98304 points (each charged as one full target compression, 237 operations), interpolates g with one inverse transform of length 49152, computes S^((p-1)/2) mod g with a low-memory transform schedule (238 Barrett squarings on 3 * 2^k transforms), and takes gcd(g, S^((p-1)/2) - 1) with a half-gcd. A trial whose gcd is constant has no useful root and is charged in full; the first trial with a root of g that is a nonzero square has its root isolated, square-rooted, mapped back, and both inputs are checked with the reference hash. The run ends there with the collision.

Numbers. time_log2 24.95135 (the executed run: N = 7,688,690,654 primitive operations = 32,441,732.7 target-compression units at 237 operations per unit), memory 9,372,932 bytes (log2 23.161), normalized cost 28.11235, success probability 1, preprocessing 0 (the twiddle table is built inside the run and counted in N), 1 trials. One squaring step of the powering costs 27,267,278 operations. One verified collision is included as a certificate; it is the output of this run, and it was checked with an independent big-integer implementation of the reduced hash and with the organizer's digest function.

How the accounting works. Every figure is a counter of the same single execution of the shipped source: field operations, 256-bit loads and stores with one address operation each, loop control at 3 operations per iteration plus 2 on exit for every loop that is not written out straight-line, other control operations, and 237 operations for each reduced permutation evaluation. Nothing is bounded or extrapolated, and no other run enters the count. The half-gcd is charged at what it executed (1,121,430,649 operations over all trials). Montgomery conversions are one field multiplication each, wherever they occur (the centre, the inputs of the reference hashes, the output). The output itself is part of the run and inside the total: stage H converts the two pairs, the digest and the centre to canonical form and encodes them as hexadecimal text, 12 operations per digit; stage I charges the formatting of the whole report (an upper bound of 256 operations per byte for the full 8,192-byte output buffer, 2,097,152), the single write system call (10,000 + 8 per buffer byte), the single exit system call (10,000), the loops of the report, the bookkeeping of the stages (1,000 per stage) and the entry code. The allocator is charged load by load, store by store, comparison by comparison, inside the stages that call it.
Loops. The loops that are genuinely unrolled in the source are the ones written with the macro FOR8 (eight copies of the body per pass, charged 3 per pass of eight; sites in ntt.c: 8, lean.c: 5) and the generated transform kernels (ntt_kern.h, ntt_big.h, ntt_a3.h), whose butterflies, loads, stores and radix-3 position kernels are straight-line code. Every other loop is a real loop and is charged per iteration, with the address operation of each load and store.
Memory. The executable is linked statically and without any C library (a small runtime, nolibc.c, supplies the entry code, the two system calls write and exit_group, memcpy/memset and the report printing); its whole image is counted: 9,307,396 bytes (text, data and bss). The heap is inside that figure: every buffer comes from one static arena of 8,734,400 bytes in the bss (a first-fit allocator with a 64-byte header per block and merging of free neighbours; no mmap and no munmap), exactly the extent the run needed (8,734,400 bytes). At the peak of use there were 12 blocks, payload 8,477,184 bytes, headers 768 bytes (8,477,952 bytes in use), in the half-gcd stage. A stack bound of 65,536 bytes completes the total (the run was executed under a 64 KiB stack limit). The largest live set of the powering is the transform buffer (3 x 2^15 elements), one transform row, the Barrett inverse, the modulus, the result and the twiddle table. The pages the kernel maps outside the executable image (vdso, vvar, page tables) are the kernel's memory. Cross-check: the maximum resident set of the run measured with GNU time was 9,064,448 bytes.

Scope of the claim. Nothing was selected beforehand: the centres are 1, 2, 3, ... in that order, the run was made once, and no earlier run of any centre is left out of N. The probability 1 is the statement about this executed run; it says nothing about how many trials another sequence of centres would need (each centre has roughly a 39 percent chance of yielding a usable root). The organizer did not run the program, so the counts rest on the shipped source. The report, its formatting and its one write call, and the allocator, are charged inside the total as stated above. The meter that records the charges (the counter increments) is how the rules are applied and is not a step of the program. The one structural assumption of the cost model is a declared register file: 18 words of 256 bits per block for the small transforms, and 264 words (256 data words of one block and 8 working words) for the transforms of 2^12 to 2^15 points, which run in two passes; that file is allocated from the counted arena and is part of the memory figure.

Reasoning narrative.
Context. Judged entries on this board for the same line of attack charge the executed run of a deterministic procedure on the fixed target with success probability 1. This entry follows that convention for the r = 1 target, with the odd-part variant of the line polynomial, which halves the degree and therefore the transform sizes and the memory.
Approach. Fix the order of the centres, run the procedure once from the first centre until it stops, and report its counters: the powering is the largest term, the half-gcd second, the evaluation of the line third.
Trade-offs. The executed run is much cheaper than a worst-case charge, in exchange for a claim that is the cost of this run rather than a probability, which the proof says in so many words. The powering keeps its spectra out of memory (they are regenerated row by row), which costs time and saves memory.
Implementation. Reused: the finite-field code, the transform engine, the low-memory powering and the half-gcd of earlier work with shared transforms and a one-pass base case, under the full loop and address rule (an address operation for every load and store, 3 per loop iteration and 2 per loop exit); new for this entry: the fixed order of centres with every trial charged, a single finite guard (MAXTR = 64 trials; the recorded run has 1 trial(s), so the guard is not reached and adds no operation; if it were reached the program would exit with status 2 and no collision), the gap-free stage chain with one printed total, the counted output stage, and the measured memory footprint of a statically linked executable without a C library.
Results. The run stopped with a collision that the organizer's hash accepts; the counters are in the table above.
Next steps. A cheaper powering schedule, or a cached transform of the modulus at a cost in memory, would lower the executed count directly.
