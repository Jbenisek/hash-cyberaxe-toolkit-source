Orchard Poseidon, r = 4 (poseidon-orchard-r4-prefix-v1): one deterministic run on the fixed target, executed operation count, complete source in the proof.

What this entry is. A collision finder for the reduced Orchard hash (eight full rounds and four partial rounds). It is a single deterministic procedure with no selection step: it tries the centres c_i = i in the fixed public order i = 1, 2, 3, ..., runs each trial completely, and stops at the first trial that yields a collision (the source caps the search at 64 trials, a cap this run did not reach). It was executed once from the start on the fixed target; it stopped after 2 trials, at c = 2. The claim is the executed cost of that one run, every trial charged, failed ones included: success probability 1 (deterministic procedure executed on the fixed target, every executed trial charged). There is no worst-case bound, no probability theorem and no heuristic premise about the mathematics; the time is the executed operation count and the memory is the executed peak (the maximum over the trials). The one declared premise in the claim file is that the stated charging rules describe the shipped program.

The method in plain terms.
1. After the first full round, the state is an affine image of two free field elements (U, V) and one constant. Along a line in the (U, V) plane where one coordinate of the second round's S-box input stays constant, the second round costs no degree: its S-box output is affine in one parameter W. The digest is then a univariate polynomial F(W) of degree 5^10 = 9765625. The line contains exactly p inputs, one for each W in F_p. This is the two-round bypass of Bariant, Bouvier, Leurent and Perrin (ToSC 2022/3).
2. For a centre c, write F(c + s) - F(c - s) = 2 s g(s^2). The polynomial g has degree 4882812 and a leading coefficient that does not depend on c (nonzero on this line: proof.md section 2.3, and tested by the program). A root S of g that is a nonzero square gives s = sqrt(S) and two different inputs W1 = c + s and W2 = c - s with the same digest. Working with g (half the degree of F) halves every transform length compared with working with F itself.
3. The program evaluates the digest at 12582912 points (each charged as one full target compression, 300 operations), interpolates g with one inverse transform of length 6291456, computes S^((p-1)/2) mod g with a low-memory transform schedule (231 Barrett squarings on 3 * 2^k transforms), and takes gcd(g, S^((p-1)/2) - 1) with a half-gcd. A trial whose gcd is constant has no useful root and is charged in full; the first trial with a root of g that is a nonzero square has its root isolated, square-rooted, mapped back, and both inputs are checked with the reference hash. The run ends there with the collision.

Numbers. time_log2 33.63159 (the executed run: N = 3,992,419,235,666 primitive operations = 13,308,064,118.9 target-compression units at 300 operations per unit), memory 1,231,371,140 bytes (log2 30.198), normalized cost 43.82959, success probability 1, preprocessing 0 (the twiddle table is built inside the run and counted in N), 2 trials. One squaring step of the powering costs 6,848,029,789 operations. One verified collision is included as a certificate; it is the output of this run, and it was checked with an independent big-integer implementation of the reduced hash and with the organizer's digest function.

How the accounting works. Every figure is a counter of the same single execution of the shipped source: field operations, 256-bit loads and stores with one address operation each, loop control at 3 operations per iteration plus 2 on exit for every loop that is not written out straight-line, other control operations, and 300 operations for each reduced permutation evaluation. Nothing is extrapolated and no other run enters the count; the only bounds are the stated constants of the report, write and exit (stage I) and of the stage bookkeeping. The half-gcd is charged at what it executed (796,457,595,708 operations over all trials; the stage D row adds 2,129 for the stage bookkeeping, the subtraction R - 1, the degree scan and the test of deg G). Montgomery conversions are one field multiplication each, wherever they occur (the centre, the inputs of the reference hashes, the output). The output itself is part of the run: stage H converts the two pairs, the digest and the centre to canonical form and encodes them as hexadecimal text, 12 operations per digit, inside the total.
Loops. The loops that are genuinely unrolled in the source are the ones written with the macro FOR8 (eight copies of the body per pass, charged 3 per pass of eight; sites in ntt.c: 2) and the generated transform kernels, whose butterflies and radix-3 position kernels are straight-line code. Every other loop is a real loop and is charged per iteration, with the address operation of each load and store.
Threads. The counted run used 6 threads (the main thread and 5 workers; the run is single 1 6). The passes of the butterfly transforms, the radix-3 stage, the pointwise and linear loops and the evaluation of the line are split into chunks that the threads take one at a time; every thread counts its own operations and the main thread sums them after each of the 216,710 dispatches, so N is the exact total over all threads. The loop control of a split loop is charged once by the main thread and the iteration bodies by the threads that run them, so the algorithmic count equals the single-thread count digit for digit (checked against the unmodified single-thread program at r = 1, 2 and 3: 3,977,289,295,772 operations in this run). The thread control is charged in addition and tallied: 15,129,788,786 operations (0.38 percent of N): 10,000 per futex or clone system call, 1,000 per worker woken for the kernel's work, and small constants for the hand-over, the chunk scheduling and the summing of the counters (proof.md section 4.5); 151,108 more operations are executed only because loops are split. A waiting worker sleeps in the kernel and executes nothing. Only the main thread allocates, so the arena and the peak are those of the single-thread program.
Memory. The executable is linked statically and without any C library (a small runtime, nolibc.c and par.c, supplies the entry code, the system calls write and exit_group and, for the threads, arch_prctl, clone and futex, memcpy/memset and the report printing); its whole image is counted: 1,231,305,604 bytes (text, data and bss). The heap is inside that figure: every buffer comes from one static arena of 1,227,182,400 bytes in the bss (a first-fit allocator with a 64-byte header per block and merging of free neighbours; no mmap and no munmap); the run used it up to 1,227,182,400 bytes, and the peak of the bytes in use was 1,072,730,624 bytes (11 live blocks, payload 1,072,729,920 bytes). The static memory of the 6 threads (worker stacks, thread blocks, scratch of the row-parallel mode: 3,706,880 bytes in all) is inside that figure. A stack bound of 65,536 bytes for the main thread completes the total (the run was executed under a 64 KiB stack limit). The largest live set of the powering is the transform buffer (3 x 2^22 elements), one transform row, the Barrett inverse, the modulus, the result and the twiddle table. The measured peak of the run (memmeter: the wait4 maximum resident set and a 10 ms sampling of the process tree) was 1,216,389,120 bytes; the claim takes the larger of the counted sum (1,231,371,140 bytes) and the measured peak.

What is not included. Nothing was selected: the start and the order of the centres (1, 2, 3, ...) are fixed in the source, and the counted run of this source was made once from c = 1. Other runs made for this entry, all after the order of the centres was fixed in the source: runs of this source and of the single-thread program at r = 1, 2 and 3 on centre 1 only (with the thread thresholds lowered so that every split path executes) to check that the counters agree, timing runs at r = 3 on centre 1 only, and the single-thread run of the earlier r = 4 program on another machine, which is not part of this entry; they select nothing and change no parameter, and the result of this run does not depend on them. The algorithm is the single counted run. The probability 1 is the statement about this executed run; it says nothing about how many trials another sequence of centres would need (each centre has roughly a 39 percent chance of yielding a usable root). The organizer did not run the program, so the counts rest on the shipped source. There is no C library: the allocator is charged per executed operation, and the formatting of the report, the one write system call and the exit are charged in stage I, inside the printed total (by stated constants: 400 per byte of the 8,192-byte output buffer, 75,536 for the write, 10,000 for the exit). The one structural assumption of the cost model is a register file of 18 words of 256 bits per transform block (16 data words and two working words: the twiddle operand and the butterfly temporary).

Reasoning narrative.
Context. Judged r = 1 and r = 2 entries for this line of attack charge the executed run of a deterministic procedure on the fixed target with success probability 1. This entry applies that convention to the r = 4 target, with the odd-part variant of the line polynomial, which halves the degree and therefore the transform sizes and the memory.
Approach. Fix the order of the centres, run the procedure once from the first centre until it stops, and report its counters: the powering is the largest term, the half-gcd second, the evaluation of the line third.
Trade-offs. The executed run is much cheaper than a worst-case charge, in exchange for a claim that is the cost of this run rather than a probability, which the proof says in so many words. The powering keeps its spectra out of memory (they are regenerated row by row), which costs time and saves memory.
Implementation. Reused from the r = 2 versions of this program: the finite-field code, the transform engine, the low-memory powering and the half-gcd with shared transforms and a one-pass base case, the fixed order of centres with every trial charged, the gap-free stage chain with one printed total, the counted output stage and the measured memory footprint of a statically linked executable, under the full loop and address rule (an address operation for every load and store, 3 per loop iteration and 2 per loop exit). New for this entry: the runtime and transform layer of the judged r = 2 single-line entry (a static arena allocator charged per operation, one buffered write, the report and exit charged in stage I, no integer multiplication, division or modulo in index code, the generator charged per operation), and the r = 4 dimensions (m = 4882812, powering transforms of 3 x 2^22 points, 12582912 line evaluations), set by the round count and the largest transform exponent in the source, and the measured peak of the run taken into the memory figure.
Results. The run stopped with a collision that the organizer's hash accepts; the counters are in the table above.
Next steps. A cheaper powering schedule, or a cached transform of the modulus at a cost in memory, would lower the executed count directly.
