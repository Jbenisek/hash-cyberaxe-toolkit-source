Orchard Poseidon, r = 3 (poseidon-orchard-r3-prefix-v1): one deterministic run on the fixed target, executed operation count, complete source in the proof.

What this entry is. A collision finder for the reduced Orchard hash (eight full rounds and three partial rounds). It is a single deterministic procedure with no selection step: it tries the centres c_i = i in the fixed public order i = 1, 2, 3, ..., runs each trial completely, and stops at the first trial that yields a collision (the source caps the search at 64 trials, a cap this run did not reach). It was executed once from the start on the fixed target; it stopped after 1 trials, at c = 1. The claim is the executed cost of that one run, every trial charged, failed ones included: success probability 1 (deterministic procedure executed on the fixed target, every executed trial charged). There is no worst-case bound, no probability theorem and no heuristic premise about the mathematics; the time is the executed operation count and the memory is the executed peak (the maximum over the trials). The one declared premise in the claim file is that the stated charging rules describe the shipped program.

The method in plain terms.
1. After the first full round, the state is an affine image of two free field elements (U, V) and one constant. Along a line in the (U, V) plane where one coordinate of the second round's S-box input stays constant, the second round costs no degree: its S-box output is affine in one parameter W. The digest is then a univariate polynomial F(W) of degree 5^9 = 1953125. The line contains exactly p inputs, one for each W in F_p. This is the two-round bypass of Bariant, Bouvier, Leurent and Perrin (ToSC 2022/3).
2. For a centre c, write F(c + s) - F(c - s) = 2 s g(s^2). The polynomial g has degree 976562 and a leading coefficient that does not depend on c (nonzero on this line: proof.md section 2.3, and tested by the program). A root S of g that is a nonzero square gives s = sqrt(S) and two different inputs W1 = c + s and W2 = c - s with the same digest. Working with g (half the degree of F) halves every transform length compared with working with F itself.
3. The program evaluates the digest at 3145728 points (each charged as one full target compression, 279 operations), interpolates g with one inverse transform of length H = 1572864 (line interpolation: 2H = 3145728 evaluations), computes S^((p-1)/2) mod g with a low-memory transform schedule (234 Barrett squarings; the big transforms have 2^(k+1) points as two rows of 2^k where the product length fits, otherwise 3 * 2^k), and takes gcd(g, S^((p-1)/2) - 1) with a half-gcd. A trial whose gcd is constant has no useful root and is charged in full; the first trial with a root of g that is a nonzero square has its root isolated, square-rooted, mapped back, and both inputs are checked with the reference hash. The run ends there with the collision.

Numbers. time_log2 30.08182 (the executed run: N = 317,054,280,703 primitive operations = 1,136,395,271.3 target-compression units at 279 operations per unit), memory 250,386,180 bytes (log2 27.900, stated separately; time plus memory penalty 37.98182 is a bookkeeping sum, the normalized scalar is log2(time) = 30.08182), success probability 1, preprocessing 0 (the twiddle table is built inside the run and counted in N), 1 trials. One squaring step of the powering costs 1,103,045,418 operations. One verified collision is included as a certificate; it is the output of this run, and it was checked with an independent big-integer implementation of the reduced hash and with the organizer's digest function.

What changed against POSR3F (the filed r = 3 entry of this line, same algorithm, same centre order, same collision). Only the transform plan changed. In POSR3F the big powering transforms had 3 x 2^20 points (a twiddle-free radix-3 stage followed by three rows of 2^20). The product to be squared has 2m - 1 = 1,953,123 coefficients, which fits 2^21 = 2,097,152 points, so this entry pulls the first radix-2 decimation-in-frequency layer out as a twisted stage (row 0 = c[i] + c[i+n], row 1 = (c[i] - c[i+n]) w^i, w^n = -1, n = 2^20) and leaves two ordinary rows of 2^20; the buffer for the row-by-row second operand stays one row of 2^20. The Barrett product with q x g uses 2^20 points instead of 3 x 2^19, and every Newton and half-gcd product picks the smallest plan among 2^(a+1) and 3 x 2^a that holds its length (plan3_for_len). The result is that the transform buffer shrinks by 1,048,576 elements and the operation count drops (powering step, Newton and half-gcd all use shorter transforms). The collision found is the same one (same centre); the other stages, the allocator, the report and the charging rules are unchanged, except that the arena constant is now 250,000,000 bytes (it was 290,000,000) and the new stage is charged by the same rules (every field operation by its fp_* call, every load and store by LD / ST, every test by CTL, the first twiddle power of each region by square-and-multiply). POSR3F's numbers (462,143,854,728 operations, 290,356,404 bytes) are the comparison; this entry's are in the Numbers paragraph above.

The program prints one total. The stage rows, the trial rows (with the row outside the trials) and the counters of the whole run are separate sums of the same counters, and the line RECONCILE of the run reads ok=1 only when all three are equal: stages 317,054,280,703 = trials 317,054,280,703 = counters 317,054,280,703.

How the accounting works. Every figure is a counter of the same single execution of the shipped source: field operations, 256-bit loads and stores with one address operation each, loop control at 3 operations per iteration plus 2 on exit for every loop that is not written out straight-line, other control operations, and 279 operations for each reduced permutation evaluation. Nothing is extrapolated and no other run enters the count; the only bounds are the stated constants of the report, write and exit (stage I) and of the stage bookkeeping. The half-gcd is charged at what it executed (56,416,271,248 operations over all trials). Montgomery conversions are one field multiplication each, wherever they occur (the centre, the inputs of the reference hashes, the output). The output itself is part of the run: stage H converts the two pairs, the digest and the centre to canonical form and encodes them as hexadecimal text, 12 operations per digit, inside the total.
Loops. The loops that are genuinely unrolled in the source are the ones written with the macro FOR8 (eight copies of the body per pass, charged 3 per pass of eight; sites in ntt.c: 14, lean.c: 5) and the generated transform kernels, whose butterflies and radix-3 position kernels are straight-line code. Every other loop is a real loop and is charged per iteration, with the address operation of each load and store.
Memory. The executable is linked statically and without any C library (a small runtime, nolibc.c, supplies the entry code, the two system calls write and exit_group, memcpy/memset and the report printing); its whole image is counted: 250,320,644 bytes (text, data and bss). The heap is inside that figure: every buffer comes from one static arena of 250,000,000 bytes in the bss (a first-fit allocator with a 64-byte header per block and merging of free neighbours; no mmap and no munmap); the run used it up to 250,000,000 bytes, and the peak of the bytes in use was 202,802,752 bytes (11 live blocks, payload 202,802,048 bytes). A stack bound of 65,536 bytes completes the total (the run was executed under a 64 KiB stack limit). The largest live set of the powering is the transform buffer (2 x 2^20 elements), one transform row, the Barrett inverse, the modulus, the result and the twiddle table. Memory is max(online, preprocessing): the program has no separate preprocessing, the twiddle table is built in stage init inside the same arena, so the two coincide and the figure below covers both. The measured peak of the run (memmeter: the wait4 maximum resident set and a 10 ms sampling of the process tree) was 222,314,496 bytes; the claim takes the larger of the counted sum (250,386,180 bytes) and the measured peak.

What is not included. Nothing was selected: the start and the order of the centres (1, 2, 3, ...) are fixed in the source, and the counted run of this source was made once from c = 1. An earlier build of the same algorithm with the C library allocator (the r = 3 entry filed before this one) ran centre 1, and monitoring runs of centres 2 to 11, after the order of the centres was fixed in the source; they select nothing and change no parameter, and the result of this run does not depend on them. The algorithm is the single counted run. The probability 1 is the statement about this executed run; it says nothing about how many trials another sequence of centres would need (each centre has roughly a 39 percent chance of yielding a usable root). The organizer did not run the program, so the counts rest on the shipped source. There is no C library: the allocator is charged per executed operation, and the formatting of the report, the one write system call and the exit are charged in stage I, inside the printed total (by stated constants: 400 per byte of the 8,192-byte output buffer, 75,536 for the write, 10,000 for the exit). The one structural assumption of the cost model is a register file of 18 words of 256 bits per transform block (16 data words and two working words: the twiddle operand and the butterfly temporary).

Reasoning narrative.
Context. Judged r = 1 and r = 2 entries for this line of attack charge the executed run of a deterministic procedure on the fixed target with success probability 1. This entry applies that convention to the r = 3 target, with the odd-part variant of the line polynomial, which halves the degree and therefore the transform sizes and the memory.
Approach. Fix the order of the centres, run the procedure once from the first centre until it stops, and report its counters: the powering is the largest term, the half-gcd second, the evaluation of the line third.
Trade-offs. The executed run is much cheaper than a worst-case charge, in exchange for a claim that is the cost of this run rather than a probability, which the proof says in so many words. The powering keeps its spectra out of memory (they are regenerated row by row), which costs time and saves memory.
Implementation. Reused from the r = 2 version of this program and from the filed POSR3F (the transform stage rows == 2 is the one new piece): the finite-field code, the transform engine, the low-memory powering and the half-gcd with shared transforms and a one-pass base case, the fixed order of centres with every trial charged, the gap-free stage chain with one printed total, the counted output stage and the measured memory footprint of a statically linked executable, under the full loop and address rule (an address operation for every load and store, 3 per loop iteration and 2 per loop exit). New for this entry: the runtime without a C library of the judged r = 2 single-line entry (a static arena allocator charged per operation, one buffered write, the report and exit charged in stage I), and the r = 3 dimensions (m = 976562, powering transforms of 2 x 2^20 points, 3145728 line evaluations), set by the round count and the largest transform exponent in the source, and the measured peak of the run taken into the memory figure.
Results. The run stopped with a collision that the organizer's hash accepts; the counters are in the table above.
Next steps. A cheaper powering schedule, or a cached transform of the modulus at a cost in memory, would lower the executed count directly.
