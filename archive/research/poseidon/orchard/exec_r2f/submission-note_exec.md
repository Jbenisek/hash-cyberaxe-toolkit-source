Orchard Poseidon, r = 2 (poseidon-orchard-r2-prefix-v1): one deterministic run on the fixed target, executed operation count, complete source in the proof.

What this entry is. A collision finder for the reduced Orchard hash (eight full rounds and two partial rounds). It is a single deterministic procedure with no selection step: it tries the centres c_i = i in the fixed public order i = 1, 2, 3, ..., runs each trial completely, and stops at the first trial that yields a collision. It was executed once from the start on the fixed target; it stopped after 1 trials, at c = 1. The claim is the executed cost of that one run, every trial charged, failed ones included: success probability 1 (deterministic procedure executed on the fixed target, every executed trial charged). There is no worst-case bound, no probability theorem and no heuristic premise about the mathematics; the time is the executed operation count and the memory is the executed peak (the maximum over the trials). The one declared premise in the claim file is that the stated charging rules describe the shipped program.

The method in plain terms.
1. After the first full round, the state is an affine image of two free field elements (U, V) and one constant. Along a line in the (U, V) plane where one coordinate of the second round's S-box input stays constant, the second round costs no degree: its S-box output is affine in one parameter W. The digest is then a univariate polynomial F(W) of degree 5^8 = 390625. The line contains exactly p inputs, one for each W in F_p. This is the two-round bypass of Bariant, Bouvier, Leurent and Perrin (ToSC 2022/3).
2. For a centre c, write F(c + s) - F(c - s) = 2 s g(s^2). The polynomial g has degree 195312 and a leading coefficient that does not depend on c (nonzero on this line: proof.md section 2.3, and tested by the program). A root S of g that is a nonzero square gives s = sqrt(S) and two different inputs W1 = c + s and W2 = c - s with the same digest. Working with g (half the degree of F) halves every transform length compared with working with F itself.
3. The program evaluates the digest at 393216 points (each charged as one full target compression, 258 operations), interpolates g with one inverse transform of length 196608, computes S^((p-1)/2) mod g with a low-memory transform schedule (236 Barrett squarings on 3 * 2^k transforms), and takes gcd(g, S^((p-1)/2) - 1) with a half-gcd. A trial whose gcd is constant has no useful root and is charged in full; the first trial with a root of g that is a nonzero square has its root isolated, square-rooted, mapped back, and both inputs are checked with the reference hash. The run ends there with the collision.

Numbers. time_log2 27.06355 (the executed run: N = 36,187,459,922 primitive operations = 140,261,472.6 target-compression units at 258 operations per unit), memory 44,788,757 bytes (log2 25.417), normalized cost 32.48055, success probability 1, preprocessing 0 (the twiddle table is built inside the run and counted in N), 1 trials. One squaring step of the powering costs 120,023,784 operations. One verified collision is included as a certificate; it is the output of this run, and it was checked with an independent big-integer implementation of the reduced hash and with the organizer's digest function.

How the accounting works. Every figure is a counter of the same single execution of the shipped source: field operations, 256-bit loads and stores with one address operation each, loop control at 3 operations per iteration plus 2 on exit for every loop that is not written out straight-line, other control operations, and 258 operations for each reduced permutation evaluation. Nothing is bounded or extrapolated, and no other run enters the count. The half-gcd is charged at what it executed (7,533,799,633 operations over all trials). Montgomery conversions are one field multiplication each, wherever they occur (the centre, the inputs of the reference hashes, the output). The output itself is part of the run: stage H converts the two pairs, the digest and the centre to canonical form and encodes them as hexadecimal text, 12 operations per digit, inside the total.
Loops. The loops that are genuinely unrolled in the source are the ones written with the macro FOR8 (eight copies of the body per pass, charged 3 per pass of eight; sites in ntt.c: 8, lean.c: 5) and the generated transform kernels (ntt_kern.h, ntt_big.h, ntt_a3.h), whose butterflies, loads, stores and radix-3 position kernels are straight-line code. Every other loop is a real loop and is charged per iteration, with the address operation of each load and store.
Memory. The executable is linked statically and its whole image is counted: 1,583,445 bytes (text, data and bss, including the C library routines it uses). The heap term is the footprint of the allocator read with mallinfo2() after every allocation, which contains the payloads, the 64-byte header of each of the 12 allocations live at the peak (768 bytes), the allocator's own chunk headers and padding, page rounding and heap not yet returned: peak 43,139,776 bytes, in the half-gcd stage (payload alive at that moment 37,640,992 bytes). A stack bound of 65,536 bytes completes the total (the run was executed under a 64 KiB stack limit). The largest live set of the powering is the transform buffer (3 x 2^17 elements), one transform row, the Barrett inverse, the modulus, the result and the twiddle table. Not counted: pages the kernel maps outside the executable image (vdso, vvar, page tables). Cross-check: the maximum resident set of the run measured with GNU time was 44,298,240 bytes.

What is not included. Nothing was selected beforehand: the centres are 1, 2, 3, ... in that order, the run was made once, and no earlier run of any centre is left out of N. The probability 1 is the statement about this executed run; it says nothing about how many trials another sequence of centres would need (each centre has roughly a 39 percent chance of yielding a usable root). The organizer did not run the program, so the counts rest on the shipped source. The standard-library call that writes the encoded output text and the program's printing of its own counters are not counted; the allocator's instruction counts are not charged as time (its memory is counted in full). The one structural assumption of the cost model is a declared register file: 18 words of 256 bits per block for the small transforms, and 520 words (512 data words of one block and 8 working words) for the transforms of 2^13 to 2^17 points, which run in two passes; that file is allocated with xalloc and counted in the allocator footprint and is part of the memory figure.

Reasoning narrative.
Context. Judged entries on this board for the same line of attack charge the executed run of a deterministic procedure on the fixed target with success probability 1. This entry follows that convention for the r = 2 target, with the odd-part variant of the line polynomial, which halves the degree and therefore the transform sizes and the memory.
Approach. Fix the order of the centres, run the procedure once from the first centre until it stops, and report its counters: the powering is the largest term, the half-gcd second, the evaluation of the line third.
Trade-offs. The executed run is much cheaper than a worst-case charge, in exchange for a claim that is the cost of this run rather than a probability, which the proof says in so many words. The powering keeps its spectra out of memory (they are regenerated row by row), which costs time and saves memory.
Implementation. Reused: the finite-field code, the transform engine, the low-memory powering and the half-gcd of earlier work with shared transforms and a one-pass base case, under the full loop and address rule (an address operation for every load and store, 3 per loop iteration and 2 per loop exit); new for this entry: the fixed order of centres with every trial charged, the removal of the bounds and halts that the run does not reach, the gap-free stage chain with one printed total, the counted output stage, and the measured memory footprint of a statically linked executable.
Results. The run stopped with a collision that the organizer's hash accepts; the counters are in the table above.
Next steps. A cheaper powering schedule, or a cached transform of the modulus at a cost in memory, would lower the executed count directly.
