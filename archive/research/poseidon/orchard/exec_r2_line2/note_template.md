What this entry is. A collision finder for the reduced Orchard hash (eight full rounds and @@PARTIAL_WORD@@). It is a single deterministic procedure with no selection step: it tries the centres c_i = i in the fixed public order i = 1, 2, 3, ..., runs each trial completely, and stops at the first trial that yields a collision. It was executed once from the start on the fixed target; it stopped after @@TRIALS@@ trials, at c = @@LASTC@@. The claim is the executed cost of that one run, every trial charged, failed ones included: success probability 1 (deterministic procedure executed on the fixed target, every executed trial charged). There is no worst-case bound, no probability theorem and no heuristic premise about the mathematics; the time is the executed operation count and the memory is the whole executable image, whose bss holds the one static arena that serves every buffer. The one declared premise in the claim file is that the stated charging rules describe the shipped program.

The method in plain terms.
1. After the first full round, the state is an affine image of two free field elements (U, V) and one constant. Along a line in the (U, V) plane where one coordinate of the second round's S-box input stays constant, the second round costs no degree: its S-box output is affine in one parameter W. The digest is then a univariate polynomial F(W) of degree 5^@@DEXP@@ = @@D@@. The line contains exactly p inputs, one for each W in F_p. This is the two-round bypass of Bariant, Bouvier, Leurent and Perrin (ToSC 2022/3).
2. For a centre c, let q(X) = (F(X) - F(c)) / (X - c), a polynomial of degree @@M@@ (the full degree of F minus one) with a leading coefficient that does not depend on c (nonzero on this line: proof.md section 2.3, and tested by the program). Any root W of q in F_p other than c gives two different inputs, W1 = c and W2 = W, with the same digest. This route uses the polynomial at its full degree: there is no odd-part, parity or half-degree reduction.
3. The program evaluates the digest at @@N2@@ points (each charged as one full target compression, @@C@@ operations), interpolates F with one inverse transform of length @@H@@, divides by X - c by synthetic division and scales to a monic q, computes X^p mod q with a low-memory transform schedule (@@STEPS@@ Barrett squarings on 3 * 2^k transforms), and takes gcd(q, X^p - X) with a half-gcd. A trial whose gcd is constant has no root and is charged in full; the first trial with a root of q has its root isolated, mapped back, and both inputs are checked with the reference hash. A root equal to c itself would give two equal inputs and end its trial as failed. The run ends at the first collision.

How the accounting works. Every figure is a counter of the same single execution of the shipped source: field operations, 256-bit loads and stores with one address operation each, loop control at 3 operations per iteration plus 2 on exit for every loop that is not written out straight-line, other control operations, and @@C@@ operations for each reduced permutation evaluation. Nothing is extrapolated, no other run enters the count, and the only bounds in it are stated constants (the per-byte formatting charge, the system calls, the stage bookkeeping, listed in proof.md section 4.2). The half-gcd is charged at what it executed (@@GCD_OBS@@ operations over all trials). Montgomery conversions are one field multiplication each, wherever they occur (the centre, the inputs of the reference hashes, the output). The output itself is part of the run and inside the total: stage H converts the two pairs, the digest and the centre to canonical form and encodes them as hexadecimal text, 12 operations per digit; stage I charges the formatting of the whole report (an upper bound of 400 operations per byte for the full 8,192-byte output buffer, 3,276,800), the single write system call (10,000 + 8 per buffer byte), the single exit system call (10,000), the loops of the report, the bookkeeping of the stages (1,000 per stage) and the entry code. The allocator is charged load by load, store by store, comparison by comparison, inside the stages that call it. The generator of the root isolation is charged shift by shift and XOR by XOR (11 operations per word). The index and control code has no integer multiplication, division or modulo: each is a shift, a mask, a running pointer or a counter, or the shift-and-subtract routine udivmod, all charged as executed (proof.md section 4.2).
Loops. The loops that are genuinely unrolled in the source are the ones written with the macro FOR8 (eight copies of the body per pass, charged 3 per pass of eight; @@FOR8_SHORT@@) and the generated transform kernels, whose butterflies and radix-3 position kernels are straight-line code. Every other loop is a real loop and is charged per iteration, with the address operation of each load and store.

Guards. The source has finite guards that stop the program without a collision if hit: at most 64 trials (exit status 2), and checks on a vanishing leading coefficient of F, a transform length beyond the twiddle table, and a non-monic modulus (exit with a message). None is reached in the recorded run, and they add nothing to N beyond the tests charged in the ledger.

Scope of the claim. Nothing was selected beforehand: the centres are 1, 2, 3, ... in that order, the run was made once, and no earlier run of any centre is left out of N. The probability 1 is the statement about this executed run; it says nothing about how many trials another sequence of centres would need (a random polynomial of this degree has a root in the field with probability about 0.63, a heuristic that the claim does not use). The organizer did not run the program, so the counts rest on the shipped source. The report, its formatting and its one write call, and the allocator, are charged inside the total as stated above. The meter that records the charges (the counter increments) is how the rules are applied and is not a step of the program. The one structural assumption of the cost model is a register file of 18 words of 256 bits per transform block (16 data words and two working words: the twiddle operand and the butterfly temporary).

Reasoning narrative.
Context. Judged entries on this board for the same line of attack charge the executed run of a deterministic procedure on the fixed target with success probability 1. This entry follows that convention for the r = @@R@@ target, with the plain line polynomial at its full degree 5^@@DEXP@@, divided by X - c, and a gcd against X^p - X; it is the single-line route and not the odd-part (parity) halving. The deterministic one-line convention, the executed-outcome count and the half-gcd root finding follow the accepted entry 186052af of mitchuski (read as text, no code of it was run or copied), which in turn uses the line of Bariant, Bouvier, Leurent and Perrin.
Approach. Fix the order of the centres, run the procedure once from the first centre until it stops, and report its counters: the powering is the largest term, the half-gcd second, the evaluation of the line third.
Trade-offs. The executed run is much cheaper than a worst-case charge, in exchange for a claim that is the cost of this run rather than a probability, which the proof says in so many words. The powering keeps its spectra out of memory (they are regenerated row by row), which costs time and saves memory.
Implementation. Reused: the finite-field code, the transform engine, the low-memory powering and the half-gcd of earlier work with shared transforms and a one-pass base case, under the full loop and address rule (an address operation for every load and store, 3 per loop iteration and 2 per loop exit); new for this entry: the fixed order of centres with every trial charged, the gap-free stage chain with one printed total, the counted output stage, the allocator and the generator charged operation by operation, no integer multiplication, division or modulo in the index and control code, and a statically linked executable without a C library whose whole image (heap arena included) is the memory figure.
Results. The run stopped with a collision that the organizer's hash accepts; the counters are in the table above.
Next steps. A cheaper powering schedule, or a cached transform of the modulus at a cost in memory, would lower the executed count directly.
