What this entry is. A collision finder for the reduced Orchard hash (eight full rounds and @@PARTIAL_WORD@@). It is a single deterministic procedure with no selection step: it tries the centres c_i = i in the fixed public order i = 1, 2, 3, ..., runs each trial completely, and stops at the first trial that yields a collision (the source caps the search at 64 trials, a cap this run did not reach). It was executed once from the start on the fixed target; it stopped after @@TRIALS@@ trials, at c = @@LASTC@@. The claim is the executed cost of that one run, every trial charged, failed ones included: success probability 1 (deterministic procedure executed on the fixed target, every executed trial charged). There is no worst-case bound, no probability theorem and no heuristic premise about the mathematics; the time is the executed operation count and the memory is the executed peak (the maximum over the trials). The one declared premise in the claim file is that the stated charging rules describe the shipped program.

The method in plain terms.
1. After the first full round, the state is an affine image of two free field elements (U, V) and one constant. Along a line in the (U, V) plane where one coordinate of the second round's S-box input stays constant, the second round costs no degree: its S-box output is affine in one parameter W. The digest is then a univariate polynomial F(W) of degree 5^@@DEXP@@ = @@D@@. The line contains exactly p inputs, one for each W in F_p. This is the two-round bypass of Bariant, Bouvier, Leurent and Perrin (ToSC 2022/3).
2. For a centre c, write F(c + s) - F(c - s) = 2 s g(s^2). The polynomial g has degree @@M@@ and a leading coefficient that does not depend on c (nonzero on this line: proof.md section 2.3, and tested by the program). A root S of g that is a nonzero square gives s = sqrt(S) and two different inputs W1 = c + s and W2 = c - s with the same digest. Working with g (half the degree of F) halves every transform length compared with working with F itself.
3. The program evaluates the digest at @@N2@@ points (each charged as one full target compression, @@C@@ operations), interpolates g with one inverse transform of length @@H@@, computes S^((p-1)/2) mod g with a low-memory transform schedule (@@STEPS@@ Barrett squarings on 3 * 2^k transforms), and takes gcd(g, S^((p-1)/2) - 1) with a half-gcd. A trial whose gcd is constant has no useful root and is charged in full; the first trial with a root of g that is a nonzero square has its root isolated, square-rooted, mapped back, and both inputs are checked with the reference hash. The run ends there with the collision.

How the accounting works. Every figure is a counter of the same single execution of the shipped source: field operations, 256-bit loads and stores with one address operation each, loop control at 3 operations per iteration plus 2 on exit for every loop that is not written out straight-line, other control operations, and @@C@@ operations for each reduced permutation evaluation. Nothing is extrapolated and no other run enters the count; the only bounds are the stated constants of the report, write and exit (stage I) and of the stage bookkeeping. The half-gcd is charged at what it executed (@@GCD_OBS@@ operations over all trials; the stage D row adds @@D_EXTRA@@ for the stage bookkeeping, the subtraction R - 1, the degree scan and the test of deg G). Montgomery conversions are one field multiplication each, wherever they occur (the centre, the inputs of the reference hashes, the output). The output itself is part of the run: stage H converts the two pairs, the digest and the centre to canonical form and encodes them as hexadecimal text, 12 operations per digit, inside the total.
Loops. The loops that are genuinely unrolled in the source are the ones written with the macro FOR8 (eight copies of the body per pass, charged 3 per pass of eight; @@FOR8_SHORT@@) and the generated transform kernels, whose butterflies and radix-3 position kernels are straight-line code. Every other loop is a real loop and is charged per iteration, with the address operation of each load and store.

What is not included. Nothing was selected: the start and the order of the centres (1, 2, 3, ...) are fixed in the source, and the counted run of this source was made once from c = 1. Other runs made for this entry, all after the order of the centres was fixed in the source: a build of the same algorithm with the C library allocator was started on centre 1 as a timing reference, with monitoring runs of centres 2 and 3 alongside it, and all of them were stopped before they finished; they select nothing and change no parameter, and the result of this run does not depend on them. The algorithm is the single counted run. The probability 1 is the statement about this executed run; it says nothing about how many trials another sequence of centres would need (each centre has roughly a 39 percent chance of yielding a usable root). The organizer did not run the program, so the counts rest on the shipped source. There is no C library: the allocator is charged per executed operation, and the formatting of the report, the one write system call and the exit are charged in stage I, inside the printed total (by stated constants: 400 per byte of the 8,192-byte output buffer, 75,536 for the write, 10,000 for the exit). The one structural assumption of the cost model is a register file of 18 words of 256 bits per transform block (16 data words and two working words: the twiddle operand and the butterfly temporary).

Reasoning narrative.
Context. Judged r = 1 and r = 2 entries for this line of attack charge the executed run of a deterministic procedure on the fixed target with success probability 1. This entry applies that convention to the r = @@R@@ target, with the odd-part variant of the line polynomial, which halves the degree and therefore the transform sizes and the memory.
Approach. Fix the order of the centres, run the procedure once from the first centre until it stops, and report its counters: the powering is the largest term, the half-gcd second, the evaluation of the line third.
Trade-offs. The executed run is much cheaper than a worst-case charge, in exchange for a claim that is the cost of this run rather than a probability, which the proof says in so many words. The powering keeps its spectra out of memory (they are regenerated row by row), which costs time and saves memory.
Implementation. Reused from the r = 2 versions of this program: the finite-field code, the transform engine, the low-memory powering and the half-gcd with shared transforms and a one-pass base case, the fixed order of centres with every trial charged, the gap-free stage chain with one printed total, the counted output stage and the measured memory footprint of a statically linked executable, under the full loop and address rule (an address operation for every load and store, 3 per loop iteration and 2 per loop exit). New for this entry: the runtime and transform layer of the judged r = 2 single-line entry (a static arena allocator charged per operation, one buffered write, the report and exit charged in stage I, no integer multiplication, division or modulo in index code, the generator charged per operation), and the r = @@R@@ dimensions (m = @@M@@, powering transforms of 3 x 2^@@AEXP@@ points, @@N2@@ line evaluations), set by the round count and the largest transform exponent in the source, and the measured peak of the run taken into the memory figure.
Results. The run stopped with a collision that the organizer's hash accepts; the counters are in the table above.
Next steps. A cheaper powering schedule, or a cached transform of the modulus at a cost in memory, would lower the executed count directly.
