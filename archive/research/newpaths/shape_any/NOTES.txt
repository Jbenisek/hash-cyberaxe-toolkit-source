shape_any/ - "let the mathematics choose the shape": free width of join trees (tree decompositions) of the
idea-1 constraint hypergraph.  Owner of this folder: the shape_any research agent.  Plain text.

MODEL (DERIVED; generic counting, each primitive equation = one 32-bit condition, solvable in any one word)
  Words = vertices, primitive equations = hyperedges (fixed: 100 words, 96 equations, F = 4;
  outhalf: 128 words, 116 equations, F = 12).
  A join tree = binary tree whose leaves are equations.  Node t holds equation set A_t; its boundary
  B(A_t) = words of A_t that also occur outside A_t.  The node's list is the projection of Sol(A_t) on B(A_t).
  rho(A, Z) = min over Z <= Y of |Y| - e_A(Y) = |Z| - (|A| - maxmatching(A, W(A) \ Z))   (Hall/Konig)
  = log2(list size)/32 when Z = B(A).  Joining children t1, t2 (hash join on shared words, memory free):
  output = projection of Sol(A_t) on B(A_t1) u B(A_t2), size 2^(32 J_t), J_t = rho(A_t, B1 u B2).
  Single equations are virtual leaves (never stored; joining one to a list is a guess/determine extension).
  "free width" of the tree = max_t J_t (words).  Work ~ (#joins) x 2^(32 width) list entries.
  Every shape is a special case: GD path = caterpillar; 2-list / k-list joins = stars; grid / cube / ring
  orders = particular elimination orders; tables of gd_promote.py = a G call grouped as a subtree (the same
  count), so table rules add nothing in this model.
  Promotions: fixing words of a sub-family = adding unit equations; slack(P) = |P| - E + maxmatch(E, V\P)
  (dimension consumed); derived constants (a G call made fully constant) cost no extra slack.
  Need ~2^64 members: fixed has slack 2, outhalf has slack 10 (fixed = outhalf + 12 promoted words, slack 8).

LOWER-BOUND ARGUMENT (DERIVED)
  In any rooted binary tree with E leaves and any 2 <= k <= E/2 some internal node has k <= |A_t| < 2k (walk the
  heavy path).  Its join costs J_t >= rho(A_t, B(A_t)).  Hence width >= LB(k) = min_{k<=|A|<2k} rho(A, B(A)).
  The same holds with nonnegative equation weights (window on the weight).  With promotions the minimum is taken
  jointly over A and a promotion set of slack <= S (lbsat3.py; window counted on equations still holding an
  unknown; mode 'drop' checks that slack S cannot delete so many equations that the window is empty).
  The bound covers EVERY tree shape (path, star, grid, cube, ring with a cut, odd trees), not only elimination
  orders.  It does not cover algorithms outside "complete lists joined along a tree".

  Bit-level (fractional) promotions and Wagner-style partial-key filters (DERIVED, generic counting): any
  constraint of s bits lowers the critical list by at most s bits, and one more whole promoted word lying in the
  critical cut's Y lowers that cut by >= 1, so LB(S) >= LB(S+1) + 1.  A strategy with j words promoted whole and
  the rest as bits or keys has width >= LB(j) - (10 - j) >= LB(10).  Caveat: the extra word may push a set out of
  the size window.  So the word-level bound also bounds bit-level and k-list restriction tricks.

THE OWNER'S QUESTION IN THIS LANGUAGE (DERIVED)
  A "shape" is the way the 100-128 words are grouped and the partial answers glued together.  Every way of
  gluing complete partial-answer lists along a tree is a tree decomposition of the word/equation hypergraph:
    path            = guess-and-determine (one growing list)            -> caterpillar
    star            = k-list join around a core (separable, ksplit)     -> star of bags
    grid / cube     = bags laid out on a lattice, cut into a tree        -> elimination order by coordinates
    ring / torus / sphere surface = a cycle of bags; to be solved it must be cut once, and the cut words ride
                      along every bag (a path with the cut words added)
    odd shapes      = any other tree; the search here is over ALL trees at once
  A shape's cost is its widest neck: the largest list it must hold, 2^(32 x width).
  The lower bound does not test shapes one by one: it proves that EVERY tree has a node holding between 1/3
  and 2/3 of the equations, and measures the cheapest such chunk's border.  If every chunk of that size has a
  border with >= w free words, no shape of any kind beats width w.
  The 4x4 torus symmetry (columns shifted by 2) is real but broken by IV/counter/flags; it would only pair
  equivalent shapes, it cannot lower the neck of the best one.

COST TRANSLATION (DERIVED; cost model: 1 unit per 2-round compression, word op 1/430, memory free)
  A tree of width w holds lists of 2^(32w) entries; each entry costs a handful of word ops (hash, key, store;
  call it c ~ 8-16) and a tree has ~100 joins of which a few reach the maximum.  List work ~ 2^(32w) * c * j / 430.
  Each of the ~1.2 * 2^64 members then needs out1,3,4,6 (E1, E3 from the known Y state: 2 G calls, ~0.1 unit),
  plus the birthday table (memory free).
      w = 2 : lists 2^64      -> total ~2^64 - 2^65  (dominated by the members themselves)
      w = 3 : lists 2^96      -> ~2^96 * 2^3.5 * 2^2 / 2^8.75 ~ 2^92.8 (2^89.3 if c*j were 10)
      w = 4 : lists 2^128     -> ~2^125
      w >= 5: > 2^155;  generic birthday 2^128.
  So "below 2^85" needs w <= 2 (w < 2.93 even with bit-level tricks), and "competitive with the board (92-94)"
  needs w = 3 with very few full-width joins.  Comparison: guess-and-determine path with 2 promoted words = 6
  guesses -> 2^192; k-list stars (separable, ksplit) 2^193 for 2^64 members.

SCOPE OF THE LOWER BOUND (DERIVED unless marked)
  - Using an equation in several subtrees (extra filters) does not escape it: the heavy path still meets a node
    with |A_t| in the window, and its list still projects onto at least B(A_t).
  - Restricting lists to get fewer members (promotions, bit fixing, random sampling, Wagner partial keys) is
    covered through the slack budget (see above).
  - Not covered: "virtual" macro-equations (a same-operation chain whose private middle word is eliminated
    algebraically, e.g. a+b=c, c+d=f -> a+b+d=f) used without building a list.  GUESS: irrelevant here, since a
    window-size chunk (>= 1/3 of the equations) mixes additions and xor-rotations and cannot collapse to one
    equation; it only affects tiny pieces.  Also not covered: non-join techniques (differential/algebraic
    characteristics, multi-block, families where the half-digest takes 2^h values).

ANSWER (to the owner's question, plain words)
  - Taken literally, the shapes were built and measured (G1): sphere (onion from both ends), hexagon, ring /
    polygon, torus sweep, cylinder, star, the message-permutation cycles.  None is better than a random order;
    their widest necks are 13-36 words (lists of 2^416 and up).
  - Letting the mathematics choose (U1-U4): the best shapes found are irregular - a spine with bushy side
    branches, or two lobes (round-0 D blocks + C calls | E0, E2 + output equations) meeting at one neck.  Their
    neck is 8 words for the fixed family (2^128 members) and 6 words for every 2^64-member family tried
    (outhalf with up to 10 promoted words, fixed with 2): lists of 2^192, total ~2^188.  That equals the
    guess-and-determine path (6 guesses) and the k-list stars (2^193): no shape opens a shortcut.
  - Why: between consecutive layers (K->D, D->C, C->E) every G call takes one word from every call of the
    layer before (complete 4x4 wiring), and each message word is used once per round.  Any chunk holding 1/3
    to 2/3 of the equations must cut many wires; local search over chunks and promotions finds no neck below
    5 (N1, N2, cutp2).  This is "expander" behaviour: there is no small separator, so every tree is wide.
  - Below 2^85 needs a neck of <= 2 words (bit-level tricks cannot help, see above).  Best found 6: dead by
    ~100 bits.  No toy end-to-end attack was run because no decomposition comes near 2^85.
  - Not proven: that no tree of width 3-5 exists.  The exact balanced-neck SAT queries did not finish (see S1
    and the final status lines below).
  N3 COMPUTED (cutp2_outhalf.txt, 24 restarts x 150000 moves, outhalf, slack 10): necks found 5 (3 times),
       6 (21 times), never 4.  GUESS: the true minimum balanced neck over all promotions is 5, so the best
       possible tree width is between 5 and 6 (list 2^160 - 2^192).
  X1 COMPUTED EXACT (bd calldp, subset DP; class = every tree whose nodes are unions of whole G calls, each call
       ("brick") built by its own exact optimal sub-tree; the four output equations form one brick).  Grids,
       cubes, rings, hexagons, stars of G calls all lie in this class:
         fixed (F=4) 9;  fixed with 2 promoted words (F'=2) 7;  outhalf with K calls + D0 constant (F'=2) 6;
         outhalf with the neck-5 promotion P5 (F'=2) 6.   (calldp_*.txt)

       C3, C0, D2 added one at a time (J 6, 5, 2).  Brick-level optimum = equation-level best (6) there.
       Per-brick lists: K 1-2, free D 5-6 (2 when its inputs are constant), C 3-4, E 5, out-group 4.
