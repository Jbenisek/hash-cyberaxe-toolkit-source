CLAIM UNDER TEST (shape_odd/NOTES.txt (c)): hold 3 of out0,2,5,7 with 0 checks -> h = 32 -> 2^80.
  Evidence given: kissat runs (1 word / 15 guesses, two triples / 13 guesses) undecided after 600 s.

VERDICT: REFUTED.  In the word-level GD model the exact check count is c(k) = k for every held subset
  (c(3) = 3 for all four triples), so the k = 3 level costs (128+32)/2 + 32*3 = 2^176, not 2^80.  Tables
  (any per-call table, incl. the gd_promote macros) and promoted constants do not change this.

2. LEMMA (DERIVED, checked by brute force in lemma.py)
   min checks of the GD process = min number of equations whose deletion leaves an EMPTY 2-core
   (2-core: repeatedly remove a word lying in exactly one remaining equation, with that equation).
   Why: with 0 checks every equation solves a word that occurs in no earlier equation; the last core
   equation in the order cannot, since each of its words lies in another, earlier core equation.  The
   guesses play no role - no choice of guesses can open a non-empty core.  Conversely an empty core
   (after deleting D) gives an order with |D| checks (reverse peeling).
   Brute force (lemma.txt) COMPUTED: 26,000 random hypergraphs (3-9 words, and 3,000 with 3-12 words),
   exhaustive guess sets vs exhaustive deletions: 26,000 agree, 0 disagree (10,539 had a non-empty core;
   exact check counts 0..4 all occur).

4. TABLES AND PROMOTED CONSTANTS (cores.py table_core; DERIVED + COMPUTED)
   Permissive table rule: any subset of ONE G call's equations (plus its held out-equation) may be removed
   when it has a perfect matching onto words used nowhere else (every call treated as table-able, any size).
   A real 0-check table step needs such a matching (Hall: otherwise part of the block over-determines its
   words = a check).  COMPUTED: the permissive core equals the plain core in all 17 cases -> tables give no
   0-check order either.
   Promotion (fix words P per sub-family; equations inside P become one-time setup constraints): a core
   minus P stays closed, so a 0-check sub-family needs the WHOLE core inside the setup constraints; then its
   freedom is <= F - deficiency(core) = 0 in every case (deficiency = F, cores.txt).  So a 0-check
   sub-family has at most one member: promotion cannot open the door.
   Sanity (promo_check.py, promo_check.txt) COMPUTED: 4 x 3001 random promotions (random and connected
   equation sets, plus "promote the whole core"); in 779 the remaining core was empty, and in every one of
   them the setup constraints contained the whole core and the sub-family freedom F' was <= 0 (max 0).
   Table model, deletion search (cores_tables.py, cores_tables.txt) COMPUTED: for every triple, no deletion
   of <= 2 equations empties the permissive table core, so even with per-call tables c(3) >= 3 (and = 3).

7. BEYOND 0 CHECKS: JOIN TREES AT k = 3 (ksplit method, rerun for k = 3) COMPUTED + DERIVED
   ksplit section 3: to output 2^80 members (h = 32) below 2^92, every node of any join tree (any k-list,
   MITM, clamping, per-call tables) needs delta <= 13 = F, and the lowest node whose closure is everything
   joins two proper closed regions A, B with delta(A), delta(B), delta(A u B) <= 13 covering the 2-core
   (the alternative, one leaf of 13 guesses with full closure, is a 0-check order: impossible, section 3).
   My export of the k = 4 system equals ksplit/sys_outhalf_plain.txt exactly (export_sys.py).
   ../ksplit/rootcore.py (read only) on my k = 3 exports, D = 13 (rc.log):
     out0,2,5  UNSAT 35 s   out0,2,7  UNSAT 37 s   out0,5,7  UNSAT 43 s   out2,5,7  UNSAT 34 s
     sanity: out0,2,5 with D = 20 SAT in 1 s, D = 16 SAT in 7 s (the encoding can say yes);
     out0,2,5 with D = 14 also UNSAT (42 s): for that triple some node needs delta >= 15 (>= 2^144).
   DERIVED: every join tree for the k = 3 sphere has a node with delta >= 14, i.e. >= 2^(80+32) = 2^112
   joined pairs for 2^80 members.  So k = 3 is dead below 2^112 even with lists / MITM / clamping, not just
   for direct samplers.  (Relies on ksplit's section-3 argument, which I re-read but did not re-derive.)
   Side result for k = 4: ksplit R11 left open "a 12-guess basis (0 checks)"; c(4) = 4 closes it, so every
   join tree for the whole half (outhalf) costs >= 2^96.  Reproduced ksplit's k = 4 root test on my own
   export: rc_k4_D12 UNSAT in 32 s.
