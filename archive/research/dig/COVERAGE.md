Generated by `research/dig/coverage.py` (pure Python, re-runnable, reads `CELLS.jsonl`, the characteristic files, ATLAS37.md, atlas38_gen.py evidence, row cards and a few result files; writes only `UNIVERSE.jsonl`, `COVERAGE.md`, `UNITS.jsonl`). Do not edit by hand.

Rule of this wave: **scan once**. A cell is SCANNED when our own code produced a number or verdict for its question, or when the question is structurally empty (reason recorded in `UNIVERSE.jsonl`). Outside-model claims do not count. When unsure the cell is UNSCANNED. A cell scanned by a result file of a running job that is not yet in CELLS.jsonl is counted SCANNED with basis FILE (pending ingest); the file is named in the cell.

Cell id = `hash|loc|object|question`; `loc` is `MEM.<key>`, `CV.<key>`, `INIT.v0`, `PIN.w4`, `OUT.d0`, `MODE.<key>`, `DOOR.d21`, `MSG.<call>.<x|y>`, `DIG.l0`, `ROW.<key>`, `STAGE.<key>`, `PREM.<key>`, `LEDGER.<key>`, `JUDGE.<key>`. A record naming `universe cell <id>` in its notes counts (full id); the wave-1 short form `universe cell round2.chi|Q1` is now read too (hash and object come from the record).

Question meanings:

- M1 (G02): bytes held by this object at its peak (exact allocation of the shipped program; say bound vs exact)
- M2 (G02): time (ledger operations, exact charge) to recompute / stream / shard this object instead of holding it, priced on the filed ledger
- M3 (G02): score-optimal point for this object: S = time_log2 + max(0, log2 bytes - 20) at the best hold-versus-recompute split, others fixed
- M4 (G02): breakpoint at 2^20 bytes: size/time trade at which total memory crosses 2^20 B, S on both sides, is crossing worth it
- R1 (G07): value charged / stated and where (read the package, name the exact line)
- R2 (G07): own re-measurement or exact recount (fresh seed, preregistered rule, or metered run of the shipped program)
- R3 (G07): control: the same tool on a known answer or a negative control (fails where it must fail)
- R4 (G07): score sensitivity: bits per unit change of this premise / row, and slack candidates (best case the program executes)
- D1 (G05 doors): the test written in the RELABEL column of CLOSED_DOORS.md for this door, run on our own code
