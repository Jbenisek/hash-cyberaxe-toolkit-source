# MAP_DATA.jsonl - shape map for a 3D/4D viewer (2026-10-25, Ledger)

5,776 shapes tested tonight, one JSON object per line. Suggested 4D view:
- x,y,z: a projection of `wordmask` (16-bit: which message words differ) - e.g. PCA/t-SNE of the 16-bit vector, or split into
  low-half / high-half / popcount. Shapes with the same words cluster = one tunnel.
- 4th axis / color: `free32` (tunnel SIZE = 32-bit linear free dimensions; bigger = deeper in the tunnel / more "effort left").
- size or shape: `R` (height) and `max_sat_width` (0/8/12/16/32 = how far up the width ladder it stays real; 0 = never SAT).
- `setup32` = "UNSAT" means dead by 32-bit arithmetic alone (a wall); otherwise "open".
Fields: name, words, kicks, R, n_words, n_kicks, span, free32, setup32, wordmask, verdicts{width:SAT/UNSAT/UNK},
max_sat_width, family.
Tunnels = clusters sharing `kicks`; their size = free32 spread; their location = wordmask. The published paths
(kp38/kp39 rows) sit at the low-free32 edge of their cluster; our tunnels (tun_/wtun_) are a separate cluster with XOR
kernel 0 (see XOR_*.tsv). 9 shapes reach w>=16.

## Added 2026-10-25 (use the wave sensor to improve the view)
Each shape now also carries the WAVE CHAIN (the equal-difference run the 32-bit setup forces), the backbone of the wave:
- `max_chain`: length of the longest equal-delta chain (1 = no wave; >=3 = a real wave; own62_6713 = 7, the period-14 wave).
- `n_chains`, `chains`: the chains as word lists (e.g. "13,20,27,34,41,48,55").
Use `max_chain` as a 5th channel: color or connect shapes along their chain. A tunnel is a set of shapes that share the
same chain; chain length = how far the wave reaches. wave_listen.py (PROBE + chain words) is the live/passive sensor:
solve unpinned at rising widths and read the chain value the solver chooses; the deepest width it stays EQUAL = the wave's
distance (.song.tsv per shape).
