# blake3-r3: plain birthday with 256 bit-sliced lanes, pivot full adders and a mask walk

Credited derivative of our own 0a9640ed-558a-4f0a-aba8-45e89ffcfd7c (blake3 round 3, bit-sliced 256-lane chain, 124.96822, passed the judges) and of our own 3356413f-cd60-410c-8847-2266d6444ac5 (124.95448, two-block mode with a fixed first block; this entry does not use that mode), which are derivatives of our cf8b0e92-4302-4813-907a-3c970c102646 (125.10041) and of Jbenisek's e479cbbf-8aca-4fc6-bdc4-31b38d55c7ca (125.1087). It also takes two circuit and walk ideas from jungjipdo's 6ae36351-5836-4a46-ad34-227688264123 (124.91252), whose proof text (3.3, 3.4) we read as data and re-implemented in our own generator without using or running any file of that entry: (1) the pivot full adder, (2) the mask walk g = f XOR q in which the digest planes are fed back exactly as the circuit stores them. Everything else is the program of 0a9640ed and 3356413f: relation, trail-and-table search with distinguished points, handlers, recovery walk, ledger method, the register file and the 36-byte instruction charge.
The target is the plain one: the message is 64 bytes, 0^32 || x, one block, flags 11, standard IV; no prefix, no advice, no polarity climb, no scan. The chain step is {PH} operations for 256 trails ({perlane:.2f} per trail) against 19,022 in 0a9640ed and 18,866 in 3356413f. The price is the declared register file of 1,024 words of 256 bits (counted as memory, every transfer charged), a program of {instr} instructions of 36 bytes and a table of {tmax} entries.

## 1. Target and relation

Target `blake3-r3-prefix-v1` (the benchmark's blake3 round-3 profile). The two colliding messages are 64 bytes, M(x) = 0^32 || LE32(x): 32 zero bytes (words m0..m7 = 0) followed by the 256-bit integer x (words m8..m15, little endian). It is one chunk of one block: chaining value IV, counter 0, block length 64, flags 11 = CHUNK_START | CHUNK_END | ROOT, 3 rounds, digest = the 8 words v[i] XOR v[i+8] (i < 8), little endian (this is `verifier/blake3.py:blake3(M(x), 3)`). Write f(x) for the digest read as a 256-bit little-endian integer.
The walk is on g(x) = f(x) XOR q, where q is the fixed 256-bit mask (weight {qweight}) of the polarities of the 256 digest planes of the circuit that the generator of Section 3.2 builds; q is printed by `python3 bsrho.py --ledger`. g(x) = g(y) if and only if f(x) = f(y): XOR with a constant is a bijection. The attack outputs x != y with g(x) = g(y), hence f(x) = f(y), and M(x) != M(y) are two distinct messages with equal complete 256-bit digests (a finite byte string of 64 bytes is in the profile's message domain, "Finite byte strings of bit length below 2^64").
The scalar digest of the program (`digest_words`) was compared outside the shipped experiments with the organizer reference `blake3(M(x), 3)` on {nref_scalar} random messages: 0 differences. The bit-sliced step (`ext` check, not shipped) was compared with the reference on {nref_step} random messages (one step: stored planes equal blake3(M(x), 3) XOR q) and on 256 messages chained for 4 steps; the packed recovery circuit on {nref_packed} messages: 0 differences in each. The program's own selftest (`python3 bsrho.py --selftest`) compares the step against the scalar compression on 4,096 lanes (16 batches of 256, the full 256-bit g), 256 lanes chained for 3 steps, the register-allocated code executed on a register file, the width-18 chain, and the packed circuit.

## 2. The attack (program `experiments/bsrho.py`, sections 3 to 6)

Parameters for n = 256: N = 2^256, 256 lanes. A point x is distinguished (a DP) when its low 32 bits are zero and the 90-bit number F = (x >> 32) mod 2^90 is below Tp = {Tp}. The density is theta = {Tp} / 2^122 and L = 1 / theta = 2^{log2L:.4f}. The key of a DP is the 56 bits of x above bit 121 followed by the 8 low bits of F (F < {Tp} < 2^8, so those 8 bits are F); 64 bits in all.
One fresh uniform 256-bit word r (one operation).
Trail t (t = 0, 1, 2, ...) starts at s_t = r + t mod 2^256 and follows x -> g(x) until a DP.
1. 256 trails run in the 256 lanes: lane l of the bit planes holds the current point of its trail. A batch is one evaluation of g for all 256 lanes by the generated straight line of Section 3.2. Batch counter b = 0, 1, ...; the start of a trail is the point of its lane before the batch in which it was inserted.
2. After every batch the stage-1 test (Section 3.3) forms the 256-bit mask of lanes whose 32 low planes are all zero. If it is zero, the next batch runs at once.
3. For each set bit of the mask (a stage-1 hit) the lane is extracted and the window test F < Tp decides whether it is a DP. A lane at a DP ends its trail: key as above, length = batches since the trail started. If the key is in the table, go to 6. Otherwise store (t, length) under the key (25-byte entry, Section 7) and
   start trail t' = next index in that lane (insert the 256 bits of r + t' into the lane).
4. At every multiple of S = 2^48 batches: a lane whose trail has age >= c = 11 L batches is restarted with a new index (a cut trail).
5. The search halts (failure) after B batches, after e2max stage-1 hits, when the table holds {tmax} keys, when a third trail would be cut, or if step 6 finds no pair.
6. Recovery. The two trails have lengths l1 >= l2. Advance the first from its start by l1 - l2 steps of g, then step both together; at the first step
   with g(a) = g(b) and a != b output (a, b). Both lanes of one packed circuit ({PH7} operations: the compression and one XOR of each of the 8 output words with the 32-bit word of q; used by nothing else) are used. At most capr = c + S batches are run (the program halts if l1 > capr).
Constants (all computed by `plan(256)` of the program from the stated formulas, printed by `python3 bsrho.py --ledger`): Tp = {Tp}, L = {Lnum} / {Lden}, B = {B}, Q = 256 B = {Qratio:.5f} * 2^128 evaluations,
e2max = {e2max}, c = {c} (= 2^{log2c:.3f}), table capacity tmax = {tmax} entries of 25 bytes. The trail numbers t stay below 2^16 (finished trails <= {tmax}, cut trails <= 2, plus the 256 starts) and every length is below c + S < 2^119, so the 2-byte and 15-byte fields of an entry never overflow (the program asserts both when it stores an entry).
Per attempt: one fresh r; no restart, no amplification, no stored collision; no nonuniform advice (the mask q is derived by the generator at setup and is also written into the recovery circuit as immediates).

## 3. Operation ledger

### 3.1 Machine
Machine model declared by this entry (as in 0a9640ed, which passed the judges with it). This entry therefore declares a load/store machine with 256-bit words, 256-bit immediates and R = 1,024 registers (a premise of the entry, H3; Section 3.5 prices smaller files). Charged: every addition, AND, OR, XOR, shift, comparison, conditional branch and the one random word; every load of a word from memory and every store of a word to memory, one operation each; every register move, one operation each.
The main loop has no loads, stores or moves: the generated straight line needs {regs} registers (`allocate` in the program assigns them; output plane j is written into the register that held input plane j, so the next batch reads the same registers), leaving {spareregs} of the 1,024 for the loop counter, the limit and the handlers' temporaries. The file of 1,024 registers is counted as memory: 32,768 bytes (Section 7).
Constants are immediates. The organizer's reference count C(r3) = 638 (222, 430 and 638 for 1, 2 and 3 rounds) is used only as the unit: Unit = 638 operations. ### 3.2 One batch = {body} operations for 256 trails
Representation: a 32-bit word is 32 planes; plane j is a 256-bit integer whose bit l is bit j of the word of lane l. A rotation is a renaming of planes (no operation). XOR, AND, OR of words are 32 operations each. The sum of two words is a ripple of full adders over the planes; the lowest bit has 2 gates (no carry in) and the highest 2 (no carry out), and constants (the IV words, the zero words m0..m7, the length and the flag word) are folded at build time.
The full adder is the pivot adder of 6ae36351 (our re-implementation, `Gen.fa`). Each signal is a pair (node, polarity): the register holds the node's value and the true plane is that value XOR polarity, so complements are free. Of three variable inputs a, b, c, two have the same polarity (pigeonhole); take the third as the pivot p and the two equal ones as x and y. With u = x XOR p and v = y XOR p: sum = u XOR y, carry = (u AND v) XOR p, because maj(x, y, p) = p XOR ((x XOR p) AND (y XOR p)). u and v have equal polarity, so the AND is always one gate (an AND of two upright planes, or an OR of two inverted planes, with the result's polarity set); every full adder with three variable inputs is 5 gates (XOR for u, XOR for the sum, XOR for v, the AND, XOR for the carry). With one constant input, sum = x XOR y XOR k and carry = x AND y or x OR y (2 or 3 gates); with two the plane passes through. The program generates the straight line at run time (`trace`, `Step`): gates are hash-consed, a gate whose result no output uses is dropped.
The mask walk: the circuit's 256 output planes are stored in registers exactly as the circuit produces them (a register holds the node value, the digest plane is that value XOR q_j, q_j the polarity of the signal) and they are the 256 input planes of the next batch. So no operation complements a plane, no polarity vector is chosen, and the chain is x -> g(x) = f(x) XOR q. q is a fixed constant of the circuit (weight {qweight} of 256); the generator derives it while it builds the circuit, and the recovery circuit uses it as 8 immediates. Equality under g is equivalent to equality under f (Section 1), so a collision of g is a collision of f.
The generated line (`python3 bsrho.py --ledger`, `--selftest`): {gates} gates = {xor} XOR + {and_} AND + {or_} OR = **{PH} operations**, no complement operation. Per trail {perlane:.3f} operations = {unit:.4f} unit, against 1 unit for a compression and 0.1332 unit for the packed circuit of cf8b0e92.
Validation: 4,096 lanes against the scalar digest in the selftest (stored planes = f XOR q); 8,192 lanes and 256 lanes chained for 4 steps against the organizer reference (Section 1); the register-allocated code executed on a register file gives the same planes as the generated function (selftest).
The generator itself runs once at the start; its work is charged in the setup row (Section 3.3), its code and peak storage are accounted in Section 3.6 and Section 7.

### 3.3 Loop, stage 1, handlers and the other events
Loop body = one batch: {PH} + stage-1 test {filt} + loop control 3 = {body} operations. Stage 1: the 32 low planes of digest word 0 (stored planes, which are the planes of the next point x) are combined into the mask of zero lanes: 31 ORs over the 32 planes, a complement, a compare of the mask with zero and a branch: {filt} operations (`stage1_ops`). The test loses no event: a DP has all 32 low bits zero, so its lane is flagged.
Loop control: batch counter increment, compare with the next slice limit, branch back: 3 operations. A batch with no flagged lane (probability about 1 - 2^-24) does nothing else.
Handlers (charged per event at the stated bounds; instruction sequences use the same registers):
- Stage-1 hit (a flagged lane): store the 256 planes to a 8 KiB copy in memory (256 stores), then a loop over the planes: load, shift right by the lane number, AND 1, shift left by the plane number, OR into the accumulator, address increment, plane counter increment, compare, branch (9 per plane, 2,304), find the lane in the mask (at most 8 halving steps of 5), window test of F < Tp (3 extractions and at most 12 further operations), counters. Total below 2,800; charged **2,800** per hit (the polarity XOR of the earlier entries is not needed any more). The hit budget e2max is enforced by a halt.
- Finished trail (a DP, new start): key formation, three read-modify-write field stores of the 25-byte entry, the new start r + t' (1 add), insertion of the 256 bits of the new start in the lane: per plane load, shift, AND 1, shift left by the lane number, AND with the complement of the lane bit, OR, store, address and counter increments, compare, branch (12 per plane, 3,072), reload of the 256 planes (256), lane arrays and counters (below 200). Total below 3,550; charged **3,800**. The key scan of the table is charged separately: the key array holds 4 keys per word, testing a word costs 8 operations, charged 3 per key. At most tmax finished trails (a halt on a full table).
- Slice check (every 2^48 batches): the 256 births (load, subtract, compare, branch: 1,024), slice counter: charged **1,300** each. Cut trail: insertion of the new start as above plus bookkeeping, charged **4,200**; at most 2 cut trails (a halt on the third).
- Recovery batch (both lanes in one packed circuit, {PH7} operations, the last 8 of them the XORs with q) plus the exact equality test of lane 0 and lane 1 on the 8 output words, which is 8 shifts, 8 XORs, 7 ORs combining the 8 words, 1 AND with the lane-0 mask, 1 compare with zero and 1 branch = 26 operations, plus loop increment, compare and branch = 3: 29 operations, plus call and return 2 and 8 moves of the digest: 39, charged as 64 per recovery batch ({PH7p} per batch). The first l1 - l2 steps move one lane only and need no test, also inside the {PH7p}.
- Setup and generator: 1 random word; the 256 starts r + t inserted in memory (256 x 3,100 = 793,600, each at most 12 x 256 + 28) and one reload; counters; fixed part charged {setupfixed}. The generator: {gencalls} primitive calls (hash-consed gate constructors) and {PH} emitted lines, each charged 200 word operations: {gen}. Setup and generator together {setupall} operations = 2^{log2setup:.2f} units, charged in the time bound (3.4). There is no other preprocessing: no scan, no climb, no advice.
Code size, instructions: loop body {body} + handlers 1,000 (256 stores, 256 reloads, the loops and the event logic) + recovery 650 (the {PH7}-operation circuit, the test, the loop, the call and the moves) + setup, cut and slice 160 = {instr} instructions.

## 4. Success probability

Heuristic H1 (model premise, Section 5). Let F be a uniformly random function from 256-bit values to 256-bit values. The attack uses the walk function only by evaluating g at points that the procedure chooses. Write A_F for the same procedure with every evaluation of g replaced by F (lazy sampling), and P_F for its success probability, taken over the fresh word r and over F. H1 states that the probability that the single attempt succeeds on the fixed target is at least P_F. The premise compares two success events; it is not a statement about the entropy of r or about the target as a random object, and it is declared, not proved. Sub-claims under it (the numbers below are printed by `python3 bsrho.py --loss`) are computations for the random function F, with the approximations named as the supporting heuristic H2 (they are not proved here):
H2 (a) the age of the trail of one lane at the halt is dominated by an exponential with mean L, and the 256 ages are independent, although restarts depend on the history of the run; (b) the number of cut trails is Poisson with the stated mean; (c) the loss for a cut trail enters linearly with the stated slope; (d) trail lengths are geometric with mean L (used for the repeats inside one trail).

Lemma 1 (a statement about g itself, no premise). A pair x != y of evaluated inputs on two different finished trails with g(x) = g(y) is output: both trails continue identically from g(x), so they end at the same DP with the same key and
the stored lengths let step 6 align and walk them; it returns the first merge pair, found within max(l1, l2) <= capr batches (a trail is cut at a slice check once its age is >= c, slice checks are S batches apart, so every length is below c + S). The returned pair satisfies g(x) = g(y) with x != y, so f(x) = f(y); the recovery checks equality before it returns.
The key determines F (F < {Tp} < 2^8 and the key holds its 8 low bits), so equal keys of two DPs differ only if their bits above 177 differ. The lanes do not interact: the generated step applies the same function to every lane (Section 3.2), so lane l holds g^b of its start after b batches, exactly as a single scalar chain would.
The stage-1 test loses no event: a DP has its 32 low bits zero, so its lane is flagged and examined. A pair inside one trail makes a cycle with no DP (the trail is then cut). A 64-bit key match without a merge ends the run (failure, cost bounded by one recovery).

Lemma 2 (for the random function F, under H2). Let U be the number of evaluations on trails finished before the halt. The number of evaluations is Q = 256 B = {Qratio:.5f} * 2^128. For F the DP indicators of the successive points of one trail are independent with probability theta, so the age of the trail of one lane at the halt (steps since its last restart) satisfies P(age >= a) <= (1 - theta)^a <= exp(-a / L), and (H2 a) the
256 ages are independent: each is stochastically dominated by an exponential with mean L. The sum of 256 such variables exceeds M L with probability at most exp(-256 (x - 1 - ln x)), x = M / 256 (Chernoff); for M = {M} this is {tailages:.2e} <= 1e-6. So the 256 unfinished trails hold at most {M} L points except with probability 1e-6.
Cut trails cost at most c + S, that is {f1:.4e} Q each; the number K of cut trails is (H2 b) Poisson with mean (Q / L) e^-11 = {trails:.0f} e^-11 = {mu:.4f} (P(K=0,1,2) = {pk0:.4f}, {pk1:.4f}, {pk2:.5f}; P(K>=3) = {pk3:.2e}, and the third cut is a halt, charged as failure).
The allowance 1.5e-4 Q already in U covers {allow:.2f} of one cut trail; for K = 1 and K = 2 the remaining loss lowers the success probability by {d1:.2e} and {d2:.2e} (H2 c: slope of 1 - exp(-U^2/2N) at the target, 2 * 0.497 * e^-0.497 = {slope:.3f} per unit of relative loss), and K >= 3 is charged as failure, so the cut-trail deficit is {pk1:.4f} * {d1:.2e} + {pk2:.5f} * {d2:.2e} + {pk3:.2e} * 0.3916 = {cutdef:.3e}. Hence U >= (1 - 1.5e-4) Q - {M} L - 1 = {Uratio:.5f} * 2^128 when K = 0 and the ages are within the bound. For U distinct inputs the probability of no colliding pair is
prod (1 - i/N) <= exp(-U(U-1)/(2N)) <= exp(-0.497) (the program's B is the least that gives U(U-1) >= 2 * 0.497 N). The expected number of colliding pairs inside a single trail is at most Q L / N = 2^{log2inside:.2f} = {inside:.2e} (H2 d: a trail of length l has at most l(l-1)/2 pairs, E[l^2] <= 2 L^2, and there are Q / L trails). The expected number of key false matches (two different DP ends with the same 64-bit key: the key space is 2^56 * {Tp} = 2^{log2keys:.2f}) is below {tmax}^2 / 2 / 2^{log2keys:.2f} = {keyfm:.1e}.
Programmed aborts. Table capacity: the number of finished trails is at most the number of DP events among the Q evaluations, binomial with mean Q / L = {trails:.0f} (and no more than a Poisson count of the same mean in the Chernoff bound); the abort needs {tmaxp1} or more, probability at most exp(-mean) (e mean / {tmaxp1})^{tmaxp1} = 2^{log2cap:.1f} = {cap:.1e} (Chernoff bound). Stage-1 budget: the number of stage-1 hits is at most binomial with
mean mu2 = Q / 2^32 = {mu2:.2e} and the abort needs 2 mu2 + 65, probability at most e^(-mu2 (2 ln 2 - 1)) = e^(-{mu2c:.1e}). A recovery that finds no pair needs a key false match or a start lying on another trail (at most {keyfm:.1e} + 2^-100).
The losses add to 1e-06 + {inside:.2e} + {cutdef:.3e} + {keyfm:.1e} + {cap:.1e} + 7.9e-31 < {sumloss:.3e}, so P_F >= 1 - e^-0.497 - {sumloss:.3e} = {Pl:.4f} >= 0.39. The {margin:.4f} left over is kept as margin.
If the real pair-collision rate is (1 - eps) of the model, P stays at least 0.39 for eps <= {eps:.4f}, and in general at most 0.5 * log2(1/(1-eps)) more bits of time restore 0.39: 0.0072 for eps = 0.01, 0.037 for 0.05, 0.076 for 0.10, 0.21 for 0.25.

## 5. Premise H1 and its evidence

H1 is the model premise of Section 4. It is a premise about one fixed function g and about one attempt; it cannot be tested at width 256: the full 256-bit functional graph, trails longer than 2^40 and 2^128 evaluations cannot be observed. It is declared and not proved. Its content, in the terms the ledger uses, is: (a) for the inputs the search evaluates, the outputs behave as the outputs of F, uniform and independent, so that two distinct evaluated inputs collide with probability 2^-256 (this entry uses no input difference and does not claim that none exists); (b) the iterates of g from the starts r + t have the first-collision law of a random mapping; (c) whether an iterate is a DP is independent of the collision events and has probability {Tp} / 2^122. A deficit eps in the pair-collision rate costs 0.5 * log2(1/(1-eps)) bits ({eps_cost:.4f} for eps = 0.01), listed in Section 4 and in the note.
Evidence that the program is right and that nothing gross is wrong is produced by the two organizer experiments (Section 6). They are program checks: the organizer recomputes every returned pair, the counts of returned pairs are reported, and they are not used as estimates of any number of this entry. No quantitative inference is drawn from a count, no confidence interval is formed, and the entry does not rely on the independence of trials (the trial seeds are public and the experiment is a check of the program). The program also prints its own observations (`python3 bsrho.py --stats`, seeds from SHA-256 of a counter), which are untrusted and are only descriptive:
{statslines}
Run by the organizer's pipeline on this program with the public seed (the pipeline reruns each experiment and requires identical output), reported without inference:
{orgsum}
Every unsuccessful attempt of the width-18 experiment ended with a halt of the program (the halts equal the unsuccessful trials). At width 18 a halt "recovery found no pair" (a trail start lying on another trail) is frequent; at width 256 it has probability below 2^-100 (Section 4). It happens equally for the ideal function.
Not tested: the full 256-bit functional graph; iterations of length above 2^40; other values of K; the bit-sliced search above width 18. A deviation of g from H1 that raises the collision rate only helps; one that lowers it by eps costs the table of Section 4.

## 6. Experiments

Two organizer experiments run the shipped program `experiments/bsrho.py` (the program dispatches on the experiment id; no outside code or library is used; the standard library only).
`bsrho-n18`: per trial, from the trial seed, one attempt of the 256-lane search at width n = 18 (DP = low 2 bits zero, plan(18): {B18} batches, cut rule, table, recovery on the packed circuit) on the target chain g (K = 0: the block 0^32 || x, the low 18 bits of g); the trial returns the two 64-byte messages 0^32 || x, 0^32 || y when the attempt succeeded and two nulls otherwise. ## 7. Memory

Table: {tmax} entries * 25 bytes = {tablebytes} bytes (the table region is empty until the search starts). An entry is the key (8 bytes), the trail number t (2 bytes) and the length (15 bytes), kept in three arrays (keys 4 per word, numbers 16 per word, lengths one per 15 bytes); `pack_entry` of the program builds and checks it.
Code: {instr} instructions * 36 bytes (opcode, registers and an inline 256-bit immediate) = {codebytes} bytes (loop body {body}, handlers 1,000, recovery 650, setup, cut and slice 160).
Counters and copies: 16,384 bytes (trail numbers 512, birth batches 4,096, counters, and the 8,192-byte copy of the 256 planes used by the handlers). The 1,024 registers, counted as memory: 32,768 bytes. No advice. Memory peak = max(setup phase {ph1}, search phase {mem}) = {mem} bytes <= 2^20 = 1,048,576; the preprocessing is inside the setup phase. This is the search phase; the setup phase, in which the circuit generator runs, is smaller ({ph1} bytes, Section 3.6). Claim `memory_log2_bytes` = 20. `python3 bsrho.py --ledger` prints the total.
The table size is the largest that fits: tmax = floor((2^20 - {codebytes} - 32,768 - 16,384) / 25) = {tmax}, and Tp = {Tp} is the largest integer for which the table-capacity bound of Section 4 stays below 2^-40 (Appendix A computes both).
