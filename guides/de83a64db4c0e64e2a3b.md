# BLAKE3 B8v2: count the rolled round and inspect the revised planner

Source: `research/blake3_r7/b8v2/pkg/blake3/experiments/bsrho.py`

Public SHA-256: `a2ad71a0ea6d0df50e4ba3b137e55ec0d5ba314ab60be29bd8ac0a1f6f7d4d8b`

## Reviewed usage contract

This edition rolls the main bit-sliced hash program, unlike B4F’s separate packed-recovery loop. Two rounds are straight-line; a generic round body runs five times. The stored program is smaller than a fully unrolled representation, but every repetition and message permutation costs work. Its output planes are upright, so q=0 and this walk uses the digest itself. The source credits jungjipdo’s 6ae36351 for the pivot-adder and masked-walk methods; this implementation’s loop and accounting are reviewed separately. This revision replaces the B8 numerical model with 20,000-bin trapezoid quadrature, revised cut terms and explicit planning margins. The finite kernel and layout remain the same. These helper changes were read in the complete edition diff, not executed or certified here.

## Source inspection and available execution evidence

static-source-review; Fresh finite fixed-word interpreter, per-instruction visit counts, compiler/reference fixtures, artificial search/recovery and supplied-budget arithmetic. No numerical optimizer or original campaign..

One finite construction/compilation: 37,276 generator primitives and 19,803 stored main instructions. The isolated recipe is checked with a ten-second subprocess limit. No original walk, optimization or C build is launched.

## Declared inputs

**Exact target and message**: Seven rounds, reference unit 1470, standard IV, counter 0, length 64 and flags 11. The message is 32 zero bytes followed by little-endian 256-bit x. ROUNDS=7 and the independent reference fixtures establish the target used in this review.

**Loop structure**: KPRE=2 and LOOPS=5. A runs the two-round prelude, normalizes state polarities and loads message slots. B is one generic round. M permutes message slots between iterations. F performs final output XORs. The flat order is A, I, B, D, C, Z, M, J, F; control operations initialize, decrement, compare, exit and jump.

**Register and plane meanings**: The input uses 256 planes, each carrying 256 trials. State starts at register 256; message slots at 768; loop temporaries at 1312. The emitted program reaches 1,827 registers within a declared 1,856-register file. Input and output polarities are upright; qint and all eight q words are zero.

**Supplied-budget accounting**: The audit supplies Tp=22, B=10^35, kappa=13 and slice size 2^48 to the ledger, replacing the numerical budget calculation. These parameters test formulas; no particular success probability or optimized price is asserted.

**Safe compiler recipe**: Use the command below with the pinned download in a disposable directory. It constructs the finite program and prints executed operations, stored instructions and register extent. It does not start a walk or optimizer. --selftest includes actual collision attempts; --stats runs campaigns; --ledger and --loss invoke numerical planning. --gen-c only emits source.

**Other interfaces are different tasks**: The retained organizer routes include reduced-width target/control experiments and projected-output statistics. Neither is the compiler recipe. Their full statistical laws and general dispatch contract are outside this bounded review.

## Outputs and interpretation

**Stored versus executed instructions**: A=10,550; B=8,416; M=576; F=256. Stored count is A+B+M+F+5 = 19,803. Executed count is A+1+5(B+3)+4(M+1)+F = 55,210. The independent interpreter checks every flat instruction’s visit multiplicity, including control operations.

**Fresh finite arithmetic**: 256 complete-message digest fixtures agree with the independently pinned reference, whose empty/abc known answers are checked. The source interpreter, compiled step and independent fixed-256-bit interpreter agree. Two chained steps, 18/20-bit fixtures and seven packed recovery values pass. Changed final-output wiring and a changed loop count both fail comparison. This is not a universal compiler proof.

**Packed recovery is a separate circuit**: Recovery uses 1,532 operations per packed batch and seven 36-bit lanes. There are no eight final output-mask XORs because q=0. The main loop’s 19,803/55,210 distinction must not be substituted for this recovery circuit’s charge.

**Declared layout**: Uniform 36-byte records give 812,844 bytes of total code, 15,989 ten-byte endpoint records, a 59,392-byte declared register file and 16,384 bytes of counters/copies. Setup and search phase totals are 944,908 and 1,048,510 bytes. These are source-model quantities, not Python/native memory measurements or a complete machine-handler certification.

**Exact fixture numerator**: N=15553362744849668638257222670990388535891 word operations for the supplied Tp=22, B=10^35, kappa=13 budget only. The main batch costs 55,247 = 55,210 + 34 filter + 3 outer-loop operations. Setup charges 200 times (2 times 37,276 generator calls + 19,803 stored instructions), plus the fixed allowance. Slices, stage-1 hits, table events, cuts and two-pass recovery remain separate. Not a default or success-certified score.

**Packing and recovery boundaries**: The endpoint stores a 64-bit key and 16-bit trail ID; the 16,247-start envelope fits 65,536 field values. Four nonnegative record roundtrips pass and two upper overflows are rejected. Negative inputs are accepted and alias unsigned maxima, so callers must enforce nonnegative fields. Six one-batch artificial-map cases and four explicit recovery graphs pass; recovery graphs use 5, 7, 4 and 2 calls. They are not hash-collision witnesses.

**Numerical helper and cache boundaries**: The loss helper retains fixed 122/256-bit scales; a reduced-width wrapper does not pass n through. A synthetic oracle confirms the budget cache omits Sb: changing that parameter can reuse an old budget until the cache is cleared. No numerical probability helper was executed and no default-plan impact is inferred.

**What remains outside this audit**: No embedded C compiler, retained WebAssembly artifact, whole-script selftest, original search, statistical campaign or numerical success theorem was replayed. The existing three-round generator bundle cannot certify this new main-loop source. The declared layout and fixture numerator are not an accepted attack score.

**One additional round is not free**: Relative to the six-round rolled edition, the main stored body remains 19,803 instructions but another loop visit costs 8,416+3+576+1=8,996 operations. Packed recovery grows from 1,299 to 1,532 operations; its 233 extra 36-byte records add 8,388 code bytes. This is a code-size/work tradeoff, not constant-cost coverage of additional rounds.

## Failure modes

- Stored instruction count is not per-trial executed work; include loop control and message permutation.
- This main-round loop is not B4F’s packed-recovery loop.
- Do not carry a nonzero output mask from an unrolled edition into this q=0 program.
- The 1,827 used registers and 1,856 declared registers have different roles in the ledger.
- The supplied-budget numerator is not a default, optimized or success-certified price.
- Reject negative record fields and isolate caches when varying omitted parameters.
- Finite Python equivalence does not establish embedded C/wasm equivalence or universal generator correctness.
- A historical source comment or another package’s adjudication does not establish this edition’s status.
