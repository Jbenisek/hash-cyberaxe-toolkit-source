# BLAKE3 B4D: inspect the revised loss model

Source: `research/blake3_r4/b4d/pkg/blake3/experiments/bsrho.py`

## Reviewed usage contract

B4D retains the two-pass B4B/B4C walk and changes the numerical planning layer. Its full-width cut allowance becomes one, its default kappa becomes 13 and its memory spare rises to 64 bytes. This guide explains which implementation checks survive and which probability claims still need their own proof. The source retains credit to jungjipdo’s 6ae36351 and to 0a9640ed / 3356413f; this review does not reassign those contributions.

## Source inspection and available execution evidence

static-source-review; Own-pin finite arithmetic, allocation, packing, artificial recovery and mocked model/cache controls; no default optimization or numerical probability certificate..

One finite circuit construction and allocation, tested with a ten-second subprocess limit. No numerical integration, default planner, original search or statistical campaign.

## Declared inputs

**Target**: Four-round BLAKE3, unit 846, complete block 32 zero bytes followed by little-endian x, standard IV, counter 0, length 64 and flags 11. The stored walk g=f XOR q has the same collision predicate as f; that algebra alone does not prove a random-function success law.

**Retained layout**: Ten-byte endpoints contain a 64-bit key and 16-bit trail ID, with no saved length. The declared register file is 800 words and instructions are charged at 36 bytes each. Recovery first rediscovers both lengths and then aligns and advances the pair. Preserve the common-endpoint premise.

**Planning boundary**: The full-width plan calls _b256 and _lossq, with default kappa=13 and CMAX=1. Reduced plans still exist for 18 and 20 bits, but loss forwards no width: its replacement helper fixes N=2^256 and L=2^122/Tp. Calling it with a reduced plan is not a reduced-width probability certificate.

**Safe entry point**: The example compiles and allocates the pinned circuit only. It does not call plan(256), loss, the original --selftest/--stats campaigns or a package launcher. Numerical integration and default optimization were intentionally not run.

**Changing parameters in one process**: The _B cache key does not include Sb even though the model uses it. The bounded test substitutes a threshold oracle, changes Sb from 10 to 20 and demonstrates stale reuse. Clear the cache or use a fresh process for such experiments. This synthetic control does not establish an error at the fixed default Sb.

## Outputs and interpretation

**Fresh own-source kernel checks**: 256 independent full-message digest fixtures, two reference known answers, two masked steps, 18/20-bit fixtures and seven packed recovery values pass. Structural checks cover 24,422 allocated instructions and reject two mutations. Register extent is 771; packed recovery has 836 operations. The full-width generated program has no shared or dead gates.

**Exact declared layout**: Body=24,459, code=954,072 bytes and endpoint capacity=5,245. Declared setup/search phases are 1,042,104 and 1,048,506 bytes. Search is 70 bytes below one MiB, satisfying the declared 64-byte spare. These are source-model sums, not host process memory measurements or a complete generator-image recount.

**Finite implementation controls**: Four nonnegative packed-field roundtrips and two upper-overflow rejections pass. Negative -1 still aliases unsigned maximal fields. Six one-batch constant-map cases test an artificial pair, a miss and four budget exits. Four finite graphs require 5, 7, 4 and 2 recovery calls for equal lengths, unequal lengths, a shared path and a cap. No case is a real BLAKE3 collision witness.

**Supplied-budget arithmetic**: Every integer ledger part is recounted with Tp=22, kappa=13, 5,245 endpoints and a mocked B=10^35. Its exact sum is 8101160960899879977153686755488794245675 word operations. That B is an explicit fixture, not an optimized run length; do not quote the sum as an attack score.

**Changed model, changed warning**: The old request for 1,000,000,001 Poisson terms is removed. The replacement uses the global CMAX=1, hence two cut terms. Its _zq helper uses floating-point midpoint integration and numerical optimization; executing such a helper would still not establish a rigorous integration bound or its probabilistic assumptions.

**Edition-specific evidence limits**: The reviewed diff changes _plan, loss and plan; adds _zq, _lossq and _b256; removes inflight_m; and leaves 52 functions/classes unchanged. Fresh finite tests use B4D’s own source bytes. No retained C/wasm execution, organizer dispatch campaign or accepted price is transferred from B4 or B4B/C.

## Failure modes

- Do not carry the predecessor’s billion-term-allocation warning into this replacement helper.
- Do not treat a width-fixed loss helper as a reduced-width model.
- A cached run length can be stale after Sb changes; the mocked counterexample is not a default-rate measurement.
- A finite ledger sum is not proof of the probability used to choose its run length.
- Preserve common-endpoint recovery preconditions and reject invalid external packed fields.
- Reference fixtures and allocation checks do not certify full-width collision rates or every machine handler.
