# Template alignment: extract shared text and row values

Source: `research/launch/port/mktmpl.py`

Public SHA-256: `ca6dfd7f02ff33d4089376f0a50cec6e02002fc2402715c21423e7f6b34812f8`

## Reviewed usage contract

Align the same relative text file across row directories, preserve common text, and store changing numeric strings, whole lines and inserted/deleted blocks in a values table. The result reconstructs documents; scientific claims require their own proofs.

## Source inspection and available execution evidence

static-source-review; synthetic-template-controls-passed; historical-package-corpus-not-regenerated.

Reads all selected texts and performs sequence alignment against the first. Cost depends on line counts and repeated content; no fixed campaign or proof-generation cost is established.

## Declared inputs

**CLI**: python mktmpl.py OUTDIR FILE_REL ROWDIR... . Supply at least one row directory containing FILE_REL. For useful comparison use multiple independently identified rows. Inputs must be trusted local files and paths.

**Alignment**: Uses the first row as a base, splits on newline, and runs difflib.SequenceMatcher with autojunk=False on number-blind line skeletons. Recognized number fragments include lowercase UUIDs, eight-hex-digit strings and a limited decimal/scientific notation pattern, not a general typed numeric grammar.

**Row keys**: Uses the last path component matching r followed by digits and word characters, otherwise the final non-pkg component. Validate key uniqueness explicitly: two distinct paths ending in r39 produce one values key and overwrite each other's slot entries.

## Outputs and interpretation

**Template and values**: Creates OUTDIR if needed and replaces BASENAME.tmpl and BASENAME.vals.json. s slots store changing numeric fragments, W slots whole lines, B slots lists of lines. Different FILE_REL values with the same basename collide in one output directory.

**Console summary**: Reports template lines, fixed lines and slot counts. Those counts describe this alignment and do not measure generalization to new rows.

## Failure modes

- Derived row-key collisions silently overwrite values; the duplicate-key fixture reconstructs one row incorrectly.
- Output filenames use only the source basename, not its full relative path.
- Python text reads normalize newlines and the template writer forces LF; byte preservation requires a separate check.
- A single-row or whole-block template can reproduce its input without constraining a new row.
- No path containment, input schema or scientific validity check is performed. Use isolated, trusted fixtures.
