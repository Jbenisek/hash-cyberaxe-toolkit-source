# D126 shard pricing: replay the time-memory grids

Source: `research/luna_jobs/d126_memory_rule/price.py`

Public SHA-256: `56585f353df438847d671e56626e10cd5618aea38aa1ea88b0df56beddc9d43f`

## Reviewed usage contract

A historical accounting study for the memory-penalized score log2(T)+max(0,log2(M_bytes)-20). It separates shard-dependent work and storage from fixed overhead, then recomputes trial counts and finite caps. The portable lesson verifies its computed grids, not the underlying attack or implemented memory layout.

## Source inspection and available execution evidence

static-source-review; selected-arithmetic-replayed; original dependency modules, search and full research CLI not executed.

The audit evaluates 79 arithmetic rows, 222 stored class inputs and a scan inequality for 3600 class sizes. It completes in seconds on the checked workstation with one Python process per branch in sequence. The huge T values are modeled cryptanalytic work, not work performed by replay.

## Declared inputs

**r37 branch**: r37_rows() returns k=0..32. It needs selected constants, 222 recorded class/sample rows and arithmetic helpers from the exact r37c xtab edition. Conditional sample means are multiplied by 1.02; these remain assumptions, not proved expectation bounds.

**r38 branch**: r38_rows() returns k=0..45. It needs six ledger constants, pre_ops and three pinned cost JSONs. All 256 A0-block sentinel charges remain; only designated header/P6 terms shrink with the shard count.

**Original environment**: The original script hardcodes a workspace ROOT and dynamically imports package ledgers. It begins at Decimal precision 90; the r38 ledger import changes that to 80. Use the portable replay instead of running an unfamiliar full dependency tree.

**Probability inputs**: Finite-precision q3 conversions are retained and checked against their declared exponents with integer inequalities. This establishes the conversion direction, not the truth of those cryptanalytic rates or the shard sampling law.

## Outputs and interpretation

**Original return values**: Each branch returns k, trial count, exact rational T, memory bytes and floating time/memory logarithms. r38 also returns its reported overflow allowance. main() prints selected rows and omits both grid winners, k=5 and k=19.

**Portable JSON report**: All 79 rows, exact T numerators/denominators, byte counts, 191 rigorously upward-rounded time/score statements, original and ceiling-adjusted r37 memory values, and explicit conditional scope. No output files are written unless the user redirects stdout.

**Finite-grid minima**: Exact rational ranking uniquely chooses r37 k=5 and r38 k=19. The winning scores round upward to 90.87121 and 130.16628. These are model-grid optima, not new global-optimum or submission claims.

## Failure modes

- A sampled mean with a 2% uplift is not a certified bound. Fraction arithmetic cannot repair an unsupported input premise.
- Eight iterations do not prove general fixed-point convergence. The lesson instead certifies the resulting finite success inequalities for these inputs.
- The original r37 storage expression uses floor division; k=28..32 need one extra byte when interpreted as rounded-up nominal storage. Actual worst-case allocation requires additional evidence.
- The printed main() subset excludes both minima. Rank the complete returned grids, using exact T*max(1,M/2^20), not rounded displayed scores.
- Different Decimal import order or changed dependency bytes can change results. The lesson fixes the branch precision and pins its inputs.
- Manifest hashes detect changes, not a malicious replacement of the whole archive. No authenticity signature is claimed.
- Neither full attack correctness, sampled-mean validity, independent trials, balanced shards, peak memory nor instruction counts is certified by this arithmetic replay.
