# BLAKE3 B4: price stored trail lengths and instruction records

Source: `research/blake3_r4/b4/pkg/blake3/experiments/bsrho.py`

Public SHA-256: `07cb1f6a62b7f375d4ba6da2653846a2df8509ec7cd3790b2624c4494dc4f747`

## Reviewed usage contract

The older B4 implementation keeps each finished trail’s length in its table, avoiding the later editions’ first recovery pass. It uses large 36-byte instruction records and 26-byte endpoints; its table is therefore much smaller than the compact variants. This guide distinguishes that tradeoff from a success or price claim. The source credits jungjipdo’s 6ae36351 for the pivot adder and fixed-mask walk, and 0a9640ed / 3356413f for its surrounding implementation.

## Source inspection and available execution evidence

static-source-review; Own-pin finite arithmetic/allocation, retained-wasm output comparison, synthetic recovery/interface controls and explicit-Tp ledger. No original search..

One finite compiler/allocation pass: 49,724 generator primitives and 24,422 emitted instructions. The recipe was tested with a ten-second subprocess limit; the separate copied wasm probe has a twenty-second limit. No original experiment or loss optimization runs.

## Declared inputs

**Executed target**: Four rounds, unit 846, standard IV, counter 0, length 64 and flags 11. The 64-byte message is 32 zero bytes followed by little-endian 256-bit x. No selected prefix or nonuniform advice is used by this source.

**Stored value versus digest**: The circuit iterates g(x)=f(x) XOR q, with q determined by output polarities. XORing both sides with the same q proves equality is preserved; it does not prove the changed trajectory has random-function behavior. Unmask stored outputs before comparing unmasked digests.

**Endpoint fields**: A packed record stores a 64-bit key, 16-bit trail ID and 128-bit length, totaling 208 bits or 26 bytes. The source validates upper bounds but not nonnegativity. Its recovery helper requires two finished trails with a common endpoint; supplying arbitrary lengths does not establish that precondition.

**Declared machine layout**: The model assigns 36 bytes to every instruction, 1,024 registers of 32 bytes each, 16,384 counter/copy bytes and 26 bytes per endpoint. This is distinct from five-byte binary records and six-byte select records. The compact editions’ demonstrated immediate-format omission cannot automatically be transferred to this layout.

**Planner and diagnostic boundaries**: The full planner scans Tp values against a floating-point tail estimate; it was not invoked for this contract. The reduced-width plan sets cmax to one billion, and loss attempts to create cmax+1 Poisson terms. A guard verified the requested allocation and stopped it before materialization. Do not use the reduced loss route as a quick smoke test.

**Entry points**: bsrho-n18 is a reduced target/ideal experiment; proj-k0-w256 reports partial projections, not a full-digest collision. --selftest and --stats run actual research attempts and were not executed. The compiler-only recipe below is finite; --gen-c emits source rather than compiling it.

## Outputs and interpretation

**Four-round reference and allocation evidence**: 256 complete-message digest fixtures agree with the independently pinned reference, whose two known answers are checked first. Two masked steps, 18/20-bit fixtures and seven packed recovery values also pass. The 24,422-instruction program occupies one generated Python function; structural allocation checks cover every operand and output and reject two mutations. Register extent is 771, with no shared/dead gates for this source.

**Retained generator replay**: The copied no-import WebAssembly artifact emits all 24,422 matching 36-byte records and the same q on two calls in one instance. Its declared minimum and maximum are both 16 pages; observed linear memory is 1,048,576 bytes. The retained C text equals embedded GEN_C after line-ending normalization. No fresh C compilation, native memory certificate, instruction/fuel recount or new 1,522-instruction proof is claimed.

**Memory arithmetic and preprocessing**: The declared body is 24,459 operations: 24,422 kernel + 34 filter + 3 loop. Other code is 2,043 instructions; total code is 954,072 bytes. At 1,744 entries the declared search phase is 1,048,568 bytes, eight below one MiB. Setup is 1,042,104 bytes, including 16,856 scratch bytes and a 1,522-times-36-byte generator image. The generator makes 49,724 primitive calls per pass and is charged for two passes.

**Explicit parameter ledger, not an optimized score**: The runtime report supplies every integer term and numerator for the explicitly chosen Tp=22, kappa=11 and 1,744-entry fixture. No default Tp optimization or probability loss was evaluated. The exact arithmetic does not certify a success rate, every handler allowance, or a valid contest price.

**Stored-length recovery controls**: Six one-batch artificial search cases cover a returned pair, no first-stage hit and four budget exits. Four separate finite graph cases cover equal lengths, unequal lengths, the same path and a length cap. Returned pairs are synthetic, not BLAKE3 witnesses. Recovery uses the 836-operation packed circuit and does not first rediscover the saved lengths.

**Respect the common-endpoint precondition**: A deliberately inconsistent endpoint example with stored length 1 and capr=1 calls the oracle twice and returns no pair. Those paths do not have a common endpoint. This shows the helper does not validate its precondition; it is not an overrun proof for valid finished trails. Do not drop that distinction when quoting the test.

**Field and interface controls**: Four nonnegative record roundtrips and three upper-overflow rejections pass. Negative fields are accepted; decoding -1 preserves length -1 while the other fields become unsigned maxima. Mocked dispatch ignores target metadata and retains repeated negative trial IDs; unknown experiment names raise ValueError. These observations do not establish general input validation.

**Finite allocation guard**: The reduced loss helper requests exactly 1,000,000,001 terms. The test intercepts range and raises before allocation; no billion-element structure was created. This warning belongs to this implementation, not to later helpers that replaced that formula.

## Failure modes

- Do not substitute the later 10-byte endpoint, two-pass recovery or compact code layout.
- A generated program matching a reference does not validate its random-function premise or full cost ledger.
- The explicit Tp fixture is not a default optimized price.
- The reduced-width loss route requests a billion-element list; avoid unbounded diagnostic execution.
- Validate nonnegative packed fields and supply genuinely common-endpoint trails to recovery.
- Observed wasm linear memory is not native process RSS or a full simultaneous machine-memory proof.
- Keep source credit, rejected-price history and edition boundaries attached to reused code.
