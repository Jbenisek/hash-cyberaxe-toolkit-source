# Replay the recovered 31 SHA-256 compression witnesses

Source: `research/public_library/qa/replay_resolve31.cjs`

Public SHA-256: `164eb635c640e9044d505d8903f43c482e914a52899b6f63875fe0237da9a72b`

## Reviewed usage contract

Independently recompute a fixed archival collection of shared-chosen-CV SHA-256 collisions, including full state and feed-forward equality, a 64-step known-answer control and the same-pair one-extra-step negative control. This is a finite verifier, not a collision search or probability estimator.

## Source inspection and available execution evidence

static-source-review; bounded-replay-passed.

For the distributed registry of 29 pairs at 38 steps and two at 39 steps, the source makes 125 compression evaluations: four per pair and one 64-step abc control, totaling 4,846 compression-step iterations. It also reads/hashes the registry, checker and 31 files and constructs their JSON records. Filesystem/serialization cost depends on input sizes; no wall-time or peak-memory measurement is claimed.

## Declared inputs

**Archive root**: Optional first argument is the directory containing research/. With no argument, the current working directory is used. Paths in the registry and the checker's self-hash are resolved from this root; preserve the archive directory structure.

**research/luna/audit_packets/RESOLVE_1028.tsv**: Tab-separated registry with header page, source, kind, n, verdict. The program skips the first line and selects verdict VERIFIED. It requires exactly 31 selected rows. The distributed registry contains 29 at 38 steps and 2 at 39 steps.

**The 31 registry-selected source files**: JSON inputs supply M1 and M2 as sixteen eight-hex-digit word strings, cv as eight such strings, optional cv2, width w/width and optional R. The supported text format has M1/M2 W= lines followed by chain= lines. Both messages must use the same CV and 32-bit width. Files are read as data; no source file is imported or executed.

**The checker at its archived relative path**: The result includes a SHA-256 digest of research/public_library/qa/replay_resolve31.cjs resolved under the root. Moving or renaming only the executable without preserving that location breaks this self-hash dependency.

## Outputs and interpretation

**Standard-output JSON**: One object containing registry/checker hashes, abc known-answer result, summary, limits and 31 records. Records include source hashes, messages, shared CV, differing-word positions, states, feed-forward output and one-step-control outputs.

**Failure behavior**: Throws rather than returning a successful report if the known-answer control fails, the selected row count changes, input shapes/model are unsupported, any pair fails equality, or any pair also collides at its one-step extension.

**Filesystem/process effects**: The script performs reads and standard-output printing only. No source files are written, no child processes are launched, no remote service is contacted and no solver is invoked. Shell output redirection would be a separate user-requested write.

## Imports

- Node.js with standard fs, path and crypto modules; no npm packages.
- The 31 selected source files and registry, preserved beneath the archive root.
- No project encoder, solver or third-party cryptographic implementation is loaded.

## Worked examples

### Replay the archived collection

Working directory: <archive-root>, the directory containing research/

```text
node research/public_library/qa/replay_resolve31.cjs
```

Freshly executed against the distributed archive tree with an explicit archive-root argument, from a temporary working directory. Use the complete archive or portable replay kit, not just the downloaded script.

Expected: Observed JSON summary: verified=31, r38=29, r39=2, standard_iv=0 and one_step_collisions=0, plus known_answer.pass=true. A malformed registry was rejected in a separate negative control.

### Specify an archive root explicitly

```text
node <checker-path>/replay_resolve31.cjs <archive-root>
```

Replace angle-bracket placeholders with local paths. The archive-root still needs the checker's canonical relative path for hashing; quoting is required if either path contains spaces.

Expected: The same verification schema, with hashes derived from the chosen root's bytes. This verifies those bytes, not whatever a filename alone promises.

## Failure modes

- Do not use --help: there is no argument parser or help mode. The first argument is treated as a filesystem root and execution begins immediately.
- Reading the script as a module also executes its top-level verification work; it is not a side-effect-free function library.
- Malformed JSON, unsupported text formatting, non-hex words, missing files or incompatible round metadata cause exceptions.
- The tool is collection-specific, not a general arbitrary-pair command. Adding or removing VERIFIED registry rows intentionally triggers its 31-row guard.
- Equal output at a chosen CV is not an ordinary standard-IV padded-message collision; no padding or domain eligibility is certified.
- Failure at n+1 refutes unchanged extension only for these same messages and CV. It is not a theorem about all longer-round attacks.
- The replay does not verify tail estimates, generation costs, characteristic annotations or an unrestricted probability law.
