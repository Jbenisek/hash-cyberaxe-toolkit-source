# BLAKE3 compact pivot edition: inspect the three-round kernel

Source: `research/blake3_r3/compact_u5b/pkg/blake3/experiments/bsrho.py`

Public SHA-256: `354198c3c1a78f4900262a54ad9b4b4ab2d154a24774d8c12f48249620976c23`

## Reviewed usage contract

The compact_u5b r3 edition stores binary-gate instructions in five bytes and endpoints in ten bytes, freeing space for a larger table. It uses the pivot full adder and g=f XOR q walk credited in the source to jungjipdo. This guide follows ROUNDS=3 and UNIT=638, not the stale seven-round prose, and distinguishes implementation equivalence from attack-success premises.

## Source inspection and available execution evidence

static-source-review; Copied finite arithmetic, allocation and retained-wasm checks; synthetic flow/interface controls and declared default ledger. No original collision search..

One finite circuit compilation and allocation: 35,340 primitive generator calls, 17,238 instructions in nine chunks. No original search, selftest, statistics, default plan or loss integral executes in the documented recipe. This host-side work is not the contest operation price.

## Declared inputs

**Actual target and message**: ROUNDS=3, UNIT=638, standard IV, counter 0, block length 64 and flags 11. The complete message is 32 zero bytes followed by a little-endian 256-bit x. The module header, several docstrings and the ledger docstring retain seven-round/1470 wording; they do not override the executed constants.

**Walk and attribution**: Step computes g(x)=f(x) XOR q, with upright input planes and q derived from output polarities. Fixed q preserves equality of two outputs, but does not prove a probability law for the changed trajectories. The source attributes both the pivot full adder and masked-walk method to jungjipdo, 6ae36351 proofs 3.3 and 3.4.

**Pivot rule and compact instruction convention**: Choose a pivot p so the other two signals x,y have equal polarity. Set u=x XOR p, v=y XOR p; sum=u XOR y and carry=(u AND v) XOR p. The variable full adder uses five binary gates. A five-byte instruction record stores an opcode and three 10-bit register indices. This is a declared machine layout, not Python object size or an independently measured host instruction cost.

**Configured widths and default plan**: Widths n=18,20,256 are supported. The full-width plan selects Tp=1328, 87,359 entries, kappa=14, one allowed cut and 800 declared registers. Its loss calculation is floating point with fixed full-width scales. A selected plan is not an exact probability certificate; reduced-width applicability is not established by that formula.

**Experiment interfaces**: bsrho-n18 combines one masked target attempt with one keyed BLAKE2b ideal-control attempt. T1 instead iterates the unmasked f with a fresh 32-byte first message half. proj-k0-w256 uses 2,048 inputs, choosing the input family by trial modulo 3, then unmasks g before seven 21-bit projections. A partial w0 repeat is not a full-digest collision.

**Execution boundary**: --selftest includes six actual collision attempts; --stats runs campaigns. Neither was run for this review. The documented compiler-only recipe avoids those routes and avoids default plan selection. --gen-c prints source, not a compiled artifact. Original launch/build scripts were inspected only where needed and were not executed.

## Outputs and interpretation

**Exact local Boolean identity**: All 512 one-bit value/polarity/constant-substitution cases pass for each of the pivot and select adders. The 64 cases with three distinct variable bits cover every value/polarity combination and use exactly five or three emitted gates respectively. Wrong-sum and wrong-carry controls are rejected. Because the operations act bitwise, this proves the local adder identity at every plane width; it does not prove the entire hash generator or a one-operation hardware price for select.

**Fresh finite digest and allocation controls**: 256 full-message digests match the separately pinned independent reference; two fixed masked steps, 18/20-bit fixtures and seven packed recovery values pass. The 17,238 generated instructions span nine chunks and use register extent 771. Every allocated operand, chunk connection and final output was checked; two altered-assignment controls fail. This certifies allocation equivalence of this generated program, not universal correctness of the generator.

**Retained generator comparison**: All 17,238 compact records and q from the retained no-import WebAssembly artifact match fresh Python on two same-instance calls. The tested module declares minimum 3 and maximum 16 pages; observed linear memory is 196,608 bytes. The C text matches embedded GEN_C after line-ending normalization. No fresh C compiler build, 1,445-instruction recount, fuel recount or native memory proof is claimed.

**Exact declared numerator, conditional interpretation**: The default ledger sums to N=23073571264435560847886065804406703968283 word operations, with unit 638. The historical displayed time_log2 is 124.76596; this review recounts the stored model arithmetic after floating plan selection, not its full-width success premise or every handler allowance. Main body is 17,275=17,238+34+3 operations per batch.

**Declared memory phases**: Code is 132,935 bytes; counters/copy 16,384; declared registers 25,600; table 873,590. Search total is 1,048,509 bytes; setup formula is 223,351 bytes. Setup uses factor 200 times (2 times 35,340 generator calls plus 17,238 emitted instructions), plus the stated fixed setup charge. These are model formulas, not native process RSS.

**Two-pass recovery and record domain**: Entries hold a 63-bit key and 17-bit trail ID in 80 bits, with no stored length. Recovery recomputes both lengths, then aligns and advances. Six one-batch synthetic cases cover an artificial pair and budget/no-hit outcomes. Four nonnegative roundtrips and two upper-overflow controls pass; negative fields are accepted and can alias maximal unsigned fields. Internal IDs are nonnegative, so no default failure follows from that boundary control.

**Parameter cache and statistics**: The B cache omits Sb although the calculation uses it. A synthetic threshold oracle demonstrates stale reuse after changing Sb; this does not establish an error for the fixed archived default. Reset or isolate the cache for sweeps. Duplicate statistics count repeated entries, not all equal pairs: [5,5,5,7] gives 2 repeats and 3 pairs. The projection comments say 22 bits where the expressions retain 21.

**Protocol behavior**: Mocked dispatch accepts repeated/negative trial IDs and ignores target metadata, while unknown experiment IDs raise ValueError. Halt preserves prior counters. These are interface observations, not evidence that arbitrary inputs or original experiments are safe or scientifically valid.

## Failure modes

- Do not call this a seven-round result because the header says seven: the executed target is three rounds.
- Do not substitute the 11,718-instruction select edition or the earlier selected-prefix message family.
- Unmask stored g outputs before comparing them with unmasked f digests.
- Do not infer a new exact success law from fixed-mask collision equivalence or finite fixtures.
- Compact byte records and a 200-operation generator factor are accounting conventions, not measured Python charges.
- Validate negative packed fields and isolate the B cache when changing omitted parameters.
- Retained wasm agreement is not a new compiler build, native memory certificate or complete attack proof.
