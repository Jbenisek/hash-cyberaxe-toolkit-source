# Fair-run launcher: inspect the two-seed comparison

Source: `research/game/climber/guided/edge2/run_fair.sh`

Public SHA-256: `2be910860021d10c398aa2c93178c24217a6eb73538bb5a3ab7f8ccba28a8455`

## Reviewed usage contract

Historical two-seed comparison against a tunnel construction. This launcher runs one released 38-step characteristic with seeds 1 and 2 and appends progress/terminal events. Its comment mentions 542 seconds for the comparison method; the launcher does not measure or validate that external reference.

## Source inspection and available execution evidence

static-source-review; not-replayed-for-publication.

Two solver lanes, one launched 20 seconds after the other, at nice level 10. Nice is priority, not a CPU or memory cap. Both runs can continue indefinitely; encoding is also uncapped. Progress is checked every 60 seconds and normally logged near half-hour boundaries. There is no proved completion-time or attack-cost bound.

## Declared inputs

**Entry point**: bash run_fair.sh has no help, dry-run, argument parser or built-in cap. Executing or sourcing it starts work immediately. Paths are resolved relative to the script, not the caller's directory.

**Required layout**: Needs ../relscan/sha_cnf.py and ../relscan/cells/hyb38_pin38_to_pin38b_s17g5/rel_hyb38_pin38_to_pin38b_s17g5_A10.xml, Bash utilities, Python 3, Kissat, nice and writable /dev/shm. Encoder/decode dependencies and environment must be checked separately; this page is not a complete campaign bundle.

**Cached formula**: Both lanes use /dev/shm/edge2_fair_hyb38_A10.cnf and its .map. Existence of the CNF alone suppresses encoding; there is no digest, map-existence or completeness check. The second lane starts after 20 seconds, not after a synchronization barrier, so an unfinished first encoding may be visible.

**Model conventions**: A fresh encode forces SIGNED=1 and passes the label sfs, inheriting the remaining environment. Whether CV equality, message nontriviality and final equality hold must be established from that exact encoder and XML, not the label or the launcher's comment.

## Outputs and interpretation

**Event ledger**: Appends to RESULTS_fair.tsv: name, seed, status and a status-dependent fourth field. START stores local HH:MM; RUNNING stores elapsed whole minutes; terminal events store seconds. BUILDFAIL has only three fields. The published 26-row table has two starts and 24 progress events, no terminal outcomes.

**Per-seed artifacts**: Writes fair_hyb38_A10_s1.out / s2.out, extracted .model files on SAT, and FOUND_fair_hyb38_A10_s1.txt / s2.txt decode text. Repeated invocation can overwrite these paths while appending another set of ledger events. Shared /dev/shm CNF and map are not cleaned up.

**Verdicts**: Kissat exit 10 maps to SAT, 20 to UNSAT, anything else to ERR<code>. On SAT the decoder's output must contain outputs equal: True or the label becomes SAT_CHECKFAIL. This gate does not separately require messages differ: True, does not run the independent checker, and does not verify all original clauses.

**Final process status**: The shell prints FAIR DONE and cats the ledger after wait. No set -e or final aggregate success check exists. A zero shell exit or FAIR DONE text is not evidence that both lanes succeeded.

## Failure modes

- Do not run it as a help command or source it into a shell; either starts the two lanes.
- Existing or partially written shared CNF files can be stale or inconsistent with the map.
- The shell has no trap that guarantees child termination when interrupted; do not assume stopping the wrapper stops the solver.
- Several command paths are unquoted; whitespace-containing locations are not supported safely.
- Progress rows are right-censored observations, not completed runtimes or independent trials.
- Decoder marker matching is weaker than independent verification and does not establish distinct messages.
