## Reviewed usage contract

B6v2 keeps the six-round circuit and declared layout, but revises the numerical planning helpers: trapezoid quadrature, cut-loss terms, margins and the planning threshold. Those changes were read in the complete edition diff; neither the numerical model nor its claimed success theorem is validated by the finite tests here.

## Source inspection and available execution evidence

static-source-review; Own-source finite kernel, compiler-only recipe, synthetic recovery and exact supplied-budget accounting. No optimizer, numerical probability replay or original campaign..

One fixed construction/allocation, checked in a subprocess with a ten-second limit. No numerical optimization or original collision search.

## Declared inputs

**Six-round target**: One full BLAKE3 block: 32 zero bytes followed by little-endian x. Six rounds, unit 1262, counter 0, length 64, flags 11 and the standard IV. The walk uses f XOR q, not the unmasked digest.

**Circuit and recovery**: 256 bit-sliced lanes; 38,790 binary main operations, 771 allocated registers, 20 compiled chunks. Recovery packs seven 36-bit lanes and uses 1,307 primitive operations before separately charged handlers.

**Declared representation**: 36 bytes per instruction, 800 declared registers, 10-byte endpoint records, 64-bit keys and 16-bit trail identifiers. The memory limit is 1,635,324 bytes, not one MiB.

**Model boundary**: The loss helper fixes L=2^122/Tp and N=2^256. Reduced-width inputs to its wrapper do not change those constants. The run-length cache omits Sb; clear it or use a fresh process when changing Sb. Mocked controls demonstrate the interface behavior, not that the fixed default is affected.

**Safe finite entry point**: Use the fingerprinted download in a disposable directory. The example only constructs and allocates the circuit. Do not substitute --selftest, --stats, the default planner, an original search or embedded-C generation for this bounded example.

## Outputs and interpretation

**Independent finite arithmetic**: 256 fixed full-width lanes match an independent BLAKE3 reference. Two known answers, two chain steps, reduced 18/20-bit cases, packed recovery fixtures, allocated instruction/chunk checks and two mutation controls pass. Not a universal generator proof.

**Declared phase accounting**: Main=38,790, stage filter=34, batch body=38,827; code=1,488,276 bytes and table=10,500 records. Setup/search phases are 1,599,956 and 1,635,260 bytes. Code alone exceeds one MiB. These are source-model quantities, not measured Python memory or a full handler audit.

**Two distinct memory components**: The allocation limit has log2(memory/2^20)=0.641145068585687400826193775239631132667199257817703796661556. The declared occupied phase peak has component 0.641088606203049511684103383803762893766300423258274883332478. Neither is a complete attack score; retain the chosen convention when reproducing a historical claim.

**Trail and field boundaries**: The start envelope 256+10,500+1+1=10,758 fits the 65,536-value trail field. Four nonnegative packing roundtrips and two upper-bound rejections pass. Negative -1 aliases unsigned all-ones fields; callers must validate nonnegative inputs.

**Supplied-budget ledger**: For Tp=22 and B=10^35, exact independently expanded components sum to N=12497547512969349027986683043134065468078. Recovery is charged twice at 1,307+64=1,371 operations per batch, plus 600. The fixture supplies the budget: it does not establish a successful, default or optimized attack.

**Artificial interface fixtures**: Six one-batch search branches and four endpoint-recovery graphs pass. The graphs require 5, 7, 4 and 2 calls respectively. They check program behavior, not real BLAKE3 collision witnesses.

## Failure modes

- Do not reuse five-round unit 1054: this target uses 1262.
- Do not claim this code fits below one MiB.
- Do not infer a complete attack score from the memory component or supplied-budget numerator.
- A revised numerical helper does not by itself prove a probability theorem or target-transfer assumption.
- Finite fixtures are not an independent audit of every machine handler, C/wasm generator or historical adjudication.
