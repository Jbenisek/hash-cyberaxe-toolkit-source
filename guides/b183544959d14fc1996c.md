# A/E/W prefix checker: the exact verify_full contract

Source: `research/tools/kepler_tools/verify_full.py`

Public SHA-256: `9ff45f77094f60f4def7a6b2e8a661abd4b3f852f7eb42331b45862bdd03e476`

## Reviewed usage contract

Compare a numerical pair's A, E and W rows with a characteristic through an inclusive endpoint using the first recorded chaining value for both messages.

## Source inspection and available execution evidence

static-source-review; source-specific-disposable-CLI-controls-passed; no-solver-run.

Two traces of max(k+1,17) steps and bounded mask comparisons; no search cost or success rate is estimated.

## Declared inputs

**PAIR.txt**: M1: W= and M2: W= fields, each containing sixteen lowercase eight-hex-digit words. The first chain= or cv= field supplies both starting states; if absent the standard IV is used. A second chain is ignored, so reject unequal chains before calling.

**TRAIL.xml and k**: Text rows with 32-symbol A/E masks and optional W masks. Require complete unique rows 0..k and 0<=k<=39. k is inclusive. This source has only 40 constants; k=40 raises IndexError.

**--iv**: Forces the standard IV even when the header specifies another chain. The mismatch is printed, not rejected. Validate your intended domain separately.

## Outputs and interpretation

**Per-row diagnostics and TOTAL violations**: Counts A/E/W violations and the W subtotal. Symbols -,u,n,x,0,1 constrain equality, ordered or unordered difference and fixed equal values. Other symbols are skipped; validate the alphabet first.

**VERIFIED / INVALID and exit code**: Both verdicts exit zero for parsed inputs. Consume the numerical violation count and independently validate the requested predicate, not just the process code or a substring.

## Worked examples

### Check an explicit common-chain prefix

Working directory: Directory containing verify_full.py, PAIR.txt and TRAIL.xml

```text
python -B verify_full.py PAIR.txt TRAIL.xml 16
```

Expected: Rows 0..16 are checked, including expanded W16 when its mask is present. Require zero total violations and the intended common chain. This is only a 17-step prefix check.

### Force the standard IV deliberately

Working directory: The same directory

```text
python -B verify_full.py PAIR.txt TRAIL.xml 16 --iv
```

Expected: The trace uses the standard IV. A reported nonzero chain distance must be resolved before using this as evidence about the original pair's declared context.

## Failure modes

- A second unequal chaining value is ignored.
- An absent W field contributes zero W violations; this is not a complete schedule-mask check unless the mask is present.
- Negative k yields an empty condition loop and a passing label; unknown symbols are unconstrained.
- INVALID exits zero and --iv does not reject a differing chain header.
- It does not certify message distinctness, padding, complete XML validity, final feedforward output or a legal-message collision.
