# Build a full-trail query from a schedule pattern

Source: `research/cloud_jobs/API_FULLTRAIL_fulltrail.py`

Public SHA-256: `bdbd5f88e455d327080539612c9882e00df24d2ef640da855e15f7e3aaa69e55`

## Reviewed usage contract

Build an nldtool-style SHA-256 query from the signed expanded-word pattern of two supplied message blocks. This frees middle state rows while asking for equal initial and terminal states; it does not pin the numerical messages or produce a collision witness.

## Source inspection and available execution evidence

static-source-review; six disposable synthetic CLI fixtures; no encoder or solver.

The helper expands two small word schedules and writes O(R) fixed-width row strings. This is query construction only, not the cost or success probability of solving the query.

## Declared inputs

**Message pair file**: M1 and M2 lines must each contain exactly 16 valid hexadecimal 32-bit words. Validate this externally: the original writer ignores extra tokens, accepts wider words and fails unclearly on short input.

**Round count**: Integer R supported by the intended downstream SHA-256 profile. The writer itself accepts R=0 and has no target-profile range validator.

**Fresh output path**: The original script writes OUT.xml unconditionally and overwrites an existing destination. Use a new, isolated output location.

## Outputs and interpretation

**XML query**: f=sha2, w=32, n=R. A/E rows -4..-1 and R-4..R-1 are equal-sign rows; intervening state rows use question marks. Every nonnegative row has the expanded W sign pattern, not fixed word values.

**Worked 39-step boundary**: Initial rows -4..-1: four A/E rows ask for a common, freely chosen chaining state. Middle rows 0..34: 35 A/E rows are unconstrained. Final rows 35..38: four A/E rows ask for equal terminal states. Together these are 43 row records, while W rows 0..38 retain all 39 prescribed schedule patterns.

**Console summary**: Reports R+4 state-row records and a list of differing expanded-word row indices. This summary is not a SAT verdict.

**Sign direction**: This writer uses u for first-side bit 1/second-side bit 0 and n for first-side bit 0/second-side bit 1. Match that convention to the exact downstream encoder rather than assuming another tool's convention.

## Failure modes

- The writer does not reject identical messages or enforce nontriviality. A downstream encoder may impose additional conditions; this audit does not assume them.
- A 33-bit input can affect expansion although the initial printed row shows only its low 32 bits. Validate all input words first.
- An extra seventeenth word is silently ignored. A 15-word input fails with IndexError in the inspected edition.
- The emitted question does not establish shared-IV reachability, standard-IV hashing, padding, feasibility, complete encoding soundness or an attack price.
- The portable replay rejects a changed original source even if its manifest is rehashed, missing source and optimized -O mode. It does not certify every downstream tool or every input.
