# Poseidon collision logs: parse and verify recorded pairs

Source: `research/poseidon/orchard/exec_r2e/verify_collision.py`

Public SHA-256: `c78a48a119c772c52450cd3fed27d30f11538289695baf44534ed1b2be9e62c2`

## Reviewed usage contract

Read lean_attack-style COLLISION lines and compare the two messages with the project reference, optionally also the organizer implementation. The bounded publication tests explicitly block organizer imports and certify only the reference-only mode.

## Source inspection and available execution evidence

static-source-review; twelve-copied-log-controls-passed; organizer-execution-not-performed.

Two reduced reference hashes per recognized complete log, plus optional organizer checks if available. This is witness verification, not a discovery-cost or success-rate estimate.

## Declared inputs

**Log paths**: python verify_collision.py LOG... . Recognizes lines beginning COLLISION TAG 0x followed by 64 lowercase hex characters; trailing text is not validated. Expected tags are nk1, rho1, nk2, rho2 and digest. Repeated tags overwrite earlier ones. No digest tag means the whole file is skipped.

**Environment and parameters**: R defaults to 1 and counts partial rounds plus eight full rounds at their original indices. R=0 is not the identity. ORCHARD_CONSTANTS_JSON points the reference to its parameter data. Canonical field inputs must be below the pinned Pallas modulus.

**Optional organizer**: The script attempts a relative-clone import and catches any import exception. If unavailable, it continues with the project reference alone. A successful exit therefore does not establish two-verifier agreement.

## Outputs and interpretation

**Recognized records**: Prints collision verified or FAILED, reference status, and organizer status. Any recognized failing record causes exit 1; malformed required fields may raise an exception.

**Skipped records**: No files, logs without a parsed digest, and uppercase-only hex digest lines can produce exit zero with no collision verified line. Require a positive explicit verified-record count in addition to a successful exit.

## Failure modes

- Skipped or absent records leave ok_all true and exit zero.
- Last duplicate tags win; the parser does not enforce one complete record per file.
- Uppercase hex is not parsed, while trailing text after a 64-hex prefix is not rejected.
- An optional organizer import failure downgrades checking rather than failing the run.
- Partial-round environment errors, missing fields and noncanonical elements can raise before a final summary.
- The reference uses assertions for schedule bounds; do not run with -O.
