# Pallas base field modulus.

## Purpose recorded in the source

Organizer-owned byte-message Poseidon reference implementation.

The target is the Poseidon instance deployed in Zcash Orchard: `PoseidonHash`,
the `P128Pow5T3` parameter set over the Pallas base field. Width 3 with rate 2
and capacity 1, S-box x^5, R_F = 8 full rounds (four leading and four
trailing) and R_P = 56 partial rounds between them, so 64 rounds in total.
Each round adds its round constants to all three state elements, applies the
S-box (to every element in a full round, to element 0 only in a partial
round), then multiplies the state by the MDS matrix.

Reduced variants execute rounds 0 through rounds-1 of that fixed deployed
schedule and stop. This is a prefix reduction, so round i always uses row i of
the deployed round constants and the deployed MDS matrix is never regenerated.
Rounds 0 to 3 and 60 to 63 are full; rounds 4 to 59 are partial. Any prefix
from 1 to 64 rounds is supported; the hash mode, initial state, message
encoding and output encoding are always exactly as deployed.

Hashing uses the deployed `ConstantLength<2>` domain: a message is exactly two
field elements, the initial state is [m0, m1, 2^65] where the capacity element
is L * 2^64 with L = 2, one permutation is applied, and the output is state
element 0. No padding block is ever appended at this length.

A message is exactly 64 bytes: two 32-byte little-endian field elements, each
strictly less than p. Non-canonical encodings are rejected, because x and
x + p would otherwise encode one field
