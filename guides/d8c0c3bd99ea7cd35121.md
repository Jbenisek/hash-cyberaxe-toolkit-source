# BLAKE3 bitslice2: a fixed first block changes the circuit and the accounting

Source: `research/blake3_r3/bitslice2/pkg/blake3/experiments/bsrho.py`

Public SHA-256: `4f46578df1c1bec00b363b269bd139833fd61c3f734f4c5513685f60cd2ee943`

## Reviewed usage contract

This edition combines the selected-prefix 128-byte message family with a 256-lane bit-sliced chain. Its changed chaining value, flags and polarity mask produce a different circuit and table plan from the single-block edition. The guide records its own finite arithmetic, structural allocation and interface checks, and distinguishes explicit preprocessing charges from a proved historical execution or full attack price.

## Source inspection and available execution evidence

static-source-review; copied finite digest and compiler checks, structural allocation certificate, synthetic capped flow, declared-ledger arithmetic and mocked experiment routes; no original search.

One prefix compression and finite packed-circuit generation at import, then 42,942 recorded generator primitives, 18,869 emitted instructions and one straight-line register assignment. This is bounded host compilation, not a measured contest-operation certificate. No prefix scan, target/ideal birthday run, fresh-key first-repeat run, selftest campaign or projection experiment is executed.

## Declared inputs

**Hash and message context**: The message is P || K || x, with a fixed 64-byte P and 32-byte little-endian K and x. The target has K=0. P uses standard IV, counter 0, length 64, flags 1 and three rounds; the last block uses its chaining value, counter 0, length 64 and flags 10. PREFIX_I=10768619076 defines P as words [PREFIX_I mod 2^32, PREFIX_I >> 32, 0, ..., 0]. Fresh-key T1 varies K inside the last block; it does not replace P. The scalar helper's K||x shorthand omits the prepended fixed block.

**Bit planes and stored polarity**: Each of 256 machine-word bits represents one lane; each plane represents one chain-state bit. Rotations rename planes rather than execute shifts. Stored plane j may be complemented according to the fixed PINS mask. Step() corrects output polarity to the same input convention, allowing repeated steps without representation changes. pack_lanes, lanes_of and lane_value must use that same polarity.

**Widths and plan support**: Plan configuration exists only for n=18,20,256; plan(22) raises KeyError. The full plan declares 1,024 registers, 256 lanes, one stage-1 test per step, s1=32 and W=90. Its source-selected threshold is Tp=142 with 10,157 endpoint entries. The 32-byte advice word is subtracted before selecting capacity. Smaller-register fallback prices are not independently audited here.

**bsrho-n18 event**: Each requested trial runs one 18-bit target attempt, one keyed BLAKE2b ideal-control attempt and a fresh-key 12-bit first-repeat statistic. Only the target can supply the returned message pair. T1 changes K in the last block of P||K||x; the target keeps K=0 and both keep P fixed. These controls do not establish a full-width random-mapping law.

**proj-k0-w256 event**: The source computes 2,048 full-width digests per trial and observes seven 21-bit projections. trial ID modulo 3 chooses uniform derived inputs, consecutive counter inputs or eight chained steps from 256 starts. Only a repeat in projection w0 with distinct input messages can produce a returned pair. It is a 21-bit event, not a full-output collision; chained inputs and repeated values require their own sampling interpretation.

**Protocol validation and safe command**: experiment_id must be bsrho-n18 or proj-k0-w256; unknown names raise ValueError. Target metadata is not validated and repeated IDs are not deduplicated. selftest() runs six original collision attempts; --stats runs a larger campaign; the added --scan performs an unbounded reduced-condition prefix search. None was executed. The finite compiler example builds the circuit and allocates registers only.

## Outputs and interpretation

**Finite arithmetic and representations**: This edition's 256 complete 128-byte digests match the independently pinned reference. The selected prefix chaining value and A1+B2 cancellation are independently checked; 14 controls omit or mutate the prefix and differ. Two fixed chain steps, two allocated executions, 18/20-bit fixtures, stage-1 masks and seven packed recovery values pass. Packed recovery has 593 instructions. These finite checks do not prove universal hash-generator correctness or prefix minimality.

**Generated straight-line allocation**: The full step emits 18,869 instructions and has register extent 771. Every generated AST operation, symbolic register operand and output is checked; induction establishes equivalence of the generated straight-line step and its allocation for arbitrary plane inputs. Fresh altered-register and altered-operator controls are rejected on this edition. This does not certify universal generator/hash equivalence or handler/caller storage.

**Declared default ledger**: The declared body is 18,907 operations: 18,869 kernel operations, 35 filter operations and 3 loop operations. Its exact declared sum is 26,298,591,365,305,506,571,259,324,304,469,458,500,594 word operations, with units divided by 638. Generator allowance is 200 times (42,942 primitive calls + 18,869 emitted instructions) = 12,362,200. The sum includes the explicit prefix-scan term. These are formula evaluations after floating-point plan selection, not independent handler/generator allowance or success proofs.

**Memory scope**: The declared unrounded storage sum is 1,048,561 bytes: 745,452 code bytes, 32,768 register bytes, 16,384 counter/copy bytes, 32 advice bytes and 10,157 x 25 table bytes. This formula has 15 bytes below 1 MiB. No separate whole-word placement/rounding certificate is established here, and this abstract instruction model does not measure Python RSS.

**Duplicate entries are not equal pairs**: dup_w0 and the other dup_* fields compute len(values)-len(set(values)). A value appearing c times contributes c-1, whereas all equal pairs number c(c-1)/2. The synthetic values [5,5,5,7] yield the program's duplicate count 2 but equal-pair count 3. The statistics printer compares duplicate totals with a pair-count expectation; the audit exposes the semantic mismatch, not its magnitude in historical runs or an invalidity proof for every sparse sample.

**Exact projection bit positions**: Every projection is masked to 21 bits. p01 retains low 11 bits of word 0 followed by low 10 bits of word 1. p23 retains low 11 bits of word 2 followed by bits 11 through 20 of word 3, because the source shifts by 107 before masking. These are not two intact 11-bit pieces after the final mask. Seven formulas were checked independently on 256 digest fixtures.

**Counters and capped control flow**: This edition keeps a mutable counter dictionary through Halt: synthetic batches=3 and stage1_hits=2 survive with halt=1, unlike the zero-reset wrappers of b3r3t/lc. Six one-step artificial-map fixtures cover a recoverable pair, no stage-1 hit and stage-1/table/recovery/cut budget exits. Synthetic pairs are not BLAKE3 witnesses; batch counts still do not count all recovery, setup or generator operations.

**Unsafe reduced-width loss helper**: Reduced plans set cmax=1,000,000,000. loss(p) constructs cmax+1 Poisson terms, so loss(plan(18)) or loss(plan(20)) attempts a billion-term calculation. This is a source-derived resource hazard; the unsafe path was not executed. The documented finite example does not call loss, a search or selftest.

**Preprocessing arithmetic and scan boundary**: The ledger adds 10,768,619,077 x 717 + 1 = 7,721,099,878,210 declared prefix-scan operations. A one-candidate check verifies the retained prefix; five synthetic fixtures check hit/exhaustion counts and the exclusive upper limit. None proves an earlier candidate could not work, that the historical scan was executed, or that every operation fits the 717-operation allowance. --scan itself was not run.

## Failure modes

- Use the bit-plane polarity consistently; a stored complemented plane is a representation choice, not a different hash.
- Do not treat 18-bit target pairs, 21-bit projection pairs or fresh-key 12-bit observations as full 256-bit collisions.
- Count repeated entries and all equal pairs separately; they differ once multiplicity reaches three.
- Projection p23 uses word-3 bits 11 through 20, not its low 10 bits.
- Do not execute loss(plan(18/20)); its billion-term loop is outside the intended full-width loss path.
- selftest() and --stats launch original searches; the documented compiler example does not.
- A generated-step allocation certificate does not prove the full hash generator, handlers or caller fit the same budget.
- Declared cost formulas and floating-point tail selection are not an independently proved success rate or complete price.
- Do not drop the fixed 64-byte prefix or use single-block flags 11 when verifying returned messages.
- Fresh-key T1 changes K in the final block, not the fixed prefix P.
- CLI --scan launches a prefix search; verifying the retained prefix does not establish scan execution or minimality.
- Do not transfer the single-block 19,022-instruction count, threshold 138 or memory formula to this source.
