# BLAKE3 b3r3lb: a selected first block, a smaller second-block kernel and separate preprocessing

Source: `research/blake3_r3/b3r3lb/pkg/blake3/experiments/rho.py`

Public SHA-256: `636e841494c0be8567c16eea7a0329b4ae56309acaf76fa656ef96ab7b6901be`

## Reviewed usage contract

This edition changes the message family, not just the loop price: M(x) is a fixed 64-byte prefix P, then 32 zero bytes, then a little-endian 256-bit x. The prefix produces a chaining value that cancels one first-round sum in the final block. Constant folding yields 593 packed instructions, compared with 595 in b3r3s. This is a verified finite arithmetic property of the retained prefix; it does not prove a full-output collision, a random-mapping success law or historical prefix-search minimality.

## Source inspection and available execution evidence

static-source-review; copied finite helper, independent two-block digest and prefix controls, exact declared-ledger arithmetic and artificial grouped-flow fixtures; no original search.

One prefix compression and finite circuit construction at import, then 10 seven-lane batches and 70 scalar last-block checks, plus the two local column computations used by prefix_condition(). No prefix-selection enumeration, walk, recovery campaign or CLI equivalence search is run. Historical prefix-selection work and full search pricing remain separate.

## Declared inputs

**Exact two-block convention**: Use all 128 message bytes. The first 64-byte block has the standard IV, counter 0, length 64 and flags 1. The final block has its chaining value, counter 0, length 64 and flags 10. Both compressions use three rounds. Hashing only the last 64 bytes with flags 11 is a different message and target.

**Pinned first block**: PREFIX_I=10768619076. P has little-endian words [PREFIX_I mod 2^32, PREFIX_I >> 32, 0, ..., 0]. The resulting CV is [3205528875,411291139,60262883,489927237,809493467,642014741,3157960105,1883752943]. The first-round zero-message columns of the final block satisfy A1+B2=0 mod 2^32. The bounded check verifies this selected P independently, not the absence of earlier solutions.

**Request and event**: JSON trials require seed and trial fields; identifiers are returned. Seeds are string-formatted with the attempt index before SHAKE-256. schema_version, target_profile and event do not validate or select a target. Default run_trial uses n=22 and up to 60 attempts. attack() separately uses n=256 and one attempt. A default returned pair is only a 22-bit event.

**Import and safe helper**: Import computes one prefix chaining value and emits the finite packed circuit; it does not launch the prefix scan or a walk. The imported selftest() checks 70 fixed inputs. CLI --selftest also runs equivalence() on 24 seeds with two group sizes: 48 original search calls. Use the documented imported-helper command instead.

**Separate profiles**: The full-width plan selects s1=32, W=90, Tp=401 and U=16; its distinguished density is 401/2^122. The reduced 22-bit plan uses s1=4, W=4, Tp=12 and U=2. Both use seven lanes in 36-bit slots. No reduced-width test certifies the full-width success law.

## Outputs and interpretation

**Finite prefix and digest evidence**: The tested helper prints True 0 593. Seven full 128-byte messages match the independently pinned organizer reference, which also passes two standard seven-round known answers. Fourteen negative controls change the prefix or omit it; none matches the original fixture digest. These are finite arithmetic checks, not collision discoveries.

**Kernel and complete-loop scope**: The packed kernel has 593 instructions and 25 live values under dying-operand reuse; saved group inputs and the filter accumulator raise the printed combined count to 34. spill_ops(R) models the kernel only, giving 0,0,3,16,39 at R=64,32,24,20,16. In particular, zero kernel spills at 32 registers is not a full grouped-loop allocation or charge certificate.

**Ledger and memory**: The selected full-width plan has 26,837 entries and declares 1,048,557 bytes including code, counters and a 64-register file: 19 bytes below 1 MiB. Ledger terms are exact Fractions after selecting parameters; Tp selection and probability-loss figures use floating-point calculations. The units divisor is 638. Host process memory, complete cost proof and judge acceptance are not certified by these calculations.

**What preprocessing evidence does not establish**: The accompanying historical proof describes scanning through PREFIX_I and charges preprocessing separately from the attack ledger. Checking the retained prefix proves it works, not that no earlier prefix works, that the scan was executed as described, or that its historical cost is independently audited. No prefix enumeration was run for this guide.

**Counters and recovery**: Reported batches omit halted attempts and do not include every speculative group, replay or recovery call. This edition independently passed eight tiny constant-map flow fixtures; some report one batch while making three or four calls, and one case reports four while making eight. Synthetic pairs are not BLAKE3 witnesses. A 64-bit endpoint-key hit is a fingerprint match and must pass recovery.

**Entry preconditions**: The 25-byte entry packs a 64-bit key, 16-bit trail number and 120-bit length. The helper checks upper bounds but accepts a negative key, so callers must also require nonnegative inputs. The full-width endpoint fingerprint can alias distinct endpoints; the bounded check demonstrates one such alias.

## Failure modes

- Do not discard P or use a single-block verifier: the message is 128 bytes and two compression contexts are required.
- Do not interpret n=22 output as a 256-bit collision; validate the exact message bytes and target independently.
- A passing retained prefix is not a minimality proof or an audited preprocessing receipt.
- CLI --selftest launches searches; only the explicitly documented imported helper is bounded here.
- Kernel liveness and spill figures do not certify saved group-state handling or complete-loop cost.
- Batch observations omit work; a non-null result and an exact rational formula do not establish a full attack price.
- The source memory figure is an abstract instruction-model layout, not Python RSS.
- Use this source identity; b3r3s, b3r3t and b3r3lc are different editions with different hash contexts and ledgers.
