# Independent SHA-256 reference: feedforward outputs and valid comparison domains

Source: `research/tools/indep_sha256_check.py`

Public SHA-256: `94ff2424948cbd2b37f95d243d840800d973ef82ea050964fd081efb5891b486`

## Reviewed usage contract

Supply a separate SHA-256 message expansion, forward step, inverse step and feedforward compression function. The CLI runs bounded randomized sanity gates and optionally compares two message blocks from a supplied common IV.

## Source inspection and available execution evidence

static-source-review; complete-cli-gate-and-comparison-invocation-passed; invalid-horizon-limits-reproduced.

A normal CLI invocation always pays for 2,000 one-block known-answer checks and 20,000 eight-step forward/backward trials, in addition to requested pair comparisons. Import its functions for a deliberately bounded application; do not confuse diagnostic time with attack complexity.

## Declared inputs

**CLI**: python indep_sha256_check.py PAIRFILE [steps...]. Without step arguments it compares 36,37,38,39,40,41 steps. The pair file has IV with eight words and M1/M2 with sixteen words, all hexadecimal. Supply validated arrays and 1<=steps<=64.

**Initial-state law**: The supplied IV is used for both messages; it is not automatically compared to the standard IV. The input is one raw compression block and the program does not validate message padding or a complete multi-block hash target.

**Library API**: expand(W16,n) extends the schedule; step(state,t,Wt) and back(state,t,Wt) are zero-based round operations. compress(cv,W16,n) performs n steps and adds cv to the working state wordwise. Importing the module does not execute its main-program gates.

## Outputs and interpretation

**Known-answer gate**: Each CLI invocation first checks 2,000 randomly generated legal one-block messages of length 0..55 bytes against hashlib.sha256. It exits on gate failure. The random inputs are not retained in its output.

**Pair comparisons**: Prints how many of eight feedforward output words agree at each requested step count. It does not require message inequality, the standard IV or a full 8/8 match to exit successfully.

**Step inversion gate**: After comparisons, tests 20,000 random states by forwarding then reversing eight steps and prints the restoration count. Unlike the initial hashlib gate, the source does not enforce a failure exit code on this printed count.

## Imports

- Python standard library. The CLI uses the random module for finite diagnostics, not a proven attack sampler. No solver, network or research output file is used.

## Worked examples

### Run a two-horizon independent comparison

Working directory: A disposable folder with the pinned reference and a validated IV/M1/M2 pair.txt

```text
python -I -B indep_sha256_check.py pair.txt 39 64
```

Check the printed gate and inversion counts, then require distinct legal inputs and 8/8 equality at the intended positive step count. Separately check whether the supplied IV and padding match the claimed target.

Expected: gate: 2000/2000, one feedforward word-agreement count for each requested horizon, and step inversion: 20000/20000. Agreement counts depend on the supplied pair.

### Replay the publication's bounded controls

Working directory: The extracted profile-contracts-kit folder

```text
python -I -B replay.py
```

Runs the complete reference CLI once with explicit valid and invalid-horizon examples, plus four deterministic hashlib controls and the related backward fixtures. It writes only inside temporary directories.

Expected: passed=true; the deliberately reproduced 0/-1-step 8/8 outputs are flagged as vacuous, not published as collisions.

## Failure modes

- Zero or negative steps execute no rounds and report 8/8 equality even for different messages, because both outputs reduce to twice the common CV. Validate the domain first.
- More than 64 rounds raises IndexError at the constant table in the tested API call.
- Repeated input labels overwrite earlier entries; there is no complete schema, word-range or distinct-message validation.
- An 8/8 result under a chosen IV is not automatically a standard-IV or legal padded-hash collision.
- Finite randomized known-answer and inversion checks are useful controls, not an exhaustive proof of every input or mode.
- Successful process exit alone does not establish a collision or even enforce every printed diagnostic count.
