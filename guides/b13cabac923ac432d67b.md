# SHA-256 pair encoder: construct trajectories and apply pins

Source: `research/game/climber/guided/kit/sha_cnf.py`

Public SHA-256: `5a6b7373b8aac2312a9c017436c17ed4d29caed27343d959af76de687e33f1aa`

## Reviewed usage contract

A project Boolean encoder for two reduced-step SHA-256 computations with a shared characteristic description. It builds gates and modular adders, applies A/E/W row conditions and writes a formula plus a variable map. The paired computations, not a difference-only approximation, are encoded. Generating a formula does not prove it satisfiable, establish a nontrivial collision or price an attack.

## Source inspection and available execution evidence

static-source-review; bounded-encoding-checks-passed; not full encoder equivalence or SAT certification.

For fixed 32-bit width and default options, gate construction grows linearly in the step count and retains all clauses in memory before writing. Cardinality and native-XOR modes change this accounting. The finite teaching run makes four 37/38-step encodings with bounded child timeouts; no search-work or attack-cost claim follows from its elapsed time.

## Declared inputs

**CLI and API**: python -B kit/sha_cnf.py instance.xml out.cnf out.map [chaining], or --decode out.map model.txt. encode defaults to chaining=free. Import defines functions and reads environment settings but does not encode until called. Running with no arguments or --help is not an argparse help interface.

**Characteristic text**: A regex reads the exact name="n" value="N" attribute pattern and lines containing index A:bits E:bits [W:bits]. This is not a general XML validator. Repeated row indices replace earlier ones. Use valid complete row lengths and an explicit target; unsupported characters are left unconstrained rather than rejected.

**Bit and state conventions**: Map words are lists of literals with bit zero first. Characteristic text defaults to most-significant bit first. A[-1..-4] denotes a,b,c,d and E[-1..-4] denotes e,f,g,h. With SIGNED=1, u means side 1=1 and side 2=0; n is the reverse. Without it, both mean merely different. A dash means equal; 0/1 pins both sides; question marks impose nothing.

**Chaining and collision obligations**: Only the literal chaining value iv pins the standard IV. Other labels allocate free initial words; passing sfs does not itself equate the two CVs. Initial equalities must come from constraints. The encoder does not automatically require unequal messages or equal outputs. Those predicates must be encoded by the characteristic and/or REQUIRE_DIFF and checked on the decoded pair. Free-CV working-state equality is not general feed-forward equality.

**Environment is part of the model**: WBITS, BITORDER, CHAINREV, SIGNED, KOFF, EXTRAW, MODDIFF, SCHED_ONLY, NEAR_K, NEAR_ENC, NEAR_OUTS, REQUIRE_DIFF, SYMBREAK, XORMODE, XOR3 and DIFFVARS affect encoding. Use the complete kit's cleaned environment for the demonstrated 32-bit case. WBITS accepts 1..32 but merely warns for degenerate scaled widths; reduced-width experiments are not standard SHA-256.

**Experimental modes**: SCHED_ONLY omits the compression step and leaves state words free. KOFF changes the constant window. NEAR_K bounds working-state bit distance, not necessarily feed-forward digest distance. Native XOR mode writes x lines requiring a compatible solver. Near-totalizer outputs are one-way threshold implications suitable for upper-bound assumptions, not arbitrary exact-count observations. These modes are outside the bounded teaching test.

## Outputs and interpretation

**CNF and map**: encode overwrites both specified output files; parents must exist. Literal 1 represents true and encode adds its unit clause. Ordinary clauses end with zero; optional native XOR lines extend ordinary DIMACS. The map records message literals, initial and internal A/E literals, sigma-family literals and allocation ranges. Width is absent at 32 and included otherwise; some environmental settings such as KOFF are not recorded.

**Decoder limitations**: The decoder scans all integer tokens, treats missing model assignments as false and does not check every formula clause. Its sha_ref recomputes working state without feed-forward and uses K[t], not K[t+KOFF]. It prints distinctness/equality without returning a failing exit merely because equality is false. This is diagnostic output, not a complete SAT certificate or model-independent collision verifier.

**Bounded evidence**: The complete kit generated four normal-width control/real formulas for two seeds, checked header/literal integrity, exact 512 band pins and the ordered 1536-literal seed-exclusion clause. Both seeds pass a separate feed-forward verifier; six negative controls fail. No solver or whole-encoder equivalence proof is part of these checks.

## Imports

- Python standard library only. The complete teaching kit includes this module, the wrapper, generator, profiler, independent checker and two attributed numerical seeds.
- A solver and a validated characteristic/model are separate requirements for a search. Neither is needed for the documented bounded recipe.

## Worked examples

### Build and inspect the four finite encodings

Working directory: The extracted boardpair-kit directory

```text
python -B replay.py --encode
```

Expected: passed=true and four encoding records. r37: 78,743 variables with 361,617 control or 361,618 real clauses. r38: 81,173 variables with 372,897 control or 372,898 real clauses. The real formula adds exactly the seed-exclusion clause; no SAT/UNSAT verdict is produced.

### Encode a separately reviewed characteristic

Working directory: The extracted kit root, with an intended instance.xml supplied separately

```text
python -B kit/sha_cnf.py instance.xml out.cnf out.map iv
```

Interface example, not a bundled input or a performed run. Use a clean process environment, canonical full-width rows, a valid step count, explicit message inequality and appropriate final equality conditions. The iv argument selects standard chaining and may be incompatible with a chosen-IV seed.

Expected: A formula, a literal map and a count line. A successful process exit only means generation completed; the formula may be unsatisfiable or may describe an unintended predicate.

## Failure modes

- This guide is pinned to the older 5a6b7373 edition. The newer b887c9f8 edition's FEEDFWD/TRUNC224 and preheader controls are documented separately in the article 'Which output did the encoder compare?' and current-encoder-contracts.zip. Do not transfer the older tests to changed source bytes.
- Unset inherited experimental variables before encoding a standard target.
- Do not infer a shared CV, output equality or nontrivial message difference from a chaining label or generation success.
- Short/overlong characteristic rows have alignment/truncation semantics; malformed characters may silently impose no constraint.
- A SAT model must satisfy the complete intended formula; decoder output does not establish this.
- KOFF and SCHED_ONLY targets are not verified by the decoder's ordinary compression calculation.
- Native XOR lines are not interchangeable with ordinary CNF for an incompatible solver.
- Keep literal maps, all environment settings, the characteristic and formula bytes together for replay.
- One-way totalizer outputs support upper-bound assumptions; interpreting every output as an exact bidirectional threshold needs additional constraints.
- No full-width result follows from a reduced-width scaled experiment, and no probability follows merely from a raw condition count.
- Current research source changed. This record and its execution evidence identify only the retained historical edition.
