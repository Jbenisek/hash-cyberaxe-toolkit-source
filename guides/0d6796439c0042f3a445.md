# Replay the Pallas Poseidon reference API with its complete numerical inputs

Source: `research/poseidon/orchard/exec_r2e/poseidon_ref.py`

Public SHA-256: `344246fc03ae862cd42beabcade902edea45d23df6cb62751f741c3df636f171`

## Reviewed usage contract

A project big-integer reference library for the Orchard P128Pow5T3 target. It exposes reduced-round and full-round hashing, a separate full-round loop and two-field-element byte encoding. The self-contained teaching kit supplies the already-public numerical dataset and an adapter for the historical constants interface. It checks existing witnesses without a collision search; it includes no imported organizer program or paper.

## Source inspection and available execution evidence

static-source-review; bounded-finite-API-replay-passed; not arbitrary-input certification.

Each valid hash_reduced call makes exactly 8+r rounds, 24+r modular fifth-power calls and 9*(8+r) MDS integer products. The r2 witness example makes two ten-round hashes: 20 rounds, 52 fifth-power calls and 180 MDS products, plus input parsing and comparisons. A full hash has 64 rounds, 80 fifth-power calls and 576 MDS products. These source-derived counts omit Python integer arithmetic, JSON and control overhead and are not a contest price or measured wall time. There is no hidden collision search.

## Declared inputs

**Pinned constants JSON via ORCHARD_CONSTANTS_JSON**: The teaching wrapper checks the source and numerical-data hashes, adapts finite-witnesses.json parameters.poseidon.round_constants_hex and mds_hex to the API's round_constants and mds fields in a temporary file, sets ORCHARD_CONSTANTS_JSON for import, then removes that file and restores the environment. These are the already-public numerical parameters attributed to halo2_poseidon-0.2.0; no external code is copied. A direct API caller still must provide compatible 64-by-3 constants and a 3-by-3 MDS matrix before import.

**hash_reduced(nk,rho,r) and hash_full(nk,rho)**: nk and rho must be exact Python integers, not bools, in [0,P), where P=0x40000000000000000000000000000000224698fc094cf91b992d30ed00000001. Both hash APIs fix the initial width-three state to [nk,rho,2^65] and return state[0]. These are fixed-capacity message hashes, not chosen-IV collisions. In hash_reduced, integer r from 0 through 56 counts partial rounds: retain full indices 0..3, partial indices 4..4+r-1 and full indices 60..63. Thus r2 means ten total rounds, and r56 means all 64.

**digest_bytes(msg64,r)**: msg64 must be a bytes object of exactly 64 bytes: two canonical 32-byte little-endian field encodings. The first is nk and the second rho. Values at least P are rejected, not reduced modulo P. The result is 32 little-endian bytes.

**Bundled finite numerical records**: finite-witnesses.json contains cross-protocol data. The wrapper selects the 33 existing distinct Poseidon profile/pair records at r1 through r5 and checks their recorded fixed-capacity digests. It does not test the SHA3 records in that file or count the repeated manifest entries as new discoveries.

## Outputs and interpretation

**Library return values**: hash_reduced and hash_full return one canonical field integer; digest_bytes returns 32 bytes; schedule returns original round indices. Directly executing poseidon_ref.py loads and validates parts of the constants data but prints no digest or success report. It is a library API, not a command-line verifier.

**Filesystem/process effects**: The API only reads its constants file. The teaching kit additionally reads its numerical dataset, creates and removes temporary parameter/log fixtures, and prints JSON. Its v2 wrapper runs the API and log controls in bounded isolated subprocesses; the log harness runs copied verifier subprocesses with organizer imports blocked. It launches no solver or network request. Use -I -B and do not use -O.

**Teaching-wrapper success**: passed=true with 74 named API checks, 33 existing distinct witnesses, five rejected mutation profiles and 20 rejected invalid inputs. The v2 kit also reports twelve cases under results.log_checker_contract. Any disagreement exits nonzero. Publication tests separately altered the reference, numerical data and log checker and confirmed hash rejection before execution.

## Failure modes

- Missing constants, a reference-notice file in place of JSON, incompatible fields or malformed hexadecimal data prevent import. Source identity metadata is not enforced by this library; callers must verify the constants provenance separately.
- The code checks the number of MDS rows but not every MDS row length. A malformed matrix can fail later during evaluation. Shape/range assertions are not a complete validation of cryptographic constants.
- Do not use Python -O: it removes round-range, constants-shape and example record-count assertions. Pass integer r in 0..56 explicitly; arbitrary types are not a supported contract.
- The low-level perm(state,r) accepts caller-supplied state. A result from arbitrary state is not a valid fixed-capacity hash witness unless the required [nk,rho,2^65] encoding is independently enforced.
- Running the module as a script or passing --help does not perform a witness check or provide CLI help; use the documented API.
- Byte encodings are little-endian and canonical. A 64-byte buffer can still be invalid when either decoded field word is at least P.
- The full-round helper is a separate loop but shares the constants, field arithmetic and MDS helper. Agreement between local APIs is not independence from those common components.
- The bounded controls certify these finite observations only. They do not prove arbitrary-input correctness, any success rate, attack runtime, full-round collision or novelty. Full/reduced API agreement shares constants and helpers.
