## Reviewed usage contract

Source-reviewed GNU make recipe for the existing TrailLab bundle. The earlier publication used a direct GCC command; it did not execute either full make test target.

## Source inspection and available execution evidence

static-source-review; not-replayed-for-publication.

Compilation and harness execution are separate. Neither quicktest nor --n in a later command establishes a whole-command work bound. Consult the individually bounded CLI examples instead of launching the full harness as a smoke test.

## Declared inputs

**Build inputs**: src/traillab.c, src/smc.c, src/diff.c and src/main.c, plus traillab.h, smc.h and diff.h. GCC-compatible compiler, POSIX threads and libm. CC and CFLAGS are overridable.

## Outputs and interpretation

**Targets**: The default target writes a local traillab executable. test runs tests/known_answers.sh; quicktest sets QUICK=1 for that same harness. clean removes the local executable.

**Portability**: Default CFLAGS include -O3 and -march=native. This builds for the local CPU, not a portable binary that should be distributed as historical evidence.

## Imports

- Use the complete source ZIP; the Makefile alone is insufficient.
- The known-answer harness and baseline chi files are separate runtime dependencies. Its unguarded K2 loops still scan full 32-bit domains in quick mode.

## Failure modes

- quicktest does not skip its two unconditional K2 full-word counts.
- The default native CPU flag can make a binary unsuitable for another machine.
- The clean target deletes the local build product; do not run it in a shared active research checkout.
- The previous direct-GCC baseline pass is not a pass of make test or make quicktest.
