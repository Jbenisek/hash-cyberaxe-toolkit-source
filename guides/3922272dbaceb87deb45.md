# SHA-3 r5 / R5N3: explore construction diagnostics and archived-run replay

Source: `research/checks_1015/pa_src/R5N3/experiments/r5.py`

Public SHA-256: `f19b1beba58d37b08e03354f5dbcd2a4d02ba45c00e3d02da65af8e753032a55`

## Reviewed usage contract

A research harness for five-round SHA-3 differential construction, capped affine-space assembly, meet-in-the-middle core checks and archived-run replay. It is not a general quick collision finder. This edition-specific contract documents the real JSON protocol and finite local arithmetic without rerunning the research campaigns or certifying a global success law.

## Source inspection and available execution evidence

static-source-review; Finite copied arithmetic, local-equation and operation-counter checks; mocked diagnostic serialization; one literal empty count CLI. No research campaign or historical witness replay..

Publication fixtures run sequentially in disposable copied-source subprocesses with forty-five-second limits. That timeout is not a runtime promise for the original harness. Some real methods enumerate large core lists, 2^32-member spaces or costly capped candidates.

## Declared inputs

**Pinned source edition**: R5N3 records affine substitution logs, keeps one best tentative state and reconstructs other candidates from those logs. It stores compact enumeration bases for accepted spaces. Its half-vector checks separate plane and key streams: HV_STEP=38 and KW_STEP=20; the fourteen-key stream expects 59 operations. The distributed source and reviewed workspace copy differ in newline encoding only; the download hash pins the distributed bytes.

**JSON stdin**: Run r5.py and send one complete JSON document with experiment_id and trials. Each trial supplies trial and seed. There is no argparse --help mode. main does not validate schema_version, target_profile or event before dispatch; callers must enforce their own target and event contract.

**Count modes**: experiment_id beginning r5-count selects finite-kernel experiment slots, but real slots can be expensive. A name ending 2 selects positional slots 8 through 11; other count names select 0 through 7. Slots are positions in the request, not the numeric trial IDs. An empty r5-count request checks the twenty-four local equations and returns no rows.

**Other modes**: r5-trail- followed by group digits runs the selected trail groups. r5-mitm-out checks the recorded output core; r5-mitm-1 also checks half-vector and match counters; r5-mitm-0 includes the capped candidate check. r5-bpfull assembles candidate/space checks. The fallback parses mode[5:] as a replay-stripe integer, so an unknown name is not safely rejected before parsing.

**Request sizes and seeds**: Trail and MITM branches assign output positions without a general row-count guard. bpfull writes positions 0 and 2, and its capped helper writes position 1. Replay accesses the first trial. Supply the mode-specific number of rows; an empty request is safe only for the documented count example. Duplicate trial IDs are preserved, not rejected. Seeds consumed by h64 are hexadecimal strings.

**State versus message**: The scalar state is 1600 bits with twenty-five little-endian 64-bit lanes. message(A0) extracts 135 bytes; it does not itself verify that the remaining state is valid SHA-3 padding. A 135-byte message requires the next absorbed byte to be 0x86 and zero capacity. digest5 consumes an already absorbed state, not a byte string.

## Outputs and interpretation

**PASS and FAIL are markers**: PASS is the pair (135 zero bytes, byte 01 followed by 134 zeros); FAIL replaces 01 with 02. Fresh independent five-round checks give three distinct digests. Neither marker is a collision. A non-null pair in trail/count/MITM/candidate-check output indicates a diagnostic result, not equal hashes.

**Replay is a different contract**: The fallback selects one stored run in a stripe, rebuilds its candidate, checks selected recorded connector statuses, and searches its recorded coordinate window. e_window checks complete five-round digest equality before returning a pair. This branch can return an actual witness or null; it was not run in the bounded publication check. The stored run table is historical evidence, not freshly generated data.

**Finite independent arithmetic**: Seven full-round messages agree with hashlib SHA3-256. Ten five-round message controls, including all three sentinel messages, and eighty intermediate-state fixtures agree with an independent coordinate implementation whose rotations and constants are generated. Sixteen states pass both directions of the linear inverse. These finite controls are not an all-input proof.

**Exact small local conditions**: All 1024 chi difference-table entries agree with exhaustive five-bit enumeration. The twenty-four stored equations define the same allowed local row values as the relevant differential tables. This local equality does not imply that all equations are globally independent or prove the probability of the complete construction.

**Packed match and affine controls**: The 109 fixed active-row controls agree with a literal 320-row oracle, with 49 modeled operations per match_step. Zero, 1, 37, 255, 256 and 257-row runs match 18+49n+3 floor(n/256). Four small affine substitutions satisfy all 256 residual assignments; the R5N3 replay log also reconstructs the same array. These are local tests, not full memory or price certificates.

**Historical rates and accounting**: The source embeds forty-eight run records and thirty-nine nonzero-space entries, and bp_rows forms a binomial lower bound from those stored entries. This audit does not rerun the records or establish independence or selection assumptions. WK separately tracks modeled row/small/permutation work and a correction d; OPS counts a particular 256-bit inner loop. Neither is elapsed time or host memory.

## Imports

- Python 3 standard library. No external data download is needed to import this self-contained source.
- Import initializes finite five-bit affine tables and a 320-bit linear inverse. That work is included in the bounded child timeout; import is not literally free.
- The bounded audit uses a disposable copy, a separate coordinate implementation gated by hashlib, and mocks only for protocol branches. No Base construction, trail_group, halves, stored-run replay or full algorithm is executed.

## Failure modes

- Treating a PASS marker as a collision is incorrect: the two ordinary five-round digests differ.
- Most mode branches need nonempty, specifically sized requests; do not generalize the empty count example to replay or bpfull.
