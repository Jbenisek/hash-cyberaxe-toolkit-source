# BLAKE3 pkg10: the representative-and-neighbour counting model

Source: `research/pkg10/pkg/blake3-r2/experiments/halfsearch.py`

Public SHA-256: `f6ba1d3353e35d008f64c5aef7d989e5df989332eb563813214ff35453ab3616`

## Reviewed usage contract

This historical two-round BLAKE3 experiment adds an explicit counted representative/neighbour path to the earlier halfsearch model. Message lengths remain 55 and 63 bytes. Representatives have e1 and X2 bits 14, 30 and 31 zero. Their six binary flips define a 64-member cluster. The four-condition gate decides which representative opens the neighbour path; the eight-condition rule still decides trial selection. The cluster test is a diagnostic model, not the JSON residual-search loop or a proved complete attack.

## Source inspection and available execution evidence

static-source-review; 131072 member indices enumerated; two fixed 64-member scalar clusters; 256 independent digest comparisons; two diagnostic schedules with 693 neighbour lanes; no selftest sweep or search.

The diagnostic representative word counted 142 operations, 40 loads and one store; a neighbour word counted 142/40/0. Gate test counted 6/4/1, full dispatch 21/9/0, final four-lane dispatch 12/6/0, cluster entry 11/10/7, and exit 0/4/1. These are observed components of the source's 256-bit-word machine, not CPU instructions or a complete attack price. The diagnostic always computes both stages and exercises every real lane, including closed gates. It is intentionally not a timed simulation of the gated algorithm.

## Declared inputs

**Pinned edition**: Use this exact pkg10 source hash. Compared with the reviewed pkg9 source, existing function bodies change in main, middle_step, table_build and packed_batch after docstrings are excluded. New cluster functions and top-level budgets require their own review; earlier edition tests do not transfer automatically.

**Organizer-shaped JSON interface**: With no CLI arguments, stdin must contain schema_version=1, target_profile=blake3-r2-prefix-v1, event.kind=digest-xor-mask, experiment_id=half-collision or residual-search, and trials containing trial identifiers and hexadecimal seeds. The program checks event kind, not arbitrary mask/value semantics. Empty trial arrays are a bounded interface check.

**Larger diagnostic commands**: --selftest N [seed] and --cluster-selftest N [seed] accept positive decimal N. The former enumerates additional class and rule patterns. The latter runs at least four generated cases, processes complete 64-member clusters, and schedules between four and 64 representative words. N is not an exact total-work cap. Neither command was run for this guide.

**External pricing inputs**: FACTOR=92675904 and EQUIVALENTS=4102 feed the declared run law. The latter encodes 41.02 trial-equivalents, an inherited measured yield, not a proved recovery law. Gate and neighbour-stage budgets are additional declared inputs. This guide does not certify them or a complete contest price.

## Outputs and interpretation

**Constructed and searched events**: half-collision returns two message hex strings with the caller trial identifier; its construction targets digest words 0,2,5,7. residual-search is the separate inherited toy loop over at most 131072 class members and seeks a zero low byte of one residual word. Neither a returned half match nor that extra byte is a full digest collision.

**Exact member-index partition**: The finite checker enumerated all 131072 member indices as 16384 representatives times eight e1 flip patterns, with no overlap or omission. The X2 flip choices give eight distinct siblings. Nine seven-lane neighbour words cover flip numbers 1 through 63 once. The last representative word has four distinct entries and three repeated padding lanes; dispatch reads only the four real entries.

**Fixed scalar controls**: Two explicit 64-member clusters passed h1 recovery from z, half-digest equality, gate translation and rule-implies-gate checks. A separate pinned JavaScript implementation agreed on all 256 two-round digests and passed two seven-round known answers. These fixed controls are not samples for estimating gate opening or recovery yield.

**Finite routing schedule**: Two diagnostic representative words, including the final partial word, passed all 14 representative/gate lanes, 11 cluster entries/exits and 693 neighbour lanes. Stored middle values, mixed-X2 words, dispatch, addresses and restoration matched the scalar references. Each observed piece stayed within 16 modeled registers. This is not an all-input register or implementation proof.

**Budget equality boundary**: The finite gate-budget control reaches the limit and returns false, using three modeled operations, three loads and one store. The underlying comparison is inequality, not less-than: correct stopping also requires the count's increment discipline and divisibility. It is not a general overflow guard.

## Failure modes

- Do not promote the observed component counts, declared budgets or measured 41.02 yield into a premise-free full-run price.
- cluster_case tests all real lanes, whether their gates open or not, and packed_batch evaluates both stages. Diagnostic work and modeled accepted-path work differ.
- Spare lanes repeat the last representative. Counting all seven as independent trials overcounts the final word.
- A passing local partition check does not prove that the cryptographic mass is uniform across representatives or that a fixed corner has the same law as a uniformly chosen member.
- The stronger rule implies the weaker gate on the same trial; this is not a proof that every neighbour preserves either condition.
- Malformed JSON, seeds or targets raise errors rather than a structured per-trial failure. The source has no whole-request trial-count cap.
- Do not use either selftest command as a one-case installation check. The documented positive-N guard is not an exact workload bound.
- No claim is made that the toy residual loop executes the priced neighbour procedure or that any full collision was found by these checks.
