# From numerical pair to characteristic: pin the prefix, inspect the tail

Source: `research/tools/funnel/pair2char.py`

Public SHA-256: `88133bed956eaefad6f519b1e8afd9adb1faabff48ad84a0e93db64c1c0a3855`

## Reviewed usage contract

Generate a full-width SHA-256 characteristic from two numerical message blocks and their initial states. Keep signed A/E differences through FIX_TO, free intervening state rows and request equal final working-state rows. This designs an input question; it neither solves the characteristic nor proves the pair collides.

## Source inspection and available execution evidence

static-source-review; eight-bounded-characteristic-and-meter-fixtures-passed; no-solver-run.

Linear trace and formatting work over R steps, at most 64 in the intended full-width domain. Solver design/search cost is separate and unmeasured here.

## Declared inputs

**CLI**: python pair2char.py PAIR.txt R FIX_TO OUT.xml SETUP.xml. Supply SETUP explicitly: the default is a historical mounted research volume workspace path. The routine uses full-width SHA-256 constants and does not validate a general step domain; keep 4<=R<=64 for the documented closure interpretation.

**Pair text**: Two W= blocks of sixteen lowercase eight-digit hex words and one or two chain= blocks of eight lowercase hex words. One chain is reused; two chains may differ. Missing matches fail by indexing, rather than a schema diagnostic. This is not the IV/M1/M2 format used by the independent checker.

**Dependencies**: A sibling mine_meter.py is required. The program reads its source prefix before rows = [] and executes that prefix to obtain run(). These files form a version-bound pair; arbitrary source changes or a different marker can change behavior.

**Tail mode**: An unset or empty NOZERO permits equal tail rows. Any nonempty value, including 0, disables the equal-tail branch. The printed summary still says zero rows, so inspect OUT.xml rather than trusting that label.

## Outputs and interpretation

**OUT.xml**: Creates or replaces the explicit output file. All W rows are the pair's signed schedule differences; A/E rows -4 through FIX_TO use its signed differences. Remaining rows before R-4 are free. Tail rows are equal only when they were not already covered by FIX_TO and NOZERO is false.

**Copied setup suffix**: Copies the text after the supplied setup's char element through the closing config tag. This includes its search block and any other suffix content; it is not a validated or normalized XML merge.

## Worked examples

### Replay the finite contracts without a research workspace

Working directory: The extracted seed-prefix-kit folder

```text
python -I -B replay.py
```

Python 3.10 or later, standard library only. The kit uses disposable directories and synthetic fixtures, not live project data or a solver.

Expected: passed=true: twelve value-seed cases, fifteen prefix-checker cases and eight characteristic/meter cases. The latter compare expanded schedules and prefixes at 10,17,39,64 steps and reproduce the documented failure behaviors.

### Generate a disposable ten-step design input

Working directory: A disposable folder with both pinned scripts, a lowercase-format pair and setup.xml

```text
python pair2char.py pair.txt 10 4 out.xml setup.xml
```

Unset NOZERO. Do not point OUT.xml at an existing research input. Inspect both scripts and the copied setup before running a solver separately.

Expected: Rows -4..4 are signed from the pair, row 5 is free, rows 6..9 request equality and W0..W9 retain the pair's signed differences. No solver is launched.

## Failure modes

- FIX_TO>=R-4 overlaps the closure window: prefix pins take precedence over the intended zero tail. Use FIX_TO<=R-5 if all four tail rows must be requested equal.
- NOZERO=0 disables zero-tail pins despite the status text saying zero.
- The two initial states need not agree. Working-state closure from differing CVs does not itself prove feedforward collision.
- The emitted u/n signs are meaningful only if the downstream solver keeps their orientations; an unsigned interpretation changes the question.
- Uppercase labels or hexadecimal letters are outside the literal lowercase parser contract.
- The requested prefix, signed W schedule and equal tail can be inconsistent. Successful file generation is not evidence of SAT or a collision.
