# Board-pair path comparison: changed signed rows and raw C1 counts

Source: `research/game/climber/guided/boardpairs/pathcheck.py`

Public SHA-256: `c52b9d35da25a285a8d6950d4a7e83310b4f9f9e0d59e6364679f325d13d8cd4`

## Reviewed usage contract

Read two fixed baseline seeds and locally stored .chk records, then compare their 32-bit SHA-256 signed A/E/W characteristics and raw C1 condition totals. It reports whether a new message pair follows a different path, without claiming that the count is an independently established probability or attack cost. Its kit import and two seeds are distributed in the teaching bundle, but a campaign out/*.chk corpus is not included. This report script is not a collision verifier.

## Source inspection and available execution evidence

static-source-review; not-replayed-for-publication.

The two seed profiles require 2*38+2*37=150 SHA-256 step iterations, plus message expansion and row/count construction. Each retained r38 candidate adds 76 step iterations; each retained r37 candidate adds 74. Thus state evaluation uses 150+76U38+74U37 step iterations for U38/U37 retained records. All matching text files must still be read to test markers and deduplicate; sorted filenames and seen keys are kept in memory. There is no time/file-count/memory cap, no solver and no search. Exact bytes, wall time and peak memory depend on the local record set and were not measured.

## Declared inputs

**Fixed seed files**: Relative to the script directory, wit/r38_s102.json is profiled at 38 steps and wit/r37_tab17.json at 37 steps. Each supplies cv[8], M1[16] and M2[16] as hexadecimal strings. File R/n metadata is ignored. The imported profiler assumes 32-bit SHA-256 constants starting at K[0] and one shared CV for each pair; it does not force the standard IV.

**Candidate .chk text files**: Scans sorted out/r38_*.chk and out/r37_*.chk relative to the script, not the current working directory. Files lacking the exact substring INDEP VERIFIED are skipped. Accepted text must contain M1: W= and M2: W= lines of lowercase hexadecimal words separated by spaces, with an immediately following indented chain= line for M1. No uppercase A-F, tabs within the word capture or additional suffix text are supported by these regexes.

**Model assumption**: The candidate's M1 chain is used for both message computations; the M2 chain is not parsed or checked. The script does not read a map or candidate step count. Only matching shared-CV, 32-bit, K[0]-based 37/38-step records are valid inputs. This is not suitable for free-start pairs with different CVs, reduced-width runs or shifted constants.

**Duplicate key**: Per board, only the first sorted record with a given textual tuple of M1 words and M1 CV words is retained. M2 is omitted from the key. Distinct partners can be suppressed, while differently padded encodings of the same integer may evade deduplication.

## Outputs and interpretation

**Standard-output report**: Prints a seed condition-total line for each board, followed by tab-separated candidate lines: board, file basename, cond, signed delta from the seed and path_rows_changed. Changed rows compare signed character strings for A/E at -4..n-1 and W at 0..n-1. A dash denotes no changed signed rows, not identical message values.

**C1 total**: With default t0=16, sum popcount(dA_t)+popcount(dE_t)+Maj-condition-bits+Ch-condition-bits over t>=16. Maj counts positions with exactly one differing input. Ch counts positions with at least one differing input except those where both f and g differ. W differences are reported through path rows but are not a separate term in this total. No independence, sampling or probability proof is performed.

**Startup and file/process effects**: Immediately on script execution or import, adds ../kit to the import path, reads both seeds, scans all matching .chk files and prints the report. There is no main guard or CLI parser. It makes no writes, invokes no solver/child process and uses no network. Python import caches are suppressed by -B in the example.

## Worked examples

### Produce a path comparison from a complete local record set

Working directory: Any directory; input locations are relative to the script itself

```text
python -B research/game/climber/guided/boardpairs/pathcheck.py
```

This relative command assumes the archive/project root as the working directory; otherwise give the script's full path. Restore the matching kit, both seeds and intended .chk records first. It scans every matching file without a row/time cap. This command was not executed for this guide.

Expected: Source-derived format: r38/r37 seed condition lines, then one candidate line per accepted deduplication key. The historical PATHCHECK.tsv reports seed totals 84 and 61; the separate teaching-kit replay confirms both seed totals, but this campaign-scanning script was not executed. Candidate lines depend on the supplied records.

### Interpret a historical changed-row record

The reviewed PATHCHECK.tsv includes r38_relE8 with cond=84, delta=+0 and path_rows_changed=E8. This is a data-reading example, not an execution command.

Expected: A signed row can change while the raw counted total stays unchanged. That observation does not by itself show improved probability, a cheaper attack or a new verified collision.

## Failure modes

- A standalone script is insufficient: preserve sibling kit and wit directories. A missing out directory silently yields seed lines only, not an error.
- The INDEP VERIFIED substring is trusted as a selection marker. It is not an authentication check; the script never checks its computed profile['collision'] flag. Marker-bearing invalid pairs can receive ordinary-looking report rows.
- The second CV, map width, constant offset, candidate step count and provenance are not verified. Do not use this report as a replacement for independent witness verification.
- Malformed marker-bearing records can crash on a missing regex match rather than being skipped. Formatting is strict and hexadecimal captures accept lowercase only.
- Deduplication omits M2 and is textual, so the report is not a count of all unique numerical collision pairs.
- There is no --help or argument selection. Importing the module runs the entire scan; passing arguments does not limit it.
- The raw C1 condition total and its delta do not establish joint-event probability or an exact contest price. A changed path with delta=0 is still an unchanged count under this rule.
