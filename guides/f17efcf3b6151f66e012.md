# BLAKE3 bitslice3: polarity-search provenance and reuse of setup memory

Source: `research/checks_1015/pa_src/b3r3bs3_pkg/experiments/bsrho.py`

Public SHA-256: `ef98cfcd1a51c617b230526f376ef194653cfe9a363ce04a1913c67d0c8d58c7`

## Reviewed usage contract

Two byte-identical copies extend the fixed-prefix bit-sliced implementation with a reproducible polarity-climb procedure and explicit setup accounting. Fresh finite checks cover their changed circuit, allocated step, declared formulas and interface. The guide separates the retained vector from the historical search that produced it, and a formula-level memory fit from a target-machine implementation certificate.

## Source inspection and available execution evidence

static-source-review; copied finite digest and compiler checks, structural allocation certificate, synthetic capped flow, declared-ledger arithmetic and mocked experiment routes; no original search.

Finite import/circuit generation and allocation: 42,942 recorded generator primitives and 18,866 emitted instructions. The optional bytecode diagnostic inspects functions without running the polarity climb. No target/ideal birthday run, prefix scan, historical 2,000-iteration climb or original selftest is executed. Host compilation is not a measured contest-operation certificate.

## Declared inputs

**Hash and message context**: The message is P || K || x, with a fixed 64-byte P and 32-byte little-endian K and x. The target has K=0. P uses standard IV, counter 0, length 64, flags 1 and three rounds; the last block uses its chaining value, counter 0, length 64 and flags 10. PREFIX_I=10768619076 defines P as words [PREFIX_I mod 2^32, PREFIX_I >> 32, 0, ..., 0]. Fresh-key T1 varies K inside the last block; it does not replace P. The scalar helper's K||x shorthand omits the prepended fixed block.

**Bit planes and stored polarity**: Each of 256 machine-word bits represents one lane; each plane represents one chain-state bit. Rotations rename planes rather than execute shifts. Stored plane j may be complemented according to the fixed PINS mask. Step() corrects output polarity to the same input convention, allowing repeated steps without representation changes. pack_lanes, lanes_of and lane_value must use that same polarity.

**Widths and plan support**: Plans support n=18,20,256 only. The default full-width plan uses 256 lanes, 1,024 declared registers, s1=32, W=90, threshold Tp=142 and 10,160 endpoint entries. Advice is now 64 bytes: the prefix index and the 256-bit polarity mask. Smaller-register fallback prices are not audited by this guide.

**bsrho-n18 event**: Each requested trial runs one 18-bit target attempt, one keyed BLAKE2b ideal-control attempt and a fresh-key 12-bit first-repeat statistic. Only the target can supply the returned message pair. T1 changes K in the last block of P||K||x; the target keeps K=0 and both keep P fixed. These controls do not establish a full-width random-mapping law.

**proj-k0-w256 event**: The source computes 2,048 full-width digests per trial and observes seven 21-bit projections. trial ID modulo 3 chooses uniform derived inputs, consecutive counter inputs or eight chained steps from 256 starts. Only a repeat in projection w0 with distinct input messages can produce a returned pair. It is a 21-bit event, not a full-output collision; chained inputs and repeated values require their own sampling interpretation.

**Protocol validation and safe command**: The two experiment IDs remain bsrho-n18 and proj-k0-w256. Unknown names raise ValueError; metadata is not target validation and repeated IDs are not deduplicated. selftest(), --stats, --scan and the new --climb launch original searches or campaigns and were not run. The compiler-only example and --gencode diagnostic are bounded commands; --gencode counts Python bytecodes, not target-machine instructions.

**Polarity climb and its starting point**: climb_pins(iters=2000,seed=2) starts at the all-zero vector, uses its own splitmix64 generator, proposes flips in mismatched planes plus an occasional random plane, and accepts non-increasing costs. A tie is accepted. Every proposal is evaluated and charged even when rejected. Zero or negative iters still performs the initial evaluation. No optimality or unique-best-mask claim follows from this heuristic.

## Outputs and interpretation

**Finite arithmetic and representations**: This edition's 256 complete 128-byte digests match the independently pinned reference. The selected prefix chaining value and A1+B2 cancellation are independently checked; 14 controls omit or mutate the prefix and differ. Two fixed chain steps, two allocated executions, 18/20-bit fixtures, stage-1 masks and seven packed recovery values pass. Packed recovery has 593 instructions. These finite checks do not prove universal hash-generator correctness or prefix minimality.

**Generated straight-line allocation**: The changed full-width mask emits 18,866 instructions with register extent 771. Fresh AST/operand/output checks cover every allocated instruction; two deliberate assignment/operator changes are rejected. Both fixed-step executions, 256 independent full-message digest fixtures and the reduced-width controls pass on this source pin. The structural allocation proof does not certify the complete hash generator, callers or handlers.

**Declared default ledger**: The declared body is 18,904 operations (18,866 kernel + 35 filter + 3 loop). The full declared sum is 26,294,461,467,906,612,499,224,604,717,289,339,335,772 word operations, with units divided by 638. It includes scan work 7,721,099,878,210 and polarity-climb work 24,959,503,800 = 200 x (86,337,248 + 38,420,251) + 2,001 x 4,000. The historical climb totals are stored constants, not recounted by this audit. Formula arithmetic after floating-point plan selection does not establish success or a complete price.

**Memory scope**: The default search formula totals 1,048,560 bytes: 745,344 code + 64 advice + 16,384 counter/copy + 32,768 registers + 10,160 x 25 table bytes. The setup formula totals 1,041,758 bytes, reusing the later table/register region for generator code and scratch. For the retained vector, 19,098 nodes give 152,168 trace bytes and 222,366 emit bytes. These are declared layouts, not Python RSS, a whole-word-placement proof or an observed peak over all historical candidates.

**Duplicate entries are not equal pairs**: dup_w0 and the other dup_* fields compute len(values)-len(set(values)). A value appearing c times contributes c-1, whereas all equal pairs number c(c-1)/2. The synthetic values [5,5,5,7] yield the program's duplicate count 2 but equal-pair count 3. The statistics printer compares duplicate totals with a pair-count expectation; the audit exposes the semantic mismatch, not its magnitude in historical runs or an invalidity proof for every sparse sample.

**Exact projection bit positions**: Every projection is masked to 21 bits. p01 retains low 11 bits of word 0 followed by low 10 bits of word 1. p23 retains low 11 bits of word 2 followed by bits 11 through 20 of word 3, because the source shifts by 107 before masking. These are not two intact 11-bit pieces after the final mask. Seven formulas were checked independently on 256 digest fixtures.

**Counters and capped control flow**: This edition keeps a mutable counter dictionary through Halt: synthetic batches=3 and stage1_hits=2 survive with halt=1, unlike the zero-reset wrappers of b3r3t/lc. Six one-step artificial-map fixtures cover a recoverable pair, no stage-1 hit and stage-1/table/recovery/cut budget exits. Synthetic pairs are not BLAKE3 witnesses; batch counts still do not count all recovery, setup or generator operations.

**Unsafe reduced-width loss helper**: Reduced plans set cmax=1,000,000,000. loss(p) constructs cmax+1 Poisson terms, so loss(plan(18)) or loss(plan(20)) attempts a billion-term calculation. This is a source-derived resource hazard; the unsafe path was not executed. The documented finite example does not call loss, a search or selftest.

**Preprocessing arithmetic and scan boundary**: The ledger adds 10,768,619,077 x 717 + 1 = 7,721,099,878,210 declared prefix-scan operations. A one-candidate check verifies the retained prefix; five synthetic fixtures check hit/exhaustion counts and the exclusive upper limit. None proves an earlier candidate could not work, that the historical scan was executed, or that every operation fits the 717-operation allowance. --scan itself was not run.

**A necessary peak-node bound under the stated formula**: With the declared 1,600 generator instructions and fixed setup terms, the emit-phase formula fits 1 MiB only through 19,717 nodes. The retained vector has 19,098 nodes; the generic nodes<32,768 assertion alone does not prove that every candidate fits. The historic peak across tried polarity vectors remains unverified.

**Bytecode counts depend on the interpreter**: The copied --gencode command prints 'bytecode instructions 1674 GEN_CODE 1600' on CPython 3.11.1. The archived comment cites 1,595 bytecodes and declares 1,600 generator instructions. This difference shows that a Python bytecode count is not a portable code-size proof. It does not alone prove that a target-machine implementation exceeds its memory budget.

**A printed match is not a failure-enforcing check**: The --climb dispatch prints whether the vector and three accumulated totals match constants; it does not raise or return failure on a mismatch. Its Boolean omits the returned cost, which is printed separately beside step ops. Mocked dispatch controls return normally for a wrong vector (False) and a wrong cost (True). No original climb was executed to obtain these controls.

**Synthetic setup controls**: Three eight-iteration synthetic-oracle cases check rejection, tie acceptance and zero-mismatch behavior. Every case evaluates nine candidates, aggregates calls and nodes including rejected proposals, and exactly repeats for the same seed. These validate control flow, not the saved 2,001-evaluation history, its optimum or peak scratch.

## Failure modes

- Use the bit-plane polarity consistently; a stored complemented plane is a representation choice, not a different hash.
- Do not treat 18-bit target pairs, 21-bit projection pairs or fresh-key 12-bit observations as full 256-bit collisions.
- Count repeated entries and all equal pairs separately; they differ once multiplicity reaches three.
- Projection p23 uses word-3 bits 11 through 20, not its low 10 bits.
- Do not execute loss(plan(18/20)); its billion-term loop is outside the intended full-width loss path.
- selftest() and --stats launch original searches; the documented compiler example does not.
- A generated-step allocation certificate does not prove the full hash generator, handlers or caller fit the same budget.
- Declared cost formulas and floating-point tail selection are not an independently proved success rate or complete price.
- Do not drop the fixed 64-byte prefix or use single-block flags 11 when verifying returned messages.
- Fresh-key T1 changes K in the final block, not the fixed prefix P.
- CLI --scan launches a prefix search; verifying the retained prefix does not establish scan execution or minimality.
- Do not read --climb exit success as proof that constants matched; inspect the vector, cost and all totals separately.
- Do not treat the selected-vector scratch measurement as a maximum over every vector the historical climb tried.
- Do not equate Python bytecodes with the contest instruction set or turn 1,674 versus 1,600 into an unproved memory-overrun claim.
- The historical climb and prefix scan were not replayed. Their declared charges do not prove minimality or optimality.
