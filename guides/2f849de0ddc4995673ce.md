## Reviewed usage contract

Read owner_count STATE/W literal totals alongside the independently sampled wcost PASTFREE/WEXP estimates. These quantities describe different predicates; joint characteristic success and complete attack costs require their own derivation.

## Source inspection and available execution evidence

static-source-review; five-reviewed-functions-extracted-with-AST-and-tested-on-disposable-fixtures; source-driver-not-executed.

The original source allocates million-element arrays for each estimated row. No runtime, peak memory or full historical campaign is certified. The documented inspection example performs no sampling.

## Declared inputs

**Characteristic file**: The source expects a particular XML-like layout with n and char attributes and 32-character A/E/W rows. This is a regex interface, not general XML validation. Missing, differently formatted or malformed rows may fail parsing or fail later lookup.

**Original CLI**: count_e2e.py CHAR.xml ... processes each named file. Importing the original module also creates its random generator and executes the top-level file loop; do not import it casually with unrelated process arguments.

## Outputs and interpretation

**STATE and W**: Literal 0/1/u/n/x counts. STATE spans parsed A/E rows; W counts only rows t<16. Equal '-' symbols do not contribute. These are not proven independent constraints.

**Completeness and flag**: Question marks are tallied in A/E and only t<16 W rows. A partial W16 row can leave q=0 and trigger FLAG_UNDER_250. The flag is not a complete-characteristic certificate.

**WEXP**: Each expanded row independently samples four parent words, sums negative log marginal match fractions, and substitutes 21 for zero hits in 2^20 samples. It does not enforce one consistent joint expanded schedule.

**Question marks**: wcost.masks maps '?' and unsupported symbols to '-': equality, not unconstrained pairs. Partial-characteristic semantics differ from standard wildcard semantics.

## Failure modes

- A later-W '?' does not prevent the printed completeness flag.
- Zero observed hits is assigned a finite heuristic cost, not a proved probability bound.
- Fresh independent parent samples do not form a globally consistent SHA-256 schedule.
- The process catches per-file exceptions and continues; a normal exit does not mean every file was priced.
- Unsupported characters are silently mapped to equality by masks().
- The evolving global RNG makes estimates sensitive to file and row order.
