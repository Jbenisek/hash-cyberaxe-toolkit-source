# Traillab CLI: baseline checks and eight-pattern diagnostics

Source: `research/tools/traillab/src/main.c`

Public SHA-256: `e6e97fea5f753e665d9672233fafa2d9c491fe8354ce5f659793ec7d6d7edce7`

## Reviewed usage contract

Command-line entry point for Traillab: load a SHA-256 characteristic and its published pair, inspect constraints and schedule dependencies, and run explicitly selected counting or sampling experiments. main.c is one component of a four-source C program, not a standalone compilable tool.

## Source inspection and available execution evidence

static-source-review; bounded-cli-replay-passed; other modes not runtime-certified.

The two flip examples enumerate eight patterns each. Each check performs 2,000 internal reference/trace/inversion cases, 16 coordinate draws and 2^22 density samples for each FSET/CELL variable (three variables for chi37; two for chi38). Fresh local flip/check invocations took under one second each; compilation took about 4.25 seconds. These observations include WSL invocation overhead and are not portable runtime guarantees or attack-cost claims. make quicktest still invokes exhaustive K2 enumeration and must not be used as a smoke test.

## Declared inputs

**Build inputs**: src/traillab.c, src/smc.c, src/diff.c, src/main.c and the three corresponding headers from the same source bundle; GCC, libm and POSIX threads.

**--chi FILE**: Required characteristic file. The demonstrated inputs are chi/chi37.txt and chi/chi38.txt, containing a common chosen CV, two messages, expected digest, conditions and sampling coordinates.

**flip --word Wt --mask HEX**: The word is an expanded word with 16 <= t < steps. The nonzero hexadecimal mask must occupy bits equal between the published members. The demonstrated mask 04022000 has three bits and enumerates exactly eight patterns.

**check --n 16**: Sixteen random-coordinate consistency draws, in addition to fixed self-tests and density samples. --n does not cap all work.

**--threads 1**: Use one worker for commands that use the parallel loop. The program's default is six; set this explicitly in a shared environment.

## Outputs and interpretation

**flip stdout**: Eight pattern rows followed by FLIP result: 1 of 8 patterns keep every later modular difference (only the published pattern), for each demonstrated input.

**check stdout**: Reference/self-test status, published-pair equality and expected-digest comparison, condition failures, anchored rebuild differences, coordinate replay diagnostics, sampled densities and CHECK ok or CHECK FAILED.

**Exit status**: 0 for the demonstrated successful commands; 1 for a failed check such as an incorrect expected digest; 2 for rejected CLI/model input. A zero exit from flip is not itself proof that a nontrivial pattern survives.

**Filesystem effects**: These demonstrated commands read the characteristic and print to stdout/stderr. The compile step creates a binary in the extracted working directory; no research source is modified.

## Worked examples

### Build the extracted source bundle

Working directory: The traillab directory extracted from downloads/traillab-source.zip

```text
gcc -O2 -Wall -pthread src/traillab.c src/smc.c src/diff.c src/main.c -lm -o traillab
```

Expected: Exit 0 and a local traillab executable. This is the compiler command used by the bounded publication check.

### Check the three disputed W22 bits

```text
./traillab flip --chi chi/chi37.txt --word W22 --mask 04022000 --threads 1
```

Expected: Exactly eight pattern lines and one surviving pattern, the published one. This is a word-level dependency experiment, not a legal-message sampler or collision search.

### Repeat at 38 steps

```text
./traillab flip --chi chi/chi38.txt --word W23 --mask 04022000 --threads 1
```

Expected: Exactly eight pattern lines; only published pattern 111 survives the later modular-difference test.

### Replay the baseline pair and coordinate checks

```text
./traillab check --chi chi/chi37.txt --n 16 --threads 1
```

Expected: Published outputs EQUAL; digest matches; zero failing rows; zero rebuild/forward/expansion/incremental differences; CHECK ok. Repeat with chi/chi38.txt for its separate baseline.

### Reject an invalid mask

```text
./traillab flip --chi chi/chi37.txt --word W22 --mask 0 --threads 1
```

Expected: Exit 2 and an explanation that the mask must be nonzero. This is an expected failure control, not a failed installation.

## Failure modes

- Compiling main.c alone omits required library definitions.
- The inputs use a chosen common chaining value: do not describe their reduced-round result as a standard-IV SHA-256 break.
- flip re-expands an edited internal word; it does not prove that the edit arose from a new legal 16-word message.
- --hold-from deliberately enables an inconsistent held-word artifact mode; its results are not valid-message gains.
- --n 0 does not eliminate fixed density loops, and make quicktest does not skip every exhaustive count.
- Increasing the mask's number of set bits increases flip work exponentially. Keep the demonstrated three-bit mask for this walkthrough.
- Sampling output is not an exact event probability, and these checks do not certify window, exact, sdiff, backward, varcount or rowtable modes.
