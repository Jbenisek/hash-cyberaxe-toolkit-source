# BLAKE3 pivot walk: compare code storage and recovery costs

Source: `research/blake3_r3/pivot1/pkg/blake3/experiments/bsrho.py`

Public SHA-256: `4109c3f80a0a25369f7c06fb7d37d86a0c07d917ff66602a0c6e6fe9ab4d5078`

## Reviewed usage contract

This earlier pivot edition generates the same 17,238-operation arithmetic program as compact_u5b, but declares a much larger code representation and stores trail lengths. It illustrates why kernel equality does not imply equal table capacity or recovery cost. The source credits the pivot rule and masked-walk method to jungjipdo; that attribution is retained.

## Source inspection and available execution evidence

static-source-review; Copied finite digest/allocation and retained-wasm controls, declared ledger and synthetic interface/recovery cases; no original search.

One finite 35,340-call circuit generation and allocation of 17,238 instructions, or a bounded bytecode inspection for the second recipe. No original selftest, collision attempt, fresh-key run, statistics, threshold scan or loss calculation runs in either documented recipe.

## Declared inputs

**Message and target**: A single 64-byte message: 32 zero bytes followed by little-endian 256-bit x, standard IV, counter 0, block length 64, flags 11 and three rounds. This source hardcodes the three-round loops rather than exposing the later ROUNDS/UNIT globals. Its accounting unit is 638.

**Masked walk and attribution**: Input planes are upright; the returned state is g(x)=f(x) XOR q, where q comes from output polarities. Fixed q preserves the collision predicate exactly but changes walk trajectories relative to f. The source attributes both pivot full addition and this masked walk to jungjipdo, 6ae36351 proofs 3.3 and 3.4.

**Generated program and declared machine**: The pivot full adder uses five binary gates for three distinct variable planes. Full width has 17,238 instructions and register extent 771. This edition compiles one straight-line function, declares 1,024 plane registers and uses 36-byte instruction records, not the compact edition’s five-byte records.

**Full-width plan**: The default plan selects Tp=177, kappa=11, two allowed cuts and 12,494 stored endpoints. It evaluates 4,096 candidate thresholds against a floating-point tail test. Its 350-trail age allowance is chosen using floating-point Chernoff arithmetic. Neither selection is an exact full-width probability certificate.

**Reduced experiment and projection families**: Configured widths are 18, 20 and 256. bsrho-n18 requests a target and keyed BLAKE2b ideal attempt. Fresh-key T1 uses unmasked f. T2 takes 2,048 values from a trial-index-selected input family, unmasks g, and projects f into seven 21-bit columns; only a distinct-input w0 repeat returns a pair. Partial matches are not full collisions.

**Safe entry point**: Use the compiler-only recipe below, not --selftest or --stats: those run actual collision attempts or campaigns. --ledger also evaluates smaller-register fallback variants; the bounded review called only the default plan/ledger explicitly. --gen-c prints embedded C; --gencode is a Python bytecode diagnostic, not a C build.

## Outputs and interpretation

**Finite arithmetic and allocation**: 256 complete-message digest fixtures match the separately pinned independent reference. Two fixed g steps, 18/20-bit fixtures and seven packed recovery values pass. Every allocated instruction and final output of the single generated function is checked; two deliberate mutations are rejected. This proves allocation equivalence for that generated program, not universal hash-generator correctness.

**Retained generator evidence**: On two calls, the retained no-import WebAssembly artifact emits all 17,238 records and q identically to fresh Python. Records are 36 bytes, of which seven encode the opcode and three 16-bit indices; tested padding remains zero. The module declares minimum 14 and maximum 16 pages; observed linear memory is 917,504 bytes. Retained C matches embedded C after line-ending normalization. No fresh compiler, fuel or native RSS proof is claimed.

**Stored-length entry format**: An entry is 200 bits: key 64, trail ID 16 and length 120, or 25 bytes. Four nonnegative roundtrips and three upper-overflow controls pass. The conservative default trail-number bound 12,753 is below 2^16. Negative fields are accepted; unpack_entry(-1) returns maximal key/ID fields and length -1. This is not a general validation API.

**Stored-length recovery boundary**: Recovery aligns the longer stored trail and advances the pair, rather than recomputing lengths. Six one-batch synthetic cases validate pair/no-hit/budget paths. The loop uses range(shorter_length+1): with stored lengths 1, capr=1 and a noncolliding artificial oracle, it makes two calls and returns None. That documents an extra-call boundary; it is not a real hash witness or a complete repricing of the recovery allowance.

**Declared numerator and memory**: The declared default ledger sums to N=23826827909359788521744622164028074328518 word operations, with unit 638. Body=17,275=17,238+34+3. Code=687,060 bytes; table=312,350; register file=32,768; counters/copy=16,384. Declared setup is 981,617 bytes and search is 1,048,562 bytes. Setup scratch is 204,733 bytes. These are independently recounted formulas, not process-memory measurements or complete success proof.

**Generator diagnostic discrepancy**: The copied --gencode command prints bytecode instructions 2072 GEN_CODE 2040 on CPython 3.11.1; the source comment cites 2,036. Interpreter bytecodes depend on Python version and are not contest-machine instructions. Do not silently equate the diagnostic with the declared code-image budget or call the difference a proven memory overrun.

**Loss helper must not receive the reduced search plan**: For n=18, the plan sets cmax=1,000,000,000. loss builds a Poisson list with cmax+1 entries. The bounded control intercepted its request for 1,000,000,001 terms before allocation. The full-width plan has cmax=2 and was evaluated within a bounded subprocess, but its floating P_lower is not an exact success certificate.

**Projection and protocol meanings**: Duplicate fields count repeated entries, not every equal pair: [5,5,5,7] gives 2 versus 3. Both concatenation expressions retain 21 bits despite a 22-bit comment. T2 unmasking is checked before projection. Mocked protocol routes ignore target metadata, preserve repeated negative IDs and reject unknown experiment names.

## Failure modes

- Do not transfer compact_u5b’s table capacity, byte layout or two-pass recovery budget to this source.
- Do not treat the 36-byte record layout as measured Python object size.
- Do not call loss(plan(18)) or loss(plan(20)); their billion-term Poisson list is inappropriate.
- Negative packed fields need caller validation. The stored-length recovery loop can make one extra no-hit oracle call.
- Diagnostic bytecodes, retained C and retained wasm are different evidence layers.
- A retained generator replay and finite digest agreement do not establish the full-width success premise.
- The existing bsel downloadable generator kit does not contain this source or its wasm.
