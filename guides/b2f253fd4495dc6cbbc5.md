# Traillab regression harness: inspect the selected test workloads

Source: `research/tools/traillab/tests/known_answers.sh`

Public SHA-256: `0d90c787ec16ce49439a868e1914c218468adc89ac1f00324436f355b998642b`

## Reviewed usage contract

A Bash harness that runs Traillab against historical pair, exact-count, sampling and artifact-control expectations. It combines different evidence types into a PASS/FAIL summary; reading the source is necessary to know which claims are exact and which are statistical comparisons.

## Source inspection and available execution evidence

static-source-review; not-replayed-for-publication.

Not a single cheap test. K1 calls check with 20,000 coordinate draws for each baseline, in addition to fixed self-tests/density loops. K2's sdiff counts are unconditional. Other unguarded sections include 128 or 512 sampled prefixes, row-table construction and a 12,103,680-member W8 enumeration. Several additional full-word counts occur only when QUICK is empty. No total runtime, operation-price proof or peak-memory bound is established for this complete harness.

## Declared inputs

**Source tree and executable**: The script changes its working directory to its parent Traillab directory and uses ./traillab plus chi/chi37.txt and chi/chi38.txt. Downloading the shell file alone is insufficient. The library's Traillab source bundle includes these inputs and the C sources needed to build the executable.

**QUICK environment variable**: Any nonempty value selects reduced sampling settings and skips only the explicitly guarded later exact-count block. QUICK=0 is still nonempty and therefore selects this branch. QUICK does not guard the earlier K2 sdiff enumerations.

**Embedded expected values**: The script embeds historical digests, counts, parity patterns, sampled-ratio tolerances and an intentionally inconsistent held-word artifact control. These are fixed source expectations, not user-selected CLI data.

**Execution budget**: The harness has no timeout, maximum elapsed-time flag or worker-count parameter. It does not pass --threads to its Traillab calls, so the binary's defaults apply. A caller must arrange a separate budget and isolation if choosing to run the full harness.

## Outputs and interpretation

**Console summary**: Named PASS/FAIL lines, selected numerical diagnostics, elapsed-time lines and a final 'N passed, M failed' total. Most binary stdout is captured into shell variables and only selected lines are shown.

**Exit behavior**: Exit 2 if the initial directory change fails. Otherwise the final shell test succeeds only when FAIL is zero. This is not a fail-fast harness: a failed expectation increments FAIL and later expensive sections still run. There is no set -e or pipefail policy.

**Evidence interpretation**: An integer-count identity in K2, a sampled confidence comparison in K3/K7 and a deliberate held-word artifact in K5 have different meanings. A complete PASS summary does not turn sampled success laws into exact proofs or the held-word control into a valid-message attack.

**Side effects**: The harness changes its own current directory and starts local binary/Unix-utility processes. It has no explicit network operation or persistent output-file redirection. Invoking it through make test or make quicktest may first compile or update the Traillab binary.

## Imports

- Bash, date, grep with extended-regex and -o support, awk, head, sed and tr.
- A matching compiled Traillab executable and chi37/chi38 baseline files.
- For make test/quicktest: Make, the complete C source bundle, a compatible compiler, libm and POSIX threads.

## Worked examples

### Check shell syntax without running the experiment

Working directory: The extracted traillab directory

```text
bash -n tests/known_answers.sh
```

Expected: With a compatible Bash and unchanged valid source, exit 0 and no diagnostic. This source-derived example checks parsing only; it does not validate expected numbers, dependencies or any binary behavior.

### Use a bounded component check instead of the whole harness

Working directory: The extracted traillab directory after the documented GCC build

```text
./traillab flip --chi chi/chi37.txt --word W22 --mask 04022000 --threads 1
```

Expected: Eight pattern rows and one surviving published pattern. This component was independently replayed by the publication's Traillab check; the complete shell harness was not.

### Recognize the misleading quick-test invocation

```text
QUICK=1 bash tests/known_answers.sh
```

This is documented for identification, not recommended as a smoke-test command. It still runs K2's exhaustive work, row-table construction and the 12,103,680-member W8 enumeration. Do not launch it without a deliberate compute budget.

Expected: Reduced sampling sizes in some sections and omission of the final guarded exact-count block. The source does not imply a short wall time or a fully bounded worker envelope.

## Failure modes

- The opening comment says QUICK skips 2^32 enumerations, but the actual earlier K2 commands are unconditional. Read the control flow rather than relying on the label.
- A failed check does not stop subsequent work. An external runtime budget must account for the shell and its own child processes, not only the parent shell.
- Default worker behavior comes from the Traillab binary; the harness provides no thread override.
- Statistical comparison failures may reflect changed sampling behavior or a real regression. Do not change expected values merely to make the suite pass.
- Output parsing depends on exact text formats. A changed binary can break the harness even when the underlying calculation is still correct.
- The --hold-from tests intentionally create an inconsistent expanded-word model. Their reported gains are negative controls, not usable collision gains.
- Historical tests involving printed characteristic cells do not automatically certify a new sampler, target profile or complete contest charge.
