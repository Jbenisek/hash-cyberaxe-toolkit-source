# SHA-256 SAT encodings: compare clause multisets

Source: `research/sha256grid/check2-1/cnfdiff.py`

Public SHA-256: `6cf3641ff312d7058e30435fa861cedce67caee29dbba43d6216b94c29460b0d`

## Reviewed usage contract

Compare two DIMACS files as multisets of clauses, ignoring literal order within each clause while retaining duplicate-clause multiplicities. In the SHA-256 encoding workflow this distinguishes a mere clause-order change from a changed formula before expensive solver experiments.

## Source inspection and available execution evidence

static-source-review; five-tiny-fixture-comparison-replay-passed.

Finite but input-dependent; the script reads both entire CNFs into memory and sorts literals in each clause. Parsing/storage scale with total literals, plus per-clause sorting and Counter bookkeeping; it has no explicit file-size, memory or runtime cap. Absolute wall time is unknown. Do not point it at large generated corpora casually.

## Declared inputs

**First and second CNF paths**: The first two positional arguments are input paths; additional arguments are ignored. Each noncomment/nonheader line must contain one complete clause ending in 0. Comments must start with c and headers with p at column 0. Variables must use the same numbering and interpretation in both files; this tool does not rename auxiliary variables.

**Supported DIMACS subset**: No blank lines, multiline clauses or multiple clauses per line. An empty clause is represented by a line containing only 0. Run normal Python, not python -O, so the terminator assertion remains active.

## Outputs and interpretation

**Header and count diagnostics**: Prints both tokenized headers, both clause totals, multiset equality and order equality. Headers are displayed but not checked against parsed clauses, so inspect discrepancies yourself.

**Difference diagnostics**: Prints total first-only and second-only clause multiplicities, then up to eight distinct clause tuples from each difference. If multisets agree but order differs, prints the first differing zero-based clause index.

**Filesystem/process effects**: Reads both files and prints diagnostics only. No files are written, no solver or other subprocess is launched, and no network operation occurs.

## Imports

- Python 3 standard library only: sys and collections.Counter.
- Two small existing CNF files using the same variable identifiers; no solver, package data or local imports.

### Distinguish ordering from formula content

Working directory: <archive-root>, the directory containing research/

```text
python3 research/sha256grid/check2-1/cnfdiff.py small-a.cnf small-b.cnf
```

The publication fixture small-a.cnf has header p cnf 2 2 and clauses 1 -2 0 then 2 0; small-b.cnf has the same header and clauses 2 0 then -2 1 0. Preparing fixtures is a separate local action; cnfdiff itself does not create them.

Expected: Observed: identical as multisets: True, same order: False, zero first-only/second-only counts, and first order difference at clause index 0.

## Failure modes

- Do not use --help: there is no help parser or main guard. Import/startup accesses sys.argv and opens inputs immediately.
- Blank lines or missing terminators raise IndexError/assertion errors; noninteger clause tokens raise conversion errors.
- The reader is not a complete DIMACS parser: multiline clauses and multiple clauses per line are not represented correctly by its one-line-per-clause assumption.
- Clause-multiset equality does not validate header variable counts, variable-map semantics or the encoding against SHA-256.
- Different variable numbering can produce a difference despite logical equivalence. Conversely, the same clause numbers with different external meanings are not the same scientific experiment.
- Duplicate clauses remain significant to this comparison even though duplication does not change SAT semantics; duplicate literals within a clause are also preserved.
- Differences are reported to stdout without a dedicated nonzero comparison exit code. Automation must parse the diagnostic or wrap it with explicit policy rather than interpret ordinary exit success as formula equality.
- No claimed SAT/UNSAT, collision probability, attack cost or solver performance follows from this utility.
