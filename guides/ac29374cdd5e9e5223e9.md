# Condition-symbol counter: literal counts and an XOR-support check

Source: `research/tools/schedexact/condcount.py`

Public SHA-256: `0345be26e85c453426b66baf55e9c123317a81b6dc620280f818ae557ab3dd69`

## Reviewed usage contract

Summarize literal lowercase u/n and 0/1 symbols in A/E fields and optionally compare W XOR support against already expanded word lists.

## Source inspection and available execution evidence

static-source-review; synthetic-parser-count-and-support-checks-passed; no cryptographic solution verification.

Linear text counting on the supplied characteristic. No cost or probability model is established.

## Declared inputs

**CHAR.xml**: Expected original text format with option name="n" followed by value, a literal <char value=" opening, multiline rows with A and E fields, and a "/> ending. Validate widths, row uniqueness, sorted indices and target independently; the tool does not do so.

**Optional --pair PAIRFILE**: n expanded hexadecimal words for side one followed by n for side two; not raw messages. The permissive reader skips nonhex tokens and does not enforce 32-bit range. Supply an independently validated file.

## Outputs and interpretation

**Per-row tally**: unA, unE, unW, fix, cond, cum. fix and cond concern A/E only; cond counts u/n plus 0/1. W, x and ? are not included in cond.

**Window totals**: Before/inside/after first-to-last listed W row containing x/u/n. Requires sorted source rows for chronological interpretation.

**MATCH**: XOR-support agreement only: x/u/n require difference, -/0/1 require equality. Does not enforce u/n orientation or fixed values, compute A/E states, expand the schedule or verify a digest.

## Worked examples

### Count a validated local characteristic

Working directory: Folder containing the downloaded condcount.py and an independently validated CHAR.xml

```text
python condcount.py CHAR.xml
```

Expected: Per-row literal counts and window totals. One u in A plus one fixed 0 in E contributes two, regardless of W. No success exponent is certified.

### Check only expanded-word XOR support

Working directory: Same folder, with a validated flat list of 2*n expanded words

```text
python condcount.py CHAR.xml --pair PAIRFILE
```

Expected: MATCH/MISMATCH rows for W support. A MATCH does not verify signed orientation, fixed values or a collision.

## Failure modes

- A character tally need not equal the number of independent remaining conditions.
- Malformed or unmatched lines can be skipped; short fields are not rejected.
- The historical ElementTree proposal lost literal-newline row boundaries; the current source already contains the HASH$CyberAxe team's repair.
- Changing u to n need not change the pair verdict because the checker tests XOR support only.
- Permissively parsed pair words may exceed 32 bits or include unintended hexadecimal-looking tokens.
