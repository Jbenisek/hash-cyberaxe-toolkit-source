## Reviewed usage contract

The saved adjudication for 2cf0d4a5 rejects this select price: select is not a permitted single contest operation, and recovery immediates were undercounted. This four-round select-gate edition uses the zero-prefix message family and a fixed output mask, not the selected prefix of stack1020. The local adder is proved by exhaustive bit/polarity cases; the full hash is checked by finite reference fixtures. Neither establishes an exact full-width success law. The source credits jungjipdo’s 6ae36351 proof 3.4 for the masked walk and identifies its select-adder implementation with 0ecdfe35 / 0a9640ed / 3356413f.

## Declared inputs

**Actual target and complete message**: ROUNDS=4, UNIT=846, standard IV, counter 0, length 64 and flags 11. The message is 32 zero bytes followed by the little-endian 256-bit x. The module header correctly says four rounds, but the scalar digest docstring still says seven. The executed constants and independent fixtures determine the target.

**Full-adder primitive and attribution**: The variable full adder uses two XOR gates and one select: choose equal-polarity x,z, set t=x XOR y, sum=t XOR z and carry=select(t,z,x). The machine model charges select as one three-input operation; the Python expression expands it into Boolean operations.

**Masked-walk interpretation**: The circuit stores g(x)=f(x) XOR q, with q derived from its output polarities. Fixed q preserves equality of two outputs exactly, but changes trajectories. f_scalar returns the unmasked digest. The same mask for these two four-round editions does not transfer a random-mapping or probability premise.

**Declared plan**: The full-width numerical selector chooses Tp=1326, 87,214 endpoints, kappa=14, 800 declared registers and one allowed cut. The B calculation uses floating-point loss estimates with fixed full-width scales. The ledger below is exact arithmetic on that selected plan, not a certified probability bound.

**Organizer experiment meanings**: bsrho-n18 combines one reduced masked target attempt with a keyed BLAKE2b ideal-control attempt. T1 instead iterates unmasked f with a fresh first message half. proj-k0-w256 unmasks stored values before seven 21-bit projections; a w0 repeat is not a full-digest collision. Trial modulo 3 selects one of three input families.

**Safe example boundary**: Use the compiler-only command below in a disposable directory with the pinned download. It performs no walk or probability optimization. --selftest includes actual collision attempts; --stats runs campaigns; --ledger and --loss select/evaluate numerical plans. --gen-c emits source but does not compile it. Original search routes and launch scripts were not run.

## Outputs and interpretation

**Local full-adder identity**: All 512 one-bit value/polarity/constant-substitution cases pass under this source pin, including 64 distinct-variable cases. The latter emit exactly 3 gates. Wrong-sum and wrong-carry controls are rejected in every case. Bitwise lifting proves this local identity at any plane width, not universal correctness of the entire hash generator or a hardware price for a primitive.

**Four-round arithmetic and allocated program**: 256 complete-message digest fixtures match the independently pinned reference, with two reference known answers, two fixed masked steps, 18/20-bit fixtures and seven packed recovery values. All 16,502 allocated instructions are structurally checked across 9 chunks, including every operand, connection and final output. Register extent is 771, packed recovery uses 836 operations, and two changed-program controls are rejected.

**Exact declared numerator with conditional meaning**: The stored model sums to N=22119818953113681525669472968451245801188 word operations, with reference unit 846. Body=16,539 = 16,502 kernel + 34 filter + 3 loop. The calculation verifies the ledger after its floating-point selector has chosen B; it does not certify that B achieves the intended success rate, cover every handler, or announce a new accepted attack score.

**Known pricing defects, not merely unchecked assumptions**: Saved verdict 2cf0d4a5 is refuted and ineligible. The 3,960 select operations each expand into three permitted Boolean operations, adding 7,920 operations per batch before repricing the run. Fresh inspection identifies eight packed recovery XORs containing large mask immediates. Pricing those at 36 rather than five bytes adds at least 248 bytes: the declared 1,048,504-byte search phase becomes at least 1,048,752, or 176 bytes over one MiB. Removing 18 ten-byte slots covers this defect alone; it is not a complete repair or a recomputed success-certified price.

**Memory and preprocessing formulas**: Code is 134,380 bytes; endpoint capacity is 87,214; counters/copy use 16,384 bytes and the declared register file 25,600. Search phase totals 1,048,504 bytes; setup totals 233,636. Setup charges factor 250 times (2 times 33,884 generator calls + 16,502 emitted instructions), plus the fixed allowance. These are model quantities, not Python RSS or native instruction measurements.

**Records and two-pass recovery**: A ten-byte endpoint contains a 63-bit key and 17-bit trail ID, not a stored length. Recovery recomputes both lengths before alignment and advance; the ledger charges two passes at 836+64 operations per batch plus 600. Six one-batch constant-map cases test an artificial pair and budget/no-hit exits. They are synthetic controls, not BLAKE3 collision witnesses.

**Domain and cache boundaries**: Four nonnegative record roundtrips and two upper-overflow controls pass. Negative packed fields are accepted and can alias maximal unsigned fields; internal IDs are nonnegative. The B cache omits Sb. A synthetic oracle demonstrates stale reuse when Sb changes, not a failure of the one fixed archived default. Validate inputs and isolate the cache for parameter sweeps.

**Statistics and dispatch**: [5,5,5,7] gives two duplicate entries but three equal pairs. Projection expressions keep 21 bits where comments say 22. Mocked dispatch ignores target metadata, retains repeated/negative trial IDs and rejects unknown experiment names. A synthetic Halt preserves prior counters. These interface observations are not a schema guarantee or complete work count.

**What has not been replayed**: No retained four-round WebAssembly artifact or fresh C build was executed in this review. The existing three-round bsel generator ZIP covers a different source identity. No original collision search, prefix selection, statistical campaign, exact numerical probability proof or complete attack-price certificate is claimed.

## Failure modes

- The select numerator is a rejected historical price, not an accepted score; neither edition’s stated layout includes the demonstrated 248-byte correction.
- Read the executed round count; stale seven-round comments are not evidence of a seven-round result.
- Do not substitute the three-round source, mask, instruction count, table capacity or replay ZIP.
- Preserving equality under a fixed mask does not prove a walk success law.
- Select and binary-gate ledgers depend on different primitive conventions; compare those before scores.
- Declared byte records and operation factors are not measured Python memory or CPU instructions.
- Unmask outputs before digest comparison; distinguish partial-output repeats from full collisions.
- Validate negative fields and reset parameter-sensitive caches when sweeping omitted keys.
- The exact ledger numerator is conditional on its selected numerical budget and machine assumptions.
