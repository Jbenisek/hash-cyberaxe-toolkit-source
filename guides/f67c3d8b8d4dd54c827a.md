# Understand and reconstruct the 39-step SHA-256 pair factory

Source: `research/game/climber/guided/pairfactory/pf.py`

Public SHA-256: `ead64dbd7f9885d9fe9051e7f2cf10def0b27ee8092864b3dc11e264de7cfbeb`

## Reviewed usage contract

Generate additional message values on a known signed 39-step SHA-256 characteristic, exclude previously known pairs, independently check solver candidates, and rank reconstructed conditional-tail samplers using a separate second seed set. The intended model is full 32-bit SHA-256 with a shared, freely chosen chaining value, not standard-IV hashing. It does not discover a new round count, prove a success probability, submit an entry or establish an attack cost by itself.

## Declared inputs

**Command line: pf.py TARGET LANES CAP [dry]**: The first three positional arguments are parsed as integers immediately at module startup. TARGET is the desired total number of FOUND_pf_ files including resumed files, not necessarily the number added in this invocation. LANES creates that many worker threads. CAP is the CPU-second limit for each Kissat process. A fourth argument exactly equal to dry skips worker launch only after initialization. There is no argparse help mode and no validation that these integers are positive.

**Known characteristic and seed witness**: ladder.py reads guided/chars/pin39b_char.xml and research/outside/kepler_in/angle_pub39_char_w32_WITNESS.json. It builds a 39-step characteristic with its original A/E rows through 34, W rows through 38, and equality in the final four A/E rows. Both messages share a chosen CV. The seed must independently profile as a collision and match the generated characteristic exactly. Each factory job then pins both copies' A/E values for four consecutive rows, starting at one of 14 positions from 6 through 19.

**Exclusion and resume corpus**: KNOWN_FILES.txt supplies paths relative to research/. Startup also scans tail_var subdirectories other than pf_ replicas and resumes FOUND_pf_ files. Supported pair inputs are witness JSON, decoded M1/M2 text, and a particular tail Python source format. Only pairs with the seed's modular message difference, allowing orientation reversal, enter the known-pair registry. The reviewed list contains 251 paths; the full transitive corpus was not reviewed as part of this usage guide. Some Python constants are parsed with eval, so these inputs must be trusted local research artifacts, not arbitrary uploads.

**Tail program, controls and request sets**: Requires work/tail/r39tail_free.py, work/tail_stats_dir.py, r39joint.py, both named baseline replicas under work/tail_var, work/req/r39-tail-01.json through r39-tail-14.json, and work/req_pool/r39-tail-15.json through r39-tail-28.json. Paths are relative to research/pkg_r39_combined except r39joint.py. Two representative request files were inspected: each has 256 trial records with string seeds; the tail program uses the first 21 seeds for its observations. Preserve the complete reviewed request sets rather than inventing substitute seed files.

**Clean model environment**: The driver sets SIGNED=1 and TAIL=own but inherits other encoder options. For the documented model, WBITS must be 32, constant offset must be zero, and schedule-only, native-XOR, altered ordering and other experimental encoder switches must retain their ordinary defaults. The encoder reads environment variables during import. An inherited reduced-width or experimental configuration is not the documented experiment. FMAX defaults to 2 and prioritizes factory work while tails wait; it is not a hard maximum on solver processes, because all LANES may become factory workers when the tail queue is empty.

## Outputs and interpretation

**Initialization, including dry mode**: Creates fixed shared-memory scratch, per-user tail scratch and found directories; writes a base XML/CNF/map; copies base.xml and base.map into the source directory; loads and profiles the known corpus; and checks the tail pin-reconstruction rule. These effects occur outside the main guard. Importing pf.py is therefore not a read-only library operation. Dry mode still performs this initialization and then prints base-variable, clause, known-pair and initial-job counts before exiting.

**Solver candidates and independently checked pair files**: Writes and repeatedly overwrites per-lane CNF, solver output, model and decoded check files. SAT output is decoded by sha_cnf.py and passed to indep_verify.py. Only output containing the independent verifier's success marker is eligible for a new FOUND_pf_NNN.txt file; the verifier recomputes distinct messages and full eight-word feed-forward equality. A further exact characteristic comparison determines whether the pair becomes a new factory source. Preserve the on-char field: independently verified pairs are not automatically equivalent to on-characteristic sources.

**Tail stages and records**: Rewrites a copy of the tail program for each eligible pair's CV, message and reconstructed pins; creates tail_var and tail_varB outputs, out_01.json through out_14.json, per-request error files and timing logs. The statistics helper also writes EXP_S.txt. Stage A measures candidates with the first seed set. Stage B measures up to five Stage-A leaders plus two baseline controls with the second seed set; the final ranking uses Stage B. TAILS_A.tsv and TAILS_B.tsv contain mean_lin and lcb999 in the helper's log2 representation. These are empirical conditional-tail statistics, not exact probabilities or filing-ready cost proofs.

**Campaign reporting and side effects**: Appends RESULTS.tsv, TAILS_A.tsv, TAILS_B.tsv and ERRORS.tsv, overwrites PROGRESS.txt, and appends an internal research run ledger. The source contains no network or submission calls. It does launch local subprocesses and writes both within and outside its own directory. Its fixed scratch locations make concurrent independent instances unsafe without prior isolation or source adaptation.

## Worked examples

### Initialization-only reconstruction in an isolated complete tree

Working directory: The root of an isolated, complete research-tree copy in a dedicated POSIX environment

```text
python3 research/game/climber/guided/pairfactory/pf.py 1 1 30 dry
```

Source-reviewed syntax, not executed for publication. This is not a harmless help command: it builds a potentially large CNF, creates directories, overwrites base artifacts and reads the known corpus. Use only after restoring the dependencies, checking model environment defaults, and isolating the fixed scratch locations from other work. It does not launch the solver or tail workers.

Expected: If initialization and all assertions succeed, stdout reports base char: NV ... NC ..., prior known pairs, on-characteristic sources, resumed found count and first-generation job count, then exits. No specific counts or runtime are asserted by this guide.

### Read the full campaign invocation, not a quick-start benchmark

Working directory: The same isolated, complete research-tree copy

```text
python3 research/game/climber/guided/pairfactory/pf.py 1 1 30
```

Removing dry launches real solver and tail work. This example documents the interface, not a recommendation to run a cheap test. One lane and a 30-second solver CPU cap do not cap total elapsed time, memory or tail work. Restored found files can satisfy TARGET before any new pair is found. Even with no new pair, Stage B can still measure baseline controls. No campaign was launched during this review.

Expected: Depending on solver outcomes and existing files, the driver appends factory results and may create verified pairs, then drains tail stages and reports the available Stage-B ranking. Empty, partial or failed scientific results are possible; a normal final print or ledger line is not sufficient evidence that every requested measurement completed successfully.

## Failure modes

- Missing relative imports, the characteristic, seed, known registry, tail_var directory, baseline replicas or request files prevent reconstruction. A standalone pf.py download cannot be run successfully.
- No --help interface and substantial import/startup effects. Do not import the module to inspect it or treat dry as no-write validation.
- Inherited encoder settings can silently change the model or trigger mismatched map/characteristic assertions. Keep the full-width, normal-round-constant model explicit.
- Solver status is inferred from stdout. The driver overwrites the Popen returncode field after os.wait4 instead of preserving the real exit status; missing solver/status text becomes UNDECIDED, not UNSAT. Time limits do not prove impossibility.
- Verifier and statistics subprocess return codes are not a complete success contract. Inspect the independent-check marker, ERRORS.tsv, complete output observations and statistics rather than trusting campaign completion alone.
- Tail cache reuse accepts any nonempty JSON object containing trials; it does not bind cached data to source hashes, seeds or the full expected observation count. Do not reuse unverified or stale output directories.
- FMAX is a scheduling preference, not a strict factory-process cap. LANES controls total driver workers, but helper subprocesses and unrestricted tail work still require explicit resource planning outside this archival script.
- Shared scratch paths, source-directory writes and non-transactional result files can collide across runs. There is no built-in graceful cancellation, process-group cleanup, checkpoint transaction, global wall-time cap or disk quota.
- Malformed resume files can fail startup; some exceptions during jobs are only logged. A failed tail task can leave an incomplete candidate summary. ERR statistics and absent candidate rows must remain missing data, not zero rates.
- Python-source constants are evaluated during parsing; only use trusted, reviewed artifacts. The guide does not certify arbitrary source files named in the historical known-pair registry.
- New values on a known 39-step characteristic and empirical tail rankings do not establish a 40-step extension, standard-IV collision, exact probability, accepted contest claim or general cryptanalytic improvement. Those need separate evidence.
