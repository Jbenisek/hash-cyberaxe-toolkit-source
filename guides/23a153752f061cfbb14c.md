# BLAKE3 bit-sliced rho: 256 lanes, checked register assignments and duplicate-count semantics

Source: `research/blake3_r3/bitslice/pkg/blake3/experiments/bsrho.py`

Public SHA-256: `b8341c83cfbdfd05cc52bd99d8a5e97ac46c0e008549082da4be5d764b917bfa`

## Reviewed usage contract

This standalone edition evaluates 256 independent three-round BLAKE3 chains in bit-sliced planes. Its chain step is distinct from the seven-lane packed recovery circuit. The reviewed contract explains both representations, the generated step's register assignment, three different experimental events and a misleading duplicate statistic. Exact source copies share these checks; differently hashed bit-sliced editions do not.

## Source inspection and available execution evidence

static-source-review; copied finite digest and compiler checks, structural allocation certificate, synthetic capped flow, declared-ledger arithmetic and mocked experiment routes; no original search.

Finite packed-circuit generation at import, then 43,246 recorded generator primitives, 19,022 emitted step operations and one straight-line register assignment. This is a small bounded compilation task on the host, not a measured contest-operation certificate. No target/ideal birthday run, fresh-key first-repeat run, selftest campaign or projection experiment is executed.

## Declared inputs

**Hash and message context**: The target message is 64 bytes: 32 zero bytes followed by little-endian 256-bit x. Standard IV, counter 0, block length 64, flags 11, three rounds. f_scalar(x,n,key) additionally supports a nonzero first half, but key=0 is the target. Fresh-key family-law observations are not the same experiment as the fixed-zero-prefix chain.

**Bit planes and stored polarity**: Each of 256 machine-word bits represents one lane; each plane represents one chain-state bit. Rotations rename planes rather than execute shifts. Stored plane j may be complemented according to the fixed PINS mask. Step() corrects output polarity to the same input convention, allowing repeated steps without representation changes. pack_lanes, lanes_of and lane_value must use that same polarity.

**Widths and plan support**: Plan configuration exists only for n=18,20,256. plan(22) raises KeyError; do not transplant the 22-bit defaults of older rho.py editions. The full plan uses 1,024 declared registers, 256 lanes, U-free per-step filtering, s1=32 and W=90. Its source-selected threshold is Tp=138 with 9,938 endpoint entries. Smaller-register fallback prices are not independently audited in this guide.

**bsrho-n18 event**: Each requested trial runs one 18-bit target attempt, one keyed BLAKE2b ideal-control attempt and a fresh-key 12-bit first-repeat statistic. Only the target can supply the returned message pair. T1 changes the first 32 message bytes, while the target keeps them zero. These controls do not by themselves prove a full-width random-mapping model.

**proj-k0-w256 event**: The source computes 2,048 full-width digests per trial and observes seven 21-bit projections. trial ID modulo 3 chooses uniform derived inputs, consecutive counter inputs or eight chained steps from 256 starts. Only a repeat in projection w0 with distinct input messages can produce a returned pair. It is a 21-bit event, not a full-output collision; chained inputs and repeated values require their own sampling interpretation.

**Protocol validation and safe command**: experiment_id is required and must be bsrho-n18 or proj-k0-w256; other names raise ValueError. Seed and trial fields are required; target metadata is not validated and repeated trial IDs are not deduplicated. The imported selftest() itself runs six original collision attempts after arithmetic checks. CLI --stats runs a larger campaign. Neither was executed; use the finite circuit-generation example below.

## Outputs and interpretation

**Finite arithmetic and representations**: All 256 fixed full-width lane digests agree with the separately pinned reference, which passes two standard known answers. A second fixed chained step agrees with scalar evaluation. Another 256 lanes each at widths 18 and 20 pass arithmetic and stage-1 mask controls. Seven packed recovery values and transposition fixtures pass. These are finite digest checks, not a universal proof of the generator's BLAKE3 equivalence.

**Generated straight-line allocation**: The full step emits 19,022 instructions and uses registers 0 through 770, an extent of 771. The audit checks the generated AST against every emitted operation, verifies that each register operand still holds the required symbolic value before a write, and checks all output registers. Induction over the 19,022 instructions establishes equivalence of this generated step and its allocated execution for arbitrary plane inputs. Altered-register and altered-operator controls are rejected. This does not certify handler/caller storage or the entire attack.

**Declared default ledger**: The declared full-width body is 19,060 operations: 19,022 kernel operations, 35 for the filter and 3 for the loop. The exact sum of its stated terms is 26,546,193,039,929,391,864,594,513,070,574,453,234,113 word operations, with units divided by 638. The generator allowance is 200 times (43,246 primitive calls + 19,022 emitted operations) = 12,453,600. These are verified formula evaluations after floating-point plan selection, not independent proofs of handler/generator allowances or full attack success.

**Memory scope**: The declared unrounded storage sum is 1,048,562 bytes: 750,960 code bytes, 32,768 register bytes, 16,384 counter/copy bytes and 9,938 x 25 table bytes. This is 14 bytes below 1 MiB in that formula. No separate whole-word placement/rounding certificate is supplied by this audit. Do not confuse this figure with Python RSS or the separately reviewed rounded layouts of other rho editions.

**Duplicate entries are not equal pairs**: dup_w0 and the other dup_* fields compute len(values)-len(set(values)). A value appearing c times contributes c-1, whereas all equal pairs number c(c-1)/2. The synthetic values [5,5,5,7] yield the program's duplicate count 2 but equal-pair count 3. The statistics printer compares duplicate totals with a pair-count expectation; the audit exposes the semantic mismatch, not its magnitude in historical runs or an invalidity proof for every sparse sample.

**Exact projection bit positions**: Every projection is masked to 21 bits. p01 retains low 11 bits of word 0 followed by low 10 bits of word 1. p23 retains low 11 bits of word 2 followed by bits 11 through 20 of word 3, because the source shifts by 107 before masking. These are not two intact 11-bit pieces after the final mask. Seven formulas were checked independently on 256 digest fixtures.

**Counters and capped control flow**: This edition keeps a mutable counter dictionary through Halt: synthetic batches=3 and stage1_hits=2 survive with halt=1, unlike the zero-reset wrappers of b3r3t/lc. Six one-step artificial-map fixtures cover a recoverable pair, no stage-1 hit and stage-1/table/recovery/cut budget exits. Synthetic pairs are not BLAKE3 witnesses; batch counts still do not count all recovery, setup or generator operations.

**Unsafe reduced-width loss helper**: Reduced plans set cmax=1,000,000,000. loss(p) constructs cmax+1 Poisson terms, so loss(plan(18)) or loss(plan(20)) attempts a billion-term calculation. This is a source-derived resource hazard; the unsafe path was not executed. The documented finite example does not call loss, a search or selftest.

## Failure modes

- Use the bit-plane polarity consistently; a stored complemented plane is a representation choice, not a different hash.
- Do not treat 18-bit target pairs, 21-bit projection pairs or fresh-key 12-bit observations as full 256-bit collisions.
- Count repeated entries and all equal pairs separately; they differ once multiplicity reaches three.
- Projection p23 uses word-3 bits 11 through 20, not its low 10 bits.
- Do not execute loss(plan(18/20)); its billion-term loop is outside the intended full-width loss path.
- selftest() and --stats launch original searches; the documented compiler example does not.
- A generated-step allocation certificate does not prove the full hash generator, handlers or caller fit the same budget.
- Declared cost formulas and floating-point tail selection are not an independently proved success rate or complete price.
- Do not transfer this guide to bitslice2 or later editions merely because their filenames match.
