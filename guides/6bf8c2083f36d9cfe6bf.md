# BLAKE3 B5: five rounds and a larger declared memory budget

Source: `research/blake3_r5/b5/pkg/blake3/experiments/bsrho.py`

Public SHA-256: `e83ab3afb633441517737e4b69c88b1e98f4ebb7d436d506974a272b356b7f4e`

## Reviewed usage contract

B5 is a useful contrast to compact four-round packages. It extends the binary circuit to five rounds and uses a uniform 36-byte instruction format. Instead of claiming to fit the code below 1 MiB, it declares a larger memory limit and pays a memory factor in its scoring model. The cost of a circuit, the size of its representation and the validity of its success premise remain separate questions. Historical predecessor attributions remain in the source.

## Source inspection and available execution evidence

static-source-review; Source-pinned finite digest/allocation, exact declared layout, explicit-budget ledger and mocked model/cache controls. No default optimization, generator or original collision search..

One fixed circuit construction/allocation, tested with a ten-second subprocess limit. No default model optimization or original campaign.

## Declared inputs

**Five-round target**: Five-round BLAKE3, unit 1054, on one full block: 32 zero bytes followed by little-endian x. Initial IV, counter 0, length 64 and flags 11. The walk uses f XOR q, not the unmasked digest.

**Circuit representation**: 256 bit-sliced lanes. The main circuit has 31,606 binary operations, allocates 771 registers and compiles into 16 chunks. Recovery packs seven 36-bit lanes and executes 1,072 primitive operations before the separately charged handler overhead.

**Record and memory inputs**: The source declares 800 registers, 36 bytes per instruction, 10-byte records with 64-bit keys and 16-bit trail IDs, and 1,363,240 bytes of memory. Validate nonnegative field inputs; negative -1 aliases unsigned all-ones fields.

**Model boundary**: The numerical loss helper fixes L to 2^122/Tp and the domain to 2^256. The loss wrapper does not forward reduced width. Its run-length cache omits Sb; use a fresh process or clear the cache when changing that parameter. These are source-specific controls, not evidence that the fixed default is affected.

**Safe finite entry point**: Use the exact hash-checked download in a disposable directory. The compiler-only example below does not call a default plan, --selftest, --stats, a collision attempt or an embedded-C build. The public copy uses CRLF while the local original uses LF; normalized text equality is checked and both fingerprints are retained in the report.

## Outputs and interpretation

**Independent finite arithmetic**: 256 fixed input lanes match the independent reference, alongside two known answers. Allocation/chunk controls, two rejected mutations, a two-step masked chain and packed recovery fixtures pass. This is bounded evidence, not a universal hash-generator proof.

**Declared phase arithmetic**: The source constants are step=31,606, stage filter=34, body=31,643, code=1,221,192 bytes and table=10,000 records. Declared setup/search phases are 1,325,688 and 1,363,176 bytes. Code alone exceeds 1 MiB. These are abstract source-model quantities, not host Python memory usage or a complete machine-handler audit.

**Memory limit versus phase peak**: The allocation limit is 1,363,240 bytes, while the maximum declared phase uses 1,363,176 bytes. Their log2(memory/2^20) components are 0.378608141980463247375509978625806213363377650241105262053169 and 0.378540410216393602098568004555773135237782124565675036942881, respectively. Do not substitute the limit for the phase peak when reproducing the historical row. Neither component is a total score or a probability proof.

**This edition fits its trail envelope**: The source envelope 256+10,000+1+1=10,258 is below the 65,536-value trail field. The original compact package’s 83,907-start mismatch must not be transferred to this edition. Likewise, the compact five-byte instruction omission is not automatically a defect in this uniform 36-byte layout.

**Explicit fixture ledger**: At supplied Tp=22 and B=100000000000000000000000000000000000, independently expanded integer components total N=10302496048561015212815230542928988826448. Recovery is charged twice at 1,072+64=1,136 operations per batch, plus 600. This is a supplied-budget fixture, not a selected or optimized plan.

**Fresh interface controls**: Four record roundtrips, two upper-overflow rejections, six one-batch artificial search branches and four common-endpoint recovery graphs pass. Recovery needs 5, 7, 4 and 2 calls in those four graphs. None is an actual BLAKE3 collision witness.

## Failure modes

- Do not reuse the four-round unit 846; this target uses 1054.
- Do not advertise the declared code as fitting under 1 MiB.
- Do not count a memory component as a full attack score.
- Do not transfer a compact five-byte instruction accounting defect to a different representation without checking it.
- The full-width numerical helper is not a calibrated reduced-width probability model.
- Synthetic recovery branches and finite digest fixtures do not validate the fixed-target random-function premise.
