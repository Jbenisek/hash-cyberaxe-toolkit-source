# Decoded SHA-256 pairs: recompute feed-forward outputs

Source: `research/game/climber/guided/kit/indep_verify.py`

Public SHA-256: `dec3ad8f2be2ffaecc6e0e63801a12d75de19c3977685a8ff5133fde278b0513`

## Reviewed usage contract

A separate plain-Python compression implementation that reads a target map and decoded message/CV lines, checks message inequality and compares all eight feed-forward output words. It imports no project encoder. It verifies a concrete equality predicate, not that every SAT clause was satisfied or that a search cost is correct.

## Source inspection and available execution evidence

static-source-review; bounded-finite-controls-passed; other modes not runtime-certified.

Two N-step compression evaluations and two schedule expansions, plus parsing and output comparison. At 32-bit width and N>=16 each schedule adds N-16 words. This is finite witness-check work, not the work of producing a witness, satisfying every CNF clause or proving a success probability.

## Declared inputs

**Invocation**: python -B kit/indep_verify.py MAP DECODE_TXT. Two positional arguments are consumed at module startup; there is no argparse/help interface or main guard. Importing the file also attempts the check.

**MAP JSON**: Reads n, optional wbits (default 32), and chaining for the printed label. It does not need the encoder's variable arrays. Validate n and width externally; the source does not enforce a complete supported-target schema. For this teaching kit use n=37 or 38, wbits=32 and a common CV.

**Decoded pair text**: For each side k=1,2, supply a line M<k>: W= followed by sixteen lowercase hexadecimal words separated by spaces, immediately followed by an indented chain= line of eight words. The regex accepts more general word lengths, but does not validate canonical 32-bit ranges or vector dimensions. Use eight hex digits per word.

**Model convention**: Both sides are evaluated from their own parsed chain values, using K[0] through K[n-1]. At width 32 this is normal reduced-step SHA-256 compression with feed-forward. Reduced widths scale rotations by max(1,(k*w+16)//32) and truncate constants; those are experimental scaled models, not standard SHA-256.

**Caller obligations**: The chaining label is only printed: sfs does not cause the script to require equal CVs, nor does iv require the standard IV. The source ignores constant-offset and schedule-only encoder settings. Check both CVs, target width, step count, canonical word bounds and intended domain outside this script.

## Outputs and interpretation

**Verification predicate**: Prints the differing message-word indices, whether the eight feed-forward outputs are equal, and exactly INDEP VERIFIED only if at least one of the first sixteen message words differs and both complete outputs match. This is not a proof that the pair obeys its original signed characteristic or band pins.

**Exit and failure behavior**: Missing expected decode lines print a diagnostic and exit 2. A well-formed noncollision or identical-message pair prints INDEP NOT VERIFIED but normally exits zero. Other malformed input can raise an exception. A caller must inspect the exact success-marker line as well as validate the input model.

**Effects**: Reads the map and decode text, computes locally and prints to stdout. No solver subprocess, file write or network operation is performed. The teaching wrapper creates its own temporary fixture files and deletes them after checking.

## Worked examples

### Use the source-checked finite replay

Working directory: The extracted boardpair-kit directory

```text
python -B replay.py
```

Expected: Two original pairs verify; their one-extra-step, one-bit-mutated-message and identical-message controls are rejected. The wrapper checks exact marker lines, not exit status alone. The 37-step pair is an external numerical control and the 38-step seed is project data.

### Check an existing decoded candidate

Working directory: The extracted kit root, with reviewed candidate.map and candidate.chk files supplied separately

```text
python -B kit/indep_verify.py candidate.map candidate.chk
```

This documents the interface; the kit does not include arbitrary files with those names. Confirm n, 32-bit word ranges and both CVs before interpreting the result. Use a full-width shared-CV record for a semi-free-start claim.

Expected: A valid nontrivial pair prints an exact INDEP VERIFIED line. An invalid or identical-message pair prints INDEP NOT VERIFIED and may still exit zero. A printed chaining=sfs label alone does not prove that the input CVs were equal.

## Failure modes

- Do not treat exit zero as successful verification.
- Do not trust a previously saved INDEP VERIFIED substring as a fresh check of current bytes.
- The source prints but does not enforce its chaining label; separately check standard-IV or common-CV eligibility.
- An encoder with shifted constants or a schedule-only filter is not the target implemented here.
- Overwide words, malformed lengths or unsupported widths can produce exceptions or misleading distinctness semantics; validate canonical inputs first.
- The verifier does not compare a solver model against every original CNF constraint or prove a signed characteristic.
- Importing the script runs it immediately; it is a CLI script, not a side-effect-free library API.
