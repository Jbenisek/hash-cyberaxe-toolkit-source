# SHA3 r8 memory program: embedding, local Boolean checks and execution limits

Source: `research/checks_1015/pa_src/pos_sha3r8/experiments/s8ls.py`

Public SHA-256: `23d51e336be6ec67c99f858afdaabe7f1b9f97295fa81db1b8b099222af2c3a0`

## Reviewed usage contract

Historical 8-round SHA3-256 experiment with an explicit register/memory program. Four 64-bit inputs embed injectively into 128-byte messages through directly readable lanes 1, 6, 4 and 9. Two dependent lanes impose XOR relations. The first-round affine structure and local chi implementation can be checked without running the full generator or a collision search. The supplied rho and projection modes seek 22-bit prefix agreement, not full 256-bit collisions.

## Source inspection and available execution evidence

static-source-review; copied-source scalar, embedding, affine and local-chi checks plus mocked dispatch; no setup, full generator, allocator or search.

Normal main builds, allocates, hashes and compiles the program before parsing JSON, then performs two packed check steps and 512 scalar reduced-round checks. Under the unregenerated NSTEP declaration, eight projection steps contribute 427,424 program operations; up to 4,000 rho steps contribute 213,712,000. Setup, input/output, event handling, stored tables, replay and Python bigint costs are additional. These are conditional components, not a complete contest price, timing benchmark or success guarantee.

## Declared inputs

**Exact request profile**: schema_version=1; target_profile=sha3-256-r8-prefix-v1; experiment_id=rho-w22 or proj-w256. event must be exactly kind=digest-xor-mask, mask_hex=ffff3f followed by 29 zero bytes, expected_hex=32 zero bytes. Extra event fields are rejected. Each trial supplies trial (preserved in the response) and seed (hex decoded by bytes.fromhex).

**Unsigned point and single-block message domains**: Use 0 <= u < 2^256 and at most 256 lanes per trial. msg_of masks four 64-bit chunks, so out-of-range points alias valid inputs rather than being rejected. Do not pass negative points to to_planes: its right-shift loop does not terminate for them. The digest wrapper handles a single padded SHA3-256 block, not arbitrary-length input; 136, 137 and 200 bytes raise IndexError. Round counts are not validated: 25 aliases 24 and -1 aliases 23. Callers must enforce 0..24 rounds.

**Declared generated-program identity**: The source declares NSTEP=53,428, listing SHA-256 dcacec2ffa1d7f9a6ee35c3f097b0e4a43840dbe3acdb83cc0ba927f74d0ccde, KR=1018, boundary resident limit KB=975 and PF_K=16. Its 1,018 program registers plus six loop registers form a declared 1,024-register budget. These are source declarations, not independently regenerated allocation or listing results.

**Embedding and plane packing**: The four point words appear in message lanes 1,6,4,9; lanes 11 and 14 are their pairwise XORs plus fixed constants. Remaining message lanes are fixed. Plane bit 256*t+l represents lane l of trial t. Request trial count is not capped; Python bigint width and host memory grow with it.

## Outputs and interpretation

**rho-w22**: After each generated step, planes 22..255 are cleared. The walk uses four distinguished bits, trail cap 128, 3,000 starts per attempt and attempt cap 400 steps. A request-wide 4,000-iteration limit raises no pair if any trial remains unfinished. Success responses contain distinct 128-byte messages and steps/trails/dead/attempts/stored/replay_evals observations. The final assertion checks 22 digest bits only.

**proj-w256**: Eight full-width steps from 256 starting lanes retain up to 2,048 image-prefix keys per trial. A repeated 22-bit key yields two reconstructed messages and a zero-based step index; no match returns null message fields. The full-width trajectory is not the same map as rho-w22. Independently rehash returned messages: main does not perform a final projection-pair check.

**Equality versus a prefix event**: The step represents digest(msg_of(u)) XOR a fixed output mask. The mask cancels when comparing complete outputs. A 22-bit equality discards 234 bits of the full collision condition. Neither experiment nor the bounded publication fixtures prove a full-width success probability.

**Finite component evidence**: Four full 24-round digests (0, 3, 128 and 135 bytes) match hashlib.sha3_256. Nine embedding boundary points, 18 plane round trips and two padding lanes pass. Zero plus all 256 basis inputs check the affine first round and next theta. Local chi checks cover 2,048 rows / 10,240 output bits across all 32 input and stored-polarity patterns and two requested-output patterns; output-bit mutation controls fail as intended. These do not certify the full generator or a global optimum.

**Request-interface evidence**: Stubbed setup/check/search/digest functions test caller IDs, distinct synthetic response messages, null projection output, empty requests and six rejected requests. Setup and check_step precede validation even on malformed input. Synthetic response messages are not collision witnesses.

**Program schedule and charge boundary**: The source schedule is AFF, GB, GA, GB, GA, GB, GA, R7. Its declared per-step total is 53,428 operations including the stated loop overhead. The publication checks did not regenerate this listing, allocation, spill count or complete contest ledger. Declared operation counts are not elapsed CPU time or proved attack cost.

## Failure modes

- Use the bounded imported example for an installation check. Empty or invalid JSON does not avoid normal main setup.
- Keep the round profile, source digest, listing digest and actual executed section multiplicities together; do not transfer a count from another LS1 or memory-program edition.
- Do not promote the tested single-block scalar helper into a general SHA3 API. Validate message length, round count, point range and lane count before calling helpers.
- Do not use Python -O for assertion-based source verification or the documented example. It removes generated-listing and final rho-event checks.
- The source has no request-size limit. Untrusted or large batches need a caller-enforced bound and separate process/time limits.
- No full graph, allocation, listing, compiled C implementation, target walk, projection search or numerical success law was executed or certified by these publication checks.
- setup may write the generated listing to the path in environment variable S7_PRINT, including in the eight-round edition. The bounded imported example never calls setup and does not write that file.
