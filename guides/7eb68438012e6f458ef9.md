# SHA-256 r37 low-memory program: the Y interface

Source: `research/checks_1015/pa_src/R37Y/experiments/lowm.py`

Public SHA-256: `83d92a9c2b968e8ca265ce4a2bab6d519f089ec3c95339224bb25089538da053`

## Reviewed usage contract

The source implements a memory-tight A0-variant procedure over a declared 222 classes containing 782,800 variants. Bit-plane tests screen W7 classes and W6 members, gathered groups of four form row-16 addresses, and two chunk tables screen those addresses before exact checks. This guide explains the pinned implementation and finite controls; it does not re-establish the full characteristic, success law or historical price.

## Source inspection and available execution evidence

static-source-review; Copied finite scalar/plane fixtures and mocked request dispatch only; no Env, member enumeration, online trial, SFS sampler or attack.

The audited small fixtures finish without constructing the original research environment. No default ledger, memory build, selftest, sampler or attack duration is promised. Full selftest checks hundreds of thousands of member objects and many additional arithmetic cases; it is not a browser-publication smoke test.

## Declared inputs

**Edition-specific layout**: The R37Y copy sends passing members directly into a four-entry group buffer, folds constant planes per ordered list batch, omits unused broadcasts and scans 13-bit chunks. Its modeled scan table has 8192 words and its slack is 2^-11. These are source-specific choices, not properties of every lowm.py.

**Safe inspection**: Use runpy.run_path without __main__ to load the copied module and inspect its declared constants. Import runs a small built-in plane-operation measurement but does not construct Env, enumerate the class lists or run a search. The example below prints declared counts, not a fresh exhaustive census.

**CLI selectors**: The positional words ledger, memory, selftest and attack select special modes; these are not --ledger or --selftest flags. Other arguments fall through to JSON stdin. No dedicated help command is implemented.

**JSON interface**: The request needs experiment_id and trials; each trial supplies trial and a string seed. IDs are matched with startswith(a0-sfs) or startswith(a0-online), not an exact allowlist. SFS rows run only when trial<128 and online rows only when trial<8. Unknown IDs or higher indices can yield null rows without an experiment error.

**Setup is work**: run_request constructs Env before inspecting the experiment ID or trials. Therefore an empty request is not the recommended lightweight smoke test: it still builds the row-16 chunk tables. memory and real online modes can additionally construct shared member lists.

## Outputs and interpretation

**Independent finite arithmetic**: Sixteen fixed-seed state/message fixtures agree with an independent 37-step compression reference; sixteen eight-step inversions recover their starting states. Four padded messages, including 64- and 128-byte inputs, agree with independent multiblock replay. Three full-64-step hashlib gates test the separate reference.

**Plane and filter controls**: 3,072 Boolean cases cover inversion flags; 1,024 four-bit add/subtract cases cover static and dynamic operands. Two 256-lane filter fixtures agree with their scalar definitions. Five scan patterns cross chunk and 64-bit boundaries. These do not enumerate all class members or prove an attack probability.

**SFS encoding**: A successful a0-sfs row serializes 24 big-endian words: eight common chosen-CV words followed by sixteen message words. The 96 bytes are a compression-test encoding, not an ordinary 96-byte message hashed from the standard IV. The real SFS routine checks its returned compression pair; no SFS search ran in this audit.

**Online-test encoding**: a0-online serializes 32 words, a common first block plus a second-block candidate using lstar(13). Its export branch requires zero local mismatch counters, not equal final digests. A mocked zero-mismatch run exported two distinct 128-byte messages whose 37-step padded digests differ. This demonstrates an interface boundary, not a failure in a real recorded witness.

**Attack output**: The separate attack routine checks that its two ordinary messages differ and that digest(ma)==digest(mb) before returning a collision. A null online-test row, a checked prefix pair and that fully verified attack result are different objects.

**Counted versus inferred work**: Mc accumulates declared category charges; the statistical ledger combines rational counts with a tail estimate and numerical stopping-budget calculations. A printed tight_up flag concerns rounding of its computed rational T, not proof of the underlying success or memory premises.

## Imports

- Python 3 standard library. The safe copied-module examples need only the downloaded pinned lowm.py.
- The finite publication checker uses a separately pinned project SHA-256 reference; it does not run that reference's random command-line selftest.
- The full experiment uses in-program class descriptors, masks and SHAKE-derived words. Those are not fetched from a server.

## Failure modes

- Unknown experiment IDs need not fail: the dispatcher can return schema-version-1 null rows. Process success alone does not establish that the requested experiment ran.
- Empty trials still construct Env. Use the copied-module examples for bounded inspection instead.
- Trial thresholds are upper checks only. Negative indices are not comprehensively rejected; validate the intended trial domain before invoking research modes.
- message_a_hex/message_b_hex have mode-specific meanings. Never treat every non-null pair as a standard-IV full collision.
- The printed selftest mismatch counts must be read. Several sections print bad counts without asserting that they are zero; successful process exit is not a blanket test verdict.
- draw_F7 uses the upper 224 bits modulo 65 for its branch. Even under exactly uniform source bits, residue zero has (floor(2^224/65)+1)/2^224 probability, not exactly 1/65. This tiny exact distinction does not itself establish practical bias or a SHAKE distribution theorem.
- The expectation and cap ledger retains inherited sampling assumptions. A finite constant sum or exact integer inequality cannot discharge them.
- Keep the retained credits and source edition. The R37Y streaming and per-batch folding changes must not be silently attributed to the R37Z accumulated-list program.
- Assertions disappear under python -O. Use normal Python for evidence checks.
