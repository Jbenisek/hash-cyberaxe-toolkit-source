# Value-seeded SHA-256 trails: pins, closing targets and precedence

Source: `research/tools/funnel/nld_seed.py`

Public SHA-256: `7a490fd7af31dddceff8c760e376eef6e56b50e11d4e2eda9f408ed40b19c56e`

## Reviewed usage contract

Write a characteristic from an explicit numerical pair. Selected VALUE_ROWS constrain agreeing bits to their actual value; differing bits retain their ordered u/n sign. This is a constraint writer, not a feasibility or collision verifier.

## Source inspection and available execution evidence

static-source-review; 12-disposable-CLI-cases-and-288-rows-compared; no-solver-run.

Two bounded SHA-256 traces plus text generation, proportional to R. The tested fixture uses R=20. No solver cost or attack probability follows.

## Declared inputs

**PAIR.txt**: Two W= fields of sixteen lowercase eight-hex-digit words and one or two chain= fields of eight words. A missing second chain reuses the first; different chains are permitted.

**R, FIX_TO, VALUE_ROWS**: R is the step count. State rows through FIX_TO are retained. VALUE_ROWS accepts comma-separated nonnegative indices and ascending inclusive ranges such as 7-8,12. Selected rows use actual agreeing values in A/E/W. The current range parser cannot express negative indices.

**OUT.xml, SETUP.xml**: OUT is overwritten. Always pass a disposable destination and explicit setup: the default setup is a machine-specific path. The suffix after the setup's char element is copied, including its search configuration.

**NOZERO environment**: Unset or empty normally enables final-four-row A/E equality. Any nonempty value, including the string 0, disables that branch. FIX or VALUE_ROWS takes precedence over that branch.

## Outputs and interpretation

**Generated XML**: A/E rows -4 through R-1 and W rows 0 through R-1. In unselected retained rows, - means equality, u means first=1/second=0 and n the reverse. In selected rows, equal bits become 0 or 1.

**Printed fixed/free/zero ranges**: A summary of nominal ranges, not a proof that all advertised zero rows are equality-pinned after branch precedence. Inspect the emitted rows.

## Worked examples

### Seed two value rows without touching the originals

Working directory: A new scratch directory containing a numerical pair, explicit setup and copies of nld_seed.py and mine_meter.py

```text
python -B nld_seed.py PAIR.txt 20 4 derived.xml 7-8 SETUP.xml
```

First remove NOZERO from the environment. Use a new derived.xml filename; the tool does not prompt before overwriting it.

Expected: Rows 7 and 8 use actual equal-bit values, rows -4..4 keep signed differences, the other middle A/E rows are free, and rows 16..19 are equality targets. All W rows are derived from the pair.

### Observe a selected closing row

Working directory: The same scratch directory

```text
python -B nld_seed.py PAIR.txt 20 4 closing-value.xml 18 SETUP.xml
```

Expected: Row 18 preserves the pair's actual A/E values and differences rather than forcing equality. The regression pair has differing bits at that row, demonstrating the precedence explicitly.

## Failure modes

- FIX or VALUE_ROWS can retain nonzero differences in a nominal closing row.
- NOZERO=0 disables closing pins; it is not a false Boolean value to this program.
- A descending range such as 5-3 selects nothing; a negative row argument fails parsing.
- The destination is overwritten, and the setup suffix may contain historical search settings.
- Different initial chains and arbitrary message words are not a shared-IV or legal padded-message certificate.
- Do not execute mine_meter.py directly for this example: its main program writes project-wide tables.
