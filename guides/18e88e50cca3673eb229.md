# SHA3 r7 LS1: message embedding, bit planes and 22-bit experiments (pos_ls1r7v)

Source: `research/checks_1015/pa_src/pos_ls1r7v/experiments/ls1.py`

Public SHA-256: `86e74bacdea157f510c8945406f4bde916f26cb9b32fd29f5d4642ea464cc9aa`

## Reviewed usage contract

Historical SHA3-256 seven-round experiment on a restricted family of 128-byte messages. Four directly readable message lanes encode a 256-bit point; two dependent lanes impose the linear structure. The bit-sliced step evaluates the reduced-round digest XOR a fixed output mask. A full-width equality would give a full collision, but both provided experiments target only the low 22 digest bits.

## Source inspection and available execution evidence

static-source-review; copied reference, embedding, plane/interpreter controls and mocked main; no generator, rho walk or projection search.

Normal main always runs setup and check_step before reading JSON, even for an empty, malformed or rejected request. Setup builds and allocates the seven-round graph; check_step performs two packed steps plus 512 scalar seven-round evaluations and checks selected lanes. proj-w256 then runs eight generated steps (284136 interpreted instruction applications under the declared program length) and retains 2048 keys per trial; reconstruction adds scalar work. rho-w22 has a 4000-iteration request-wide cap, up to 142068000 generated instruction applications under that same declared length, plus event handling and replay. These are structural ceilings/components, not CPU timings or a complete contest charge. Memory and bigint cost grow with trial count.

## Declared inputs

**Exact JSON request**: schema_version is 1, target_profile is sha3-256-r7-prefix-v1, and experiment_id is rho-w22 or proj-w256. event must equal the three-field dictionary with kind=digest-xor-mask, mask_hex=ffff3f followed by 29 zero bytes, and expected_hex=32 zero bytes. Even an extra event field is rejected. trials contains a caller trial identifier and a hexadecimal seed decoded with bytes.fromhex.

**Fixed source edition and constants**: This reviewed edition has source digest 86e74bacdea157f510c8945406f4bde916f26cb9b32fd29f5d4642ea464cc9aa. The source selects TRIAL=192 and declares a 35,517-instruction, five-byte-per-instruction program with SHA-256 ed4af4873b36404745c369ab75c615d7ef2efff7b724cbd64f6107118924452c. setup asserts that identity and a register peak no greater than 2304. The publication audit did not regenerate that graph or certify its allocation.

**Point domain and packing**: The documented embedding domain is 0 <= u < 2^256. Four 64-bit words appear directly in message lanes 1,6,4,9, while lanes 11 and 14 carry their pairwise XORs plus fixed constants. Each trial occupies 256 lanes; plane bit 256*t+l holds lane l of trial t. Python integers grow with the number of request trials; no request-size cap is enforced.

## Outputs and interpretation

**rho-w22**: Uses a 22-bit map: output planes 22..255 are zeroed after every generated step. It uses four distinguished bits, trail cap 128, at most 3000 starts per attempt, and an attempt time cap of 400 steps. The shared loop raises RuntimeError("no pair") if it exceeds 4000 iterations before all trials finish. Successful rows preserve caller IDs and contain two distinct 128-byte messages plus steps, trails, dead, attempts, stored and replay_evals observations. The final assertion checks only the low 22 digest bits.

**proj-w256**: Starts 256 full-width points per trial and evaluates eight steps without truncating the state. It retains their low 22 output bits and seeks the first repeated key with distinct reconstructed inputs. A found row returns two 128-byte messages and a zero-based step index. No match returns two null message fields and no observations. At most 2048 image keys per trial are examined; a repeated prefix is not a full collision.

**Different experiments, same prefix event**: The width-reduced walk and the full-width projection walk have different state distributions. Do not transfer a measured success rate between them or substitute either prefix result for 256-bit digest equality. XOR with the fixed output mask cancels when comparing two full outputs, but truncation discards information.

**Bounded publication evidence**: Five 24-round reference digests match hashlib.sha3_256, including padding-boundary lengths. Nine fixed embedding examples, 18 packed points, four interpreter opcodes and instruction encoding pass. Mocked main controls check IDs, null responses, validation ordering and six request rejections. No generated 35,517-instruction graph, rho walk, projection search, full collision or measured success rate was produced.

## Failure modes

- Do not use an empty request as a cheap installation test: substantial setup occurs before input validation. Use the bounded imported reference example instead.
- The two experiment modes certify only their requested 22-bit event when independently checked. The title collision search does not make their returned pairs full collisions.
- The no-pair exception aborts the request rather than returning partial results for its remaining trials. A malformed seed also prevents a complete response.
- Assertions enforce the generated-program identity, reference checks and rho output predicate. Python -O removes them; the documented example also requires normal assertion-enabled execution.
- The projection response is not rehashed in main. Recompute the intended reduced-round prefix event on the actual returned messages in a separate checker.
- Keep program hash, round profile, constants, point domain and request mode together. The six-round LS1C and seven-round pos_ls1r7t/pos_ls1r7v sources have separate identities, constants and runtime reports. Neither certifies later planner editions.
- Directory fragments are not protocol labels: this source explicitly implements sha3-256-r7-prefix-v1.
- The mocked response fixture replaces the digest/search functions; its synthetic messages are interface test data, not cryptographic witnesses.
