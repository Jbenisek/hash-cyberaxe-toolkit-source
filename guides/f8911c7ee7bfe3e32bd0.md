# Search-base generator: build signed schedule relations

Source: `research/publication_sources/FROM_HENSEL_1102_B32/lawbase.py`

Public SHA-256: `a6e1cf0c62710affe52a7f46640e0892cfeac7b23b2a13f0a3824112a7425d2f`

## Reviewed usage contract

Convert two raw SHA-256 message-word lists into signed schedule relations and a caller-selected state-freeing pattern. This guide documents the existing project helper delivered as FROM_HENSEL_1102_B32/lawbase.py.

## Source inspection and available execution evidence

static-source-review; portable two-case generator replay and rehashed refusal controls; no encoder or solver.

Two short word-schedule expansions and O(R) row-string generation. This does not price solving the XML query or finding a collision.

## Declared inputs

**Runtime and source**: Python 3 and the original lawbase.py source; only the Python standard library is used.

**Message-pair text**: A text file with one M1 line and one M2 line, each followed by sixteen valid 32-bit hexadecimal words. The existing LIFT_s9.check input is the worked example.

**Fresh output path and R/E parameters**: An output XML path, a requested row count R, and a caller-supplied last-active-row parameter E. The helper does not validate that E actually matches the schedule. The original writer overwrites the destination; use a fresh path.

## Outputs and interpretation

**Example header and negative rows**: The source-generated options are f=sha2, n=40 and w=32. The XML has state rows -4 through 39. The four negative-index rows require equal A/E relations, not explicit standard-IV values.

**Example rows 0-21**: Both A and E state relations are free, printed as question marks.

**Example rows 22-25**: A is equal across the pair; E is still free. These are the four transitional rows.

**Example rows 26-39**: Both A and E state relations are equal across the pair. Printed relations are not solved values.

**Example schedule words**: All forty W relations match the already replayed, independently expanded public seed-9 schedule, including the bit directions. The last differing W row is 29.

**Caller-validation limit**: The source also accepts E=28 for the same input. That changes the state template; it is not automatic validation of the intended finish law.

**Relations, not assignments**: A '-' relation means equality; '?' leaves the displayed state relation free. In W, 'u' and 'n' encode the two directions of an active bit. A printed XML relation is not a returned assignment. The input messages choose the signed schedule masks. The helper does not explicitly assign complete messages or a standard IV in the XML. Active signed bits constrain values, but the remaining equations are not solved by this helper. The generator expands a fixed 64 schedule words, then writes the requested prefix. This guide checks the concrete R=40, E=29 example; it does not certify every parameter combination or downstream encoder.

## Failure modes

- No SAT solver runs, state completion, compression collision check, legal-padding check, rank calculation or cost certificate is produced.
- The caller must supply valid message words and parameters, including the intended last-active-row choice. Argument validation is not implemented as a friendly input contract in the original helper.
- Equal negative-index differences must not be mistaken for explicit standard-IV initialization. Downstream encoder flags and absolute-value constraints require their own checks.
- The number of equal or free printed symbols is not a proof of an independent-condition count, a success probability or an attack score.
- The original source overwrites its output and does not provide a friendly input-validation interface.
