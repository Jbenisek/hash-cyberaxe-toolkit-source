# Template extractor: fit a real file and capture its slots

Source: `research/launch/port/extract.py`

Public SHA-256: `defe4d79fffa4ea40b37abab8f781b137f9ac2044d0d1faf0795ed24dd9cc5cb`

## Reviewed usage contract

Build an anchored regular expression from a template, match the entire real file, and save the captured slot values under a chosen row key. This tests actual fit to that template, not the correctness of the document's claims.

## Source inspection and available execution evidence

static-source-review; synthetic-fit-roundtrip-rejection-and-duplicate-slot-controls-passed.

Regex construction and whole-text matching, including variable-length block captures. No hard runtime bound is established for adversarial templates or inputs; use bounded trusted text.

## Declared inputs

**CLI**: python extract.py TEMPLATE REAL_FILE ROW_KEY OUTPUT_JSON . Reads UTF-8 text with universal newline normalization. Fixed text must match; s<number> slots use the limited numeric grammar, W slots capture one line, B slots capture zero or more lines.

**Numeric and slot limits**: The numeric pattern supports lowercase UUID/eight-hex fragments and a restricted decimal form with optional lowercase e and optional negative exponent. A bare negative value does not fit a numeric slot unless the minus sign belongs to fixed template text. Repeated slot names produce duplicate regex groups and fail.

## Outputs and interpretation

**Captured values**: On fit, replaces OUTPUT_JSON with one row-key object and prints an extracted-value count. Block captures become lists of lines; other captures remain strings.

**Non-fit**: Prints DOES NOT FIT and exits 1. An older OUTPUT_JSON remains untouched, so do not consume a stale extraction after failure.

## Failure modes

- A negative-number fixture is rejected despite being valid mathematical text; slot grammar, not general numeric validity, decides fit.
- Repeated scalar slots accepted by filltmpl.py are rejected here as duplicate named regex groups.
- The failed-fit path retains an existing output file. Check return code before loading it.
- A fit is not a raw-byte match because text input normalizes line endings.
- A fit does not certify a proof, experimental manifest, dependency law or claim price.
