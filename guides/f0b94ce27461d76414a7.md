# BLAKE3 b3r3s: grouped filters, paid replays and the kernel-versus-loop register boundary

Source: `research/blake3_r3/b3r3s/pkg/blake3/experiments/rho.py`

Public SHA-256: `8cb1b4256e971a796ee108f6c36a7f9afce4ea038b4f7f0f2968da71c08c3882`

## Reviewed usage contract

This three-round BLAKE3 candidate groups several seven-lane batches under a cheap combined filter, replaying flagged groups for detailed checks. It selects mixed distinguished points and packs table entries into 25 bytes. These are cost-engineering mechanisms, not a demonstrated full-output collision. Its JSON experiment still targets only 22 digest bits; its full-width attack and cost model are separate entry points.

## Source inspection and available execution evidence

static-source-review; copied finite helper, seven independent digests, exact ledger arithmetic and synthetic grouped-flow controls; no original cryptographic walk.

The example performs 10 seven-lane packed batches, 70 scalar digest checks and a 595-instruction liveness analysis, plus finite circuit/input setup. Grouped full-width work uses 16 batches per group and must pay flagged replays and recovery separately. Exact source-ledger terms and model spill counts are retained in the runtime report; they are not a freshly certified full attack price.

## Declared inputs

**Request contract**: Default JSON requires trials with seed and caller trial fields. Caller identifiers are preserved. Seeds are string-formatted with an attempt index before SHAKE-256; no hex-format validation is performed. schema_version, target_profile and event do not select or validate the target. The default trial uses n=22 and at most 60 attempts.

**Message and state convention**: Messages have 32 zero bytes followed by a 256-bit little-endian chain value: one 64-byte block, standard IV, counter zero, flags 11, three rounds. The chain uses the low n bits of the little-endian digest integer. Seven lanes occupy 36-bit slots, including four guard bits per 32-bit value.

**Mixed distinguished points**: At full width, the chosen source plan has s1=32, W=90 and Tp=400: low 32 bits must be zero and the next 90-bit window must be below 400. Groups have U=16. The 22-bit experiment instead has s1=4, W=4, Tp=12 and U=2. These are separate profiles; do not test one and silently price the other.

**Entry points and safe import**: Import builds the packed arithmetic circuit but does not run a search. The selftest() helper checks 70 fixed inputs. CLI --selftest additionally calls equivalence() on 24 seeds, running grouped and per-batch searches for each: 48 search calls. The documented example imports only the finite helper. --ledger, --loss and --spill compute declared models; unknown options fall through to the JSON experiment.

## Outputs and interpretation

**Pairs and counters**: Default non-null message fields indicate only a 22-bit event. observations.batches omits every budget-halted attempt. Even a normally returned search counts committed main batches, not all speculative group, replay or recovery evaluations. Synthetic constant-map controls produced one reported batch but three or four actual batch calls; another case reported four while making eight calls. These are accounting fixtures, not BLAKE3 collisions.

**Packed arithmetic and live values**: The kernel emits 595 arithmetic instructions and has 25 live values under the stated dying-operand reuse convention. Eight saved group inputs and the filter accumulator give a reported combined peak of 34. Seven fixed digests agree with an independent implementation; the imported 70-input helper passes. These controls do not prove every machine implementation or a success law.

**Register-sensitivity trap**: spill_ops(R) models the kernel, not the complete grouped loop. It reports 0,0,3,16,39 loads/stores at R=64,32,24,20,16. In particular, spill_ops(32)=0 while the separately printed grouped peak is 34. --spill passes R directly to that kernel model and adds its body allowance only if kernel spills are nonzero. Do not read the R=32 output as verification that the complete grouped algorithm fits 32 registers; a full-loop allocation and charge remain separate.

**Exact ledger, selected parameters and memory**: The source-selected full-width plan uses 26,791 entries and computes 1,048,559 bytes, 17 below its 1 MiB limit, including its stated code, counters and register file. Ledger terms are exact rational arithmetic once parameters are chosen, and conversion divides by 638. The choice of Tp and probability-loss figures use floating-point tail calculations. Recomputing the formula is not interval certification, complete cost proof or historical judge acceptance.

**Table entries and fingerprints**: pack_entry uses an 8-byte key, 2-byte trail number and 15-byte length. Legal inputs must be nonnegative and below 2^64, 2^16 and 2^120; its assertions check only upper bounds, so callers must also enforce nonnegativity. The full-width endpoint key retains only 64 bits and can alias distinct endpoints. A key hit triggers recovery, not automatic collision acceptance.

## Failure modes

- Do not copy the earlier candidate’s safe --selftest command into this edition: here that CLI flag also runs 48 original searches.
- The default experiment is 22-bit, not full-output equality. Independently verify any exported pair against its intended profile.
- Reported batches are not total kernel calls or charged operations; halted attempts and speculative/recovery work are not fully represented.
- The 34-value grouped working set and the 25-value kernel have different register requirements. Kernel spill counts alone do not settle full-loop prices.
- The declared memory figure includes code and register storage under this source’s instruction model, not Python container memory or host process RSS.
- The full-width table key is a fingerprint. Recovery failure is a possible Halt outcome, not a proven collision.
- Finite synthetic grouping checks and matching reduced experiments do not establish a field-sized random-mapping law or interval-certified abort probabilities.
- Use this source hash. b3r3lb, b3r3t and b3r3lc have distinct definitions and accounting; similarly named files are not interchangeable.
