# BLAKE3 four-round stack: inspect deferred stopping checks

Source: `research/blake3_r3/stack1020_r4/pkg/blake3/experiments/bsrho.py`

## Reviewed usage contract

This edition extends the fixed-prefix implementation to four rounds and reduces recurring control work by deferring limit checks until a batch passes its first gate. That optimization changes the stopping argument: an allowance for delayed checks is not an unconditional cap enforced by the loop. The source retains pivot/masked-walk credit to 6ae36351 and column-template credit to 10ce9f59.

## Source inspection and available execution evidence

static-source-review; Finite four-round arithmetic, local columns, table/recovery controls, compiler recipe and fixture ledger; synthetic deferred-limit boundary; no original search.

One finite generator/allocation pass, tested in a ten-second subprocess. No default probability optimization, prefix-selection scan or original collision attempt.

## Declared inputs

**Executed target, not folder name**: ROUNDS=4 and UNIT=846. The source lives under research/blake3_r3/stack1020_r4, but fresh independent four-round message fixtures verify the executed configuration. Standard IV, counter 0, flags 11, one 64-byte block. The first eight little-endian words are 80000000,00000000,80000000,00000000,70000000,00000000,00000000,00000000; x occupies the last eight. This is a public prefix, not a secret key.

**Circuit and local columns**: The same three-addend carry-pair design and four stored column circuits are regenerated for the four-round target. Greedy local template selection is not a globally optimal circuit proof. Iteration uses the source-specific output mask g(x)=f(x) XOR q.

**All-ones two-stage gate**: The first 12 stored planes are ANDed; an early rejection returns None. A passing batch is counted and tests the remaining 20 planes, possibly returning integer zero. None skips all limit checks; zero reaches them. Four branch fixtures preserve this distinction.

**Declared layout changes**: The model uses 775 registers,5,248 counter bytes, seven-byte quotient-filter slots with 18-bit trail IDs, and 32 bytes of prefix advice. Other instructions are nine bytes except a 64-instruction allowance for 37-byte large-immediate records. The generator image separately uses 36 bytes per declared instruction.

**Use the finite recipe**: The compiler-only command does not run the full-width planner, prefix chooser or collision search. --selftest and --choose-key are research runs; --ledger and --loss invoke numerical planning. They are not documentation smoke tests.

## Outputs and interpretation

**Four-round arithmetic and allocation**: 256 full-message digest fixtures match the independently pinned reference, alongside two reference known answers, two masked-walk steps, reduced-width fixtures and seven packed recovery lanes. All 23,479 allocated instructions pass structural checks across 12 chunks; two intentional mutations are rejected. Register extent=773; packed recovery=845 operations; no shared/dead gates for this source.

**Local column evidence**: Fresh tests under this source identity pass 6,144 all-variable and 1,536 constant-carry cases, including stored polarities and terminal carry omission. All 7,680 wrong-sum controls are rejected. These are local Boolean identities, not a complete probability or target-machine cost proof.

**Table and checkpoint behavior**: Three quotient-filter layouts agree with dictionaries through 36, 63 and 100 insertions and 100 queries each, with capacity/corruption controls. Twenty synthetic checkpoint cases test equal/unequal lengths, same-path starts, distinct endpoints and a length cap. Artificial returned pairs are not hash-collision witnesses.

**The deferred limit is not a hard cap**: The source increments the batch counter, calls stage1 and immediately continues if its result is None. Only passing batches test the next slice or B. With artificial B=1 and DELAY_MAX=3000, an always-rejecting oracle completes 3002 batches before our own fixture exception stops it. The source does not enforce B+DELAY_MAX for every possible trajectory.

**What that boundary does and does not mean**: The synthetic oracle is not BLAKE3 and supplies no real-hash frequency estimate. It does not refute an explicitly probabilistic delay argument. It does require a claim to distinguish an assumed/proved delay tail, what happens beyond it, and the relevant work metric. Do not describe the allowance as an unconditional timeout.

**Exact fixture arithmetic, not a default score**: With explicitly supplied B=10^35 and Tp=1500, the ledger sums exactly and includes B+3000 in its main and slice work. The body is 23,492, split gate charges 12/23, code 135,582 bytes and endpoint capacity 126,121. Declared setup/search phases are 246,735/1,048,516 bytes. These are model arithmetic, not measured Python/native memory or a validated success budget.

**Preprocessing and changed assumptions**: The generator counts 344,207 primitive calls per pass, with two passes charged. The ledger includes a declared 17,750,836,600-operation prefix-choice allowance. The full-width passing budget uses slack 1/1024, not the three-round edition’s factor 2. No historical prefix scan, new C/wasm replay, default optimization or numerical probability certificate was produced here.

## Failure modes

- The folder name is not the target: this source executes four rounds, unit 846.
- None and zero have different control-flow meanings at stage1.
- B+DELAY_MAX is charged by the model but not enforced as an unconditional loop cap.
- The artificial overrun fixture does not establish a real-hash overrun rate or invalidate a probabilistic proof.
- Do not transfer the three-round gate polarity, register allowance, counter layout or prefix-choice price.
- The supplied-B ledger is not an attack score or a success certificate.
- Reported instruction/storage counts are not native process-memory measurements.
