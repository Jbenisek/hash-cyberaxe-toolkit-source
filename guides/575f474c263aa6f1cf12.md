# BLAKE3 B9r6: same rolled circuit, revised probability accounting

Source: `research/blake3_r6/b9r6/pkg/blake3/experiments/bsrho.py`

Public SHA-256: `e0c9ac2a5ca6b3f6274f1f0144a88d917599ad8b6a911b0a25d76fb4078db670`

## Reviewed usage contract

B9r6 retains B8r6’s rolled six-round circuit, q=0 output convention and declared layout. Its complete source diff instead changes the probability accounting: it removes the previous trail-sum quantile helper, introduces a binned collision/detection-delay calculation and revises the remaining loss terms. It also changes default KAPPA_256 from 13 to 14. This guide reproduces the finite arithmetic and supplied-budget interfaces on the new source; it does not run or certify the revised numerical success model.

## Source inspection and available execution evidence

static-source-review; Fresh finite fixed-word interpreter, per-instruction visit counts, compiler/reference fixtures, artificial search/recovery and supplied-budget arithmetic. No numerical optimizer or original campaign..

One finite construction/compilation: 37,276 generator primitives and 19,803 stored main instructions. The isolated recipe is checked with a ten-second subprocess limit. No original walk, optimization or C build is launched.

## Declared inputs

**Exact target and message**: Six rounds, reference unit 1262, standard IV, counter 0, length 64 and flags 11. The message is 32 zero bytes followed by little-endian 256-bit x. Stale seven-round profile comments do not override ROUNDS=6; independent reference fixtures check the actual target.

**Loop structure**: KPRE=2 and LOOPS=4. A runs the two-round prelude, normalizes state polarities and loads message slots. B is one generic round. M permutes message slots between iterations. F performs final output XORs. The flat order is A, I, B, D, C, Z, M, J, F; control operations initialize, decrement, compare, exit and jump.

**Register and plane meanings**: The input uses 256 planes, each carrying 256 trials. State starts at register 256; message slots at 768; loop temporaries at 1312. The emitted program reaches 1,827 registers within a declared 1,856-register file. Input and output polarities are upright; qint and all eight q words are zero.

**Supplied-budget accounting**: The audit supplies Tp=22, B=10^35, kappa=13 and slice size 2^48, replacing numerical budget selection. This is intentionally not the source default kappa=14. Equality with the B8r6 fixture numerator checks unchanged accounting under equal inputs; it does not equate optimized plans or success probabilities.

**Safe compiler recipe**: Use the command below with the pinned download in a disposable directory. It constructs the finite program and prints executed operations, stored instructions and register extent. It does not start a walk or optimizer. --selftest includes actual collision attempts; --stats runs campaigns; --ledger and --loss invoke numerical planning. --gen-c only emits source.

**Other interfaces are different tasks**: The retained organizer routes include reduced-width target/control experiments and projected-output statistics. Neither is the compiler recipe. Their full statistical laws and general dispatch contract are outside this bounded review.

## Outputs and interpretation

**Stored versus executed instructions**: A=10,550; B=8,416; M=576; F=256. Stored count is A+B+M+F+5 = 19,803. Executed count is A+1+4(B+3)+3(M+1)+F = 46,214. The independent interpreter checks every flat instruction’s visit multiplicity, including control operations.

**Fresh finite arithmetic**: 256 complete-message digest fixtures agree with the independently pinned reference, whose empty/abc known answers are checked. The source interpreter, compiled step and independent fixed-256-bit interpreter agree. Two chained steps, 18/20-bit fixtures and seven packed recovery values pass. Changed final-output wiring and a changed loop count both fail comparison. This is not a universal compiler proof.

**Packed recovery is a separate circuit**: Recovery uses 1,299 operations per packed batch and seven 36-bit lanes. There are no eight final output-mask XORs because q=0. The main loop’s 19,803/46,214 distinction must not be substituted for this recovery circuit’s charge.

**Declared layout**: Uniform 36-byte records give 804,456 bytes of total code, 16,828 ten-byte endpoint records, a 59,392-byte declared register file and 16,384 bytes of counters/copies. Setup and search phase totals are 936,520 and 1,048,512 bytes. These are source-model quantities, not Python/native memory measurements or a complete machine-handler certification.

**Exact fixture numerator**: N=13189678526946937664065952745255267623686 word operations for the supplied budget only. The main batch costs 46,251 = 46,214 + 34 filter + 3 outer-loop operations. Setup charges 200 times (2 times 37,276 generator calls + 19,803 stored instructions), plus the fixed allowance. The ledger separately includes slices, stage-1 hits, table events, cuts and two-pass recovery.

**Packing and recovery boundaries**: The endpoint stores a 64-bit key and 16-bit trail ID; the 17,086-start envelope fits 65,536 field values. Four nonnegative record roundtrips pass and two upper overflows are rejected. Negative inputs are accepted and alias unsigned maxima, so callers must enforce nonnegative fields. Six one-batch artificial-map cases and four explicit recovery graphs pass; recovery graphs use 5, 7, 4 and 2 calls. They are not hash-collision witnesses.

**Numerical helper and cache boundaries**: The loss helper retains fixed 122/256-bit scales; a reduced-width wrapper does not pass n through. A synthetic oracle confirms the budget cache omits Sb: changing that parameter can reuse an old budget until the cache is cleared. No numerical probability helper was executed and no default-plan impact is inferred.

**What remains outside this audit**: No embedded C compiler, retained WebAssembly artifact, whole-script selftest, original search, statistical campaign or numerical success theorem was replayed. The existing three-round generator bundle cannot certify this new main-loop source. The declared layout and fixture numerator are not an accepted attack score.

**Same stored main body does not mean identical total code**: The main listing remains 19,803 instructions, while total declared code rises from 795,996 to 804,456 bytes. Recovery grows from 1,064 to 1,299 operations; its 235 extra uniform records account for the 8,460-byte difference. One extra main loop visit adds 8,416+3+576+1=8,996 executed operations. All six-round numerical claims here use the new source-specific report.

**Revised numerical law remains a separate review**: The complete diff removes _zq, EPS and HZ. The new _lossq accepts fine=20000 and coarse=2000 bin counts, accumulates a detection-delay sum, and returns collision, delay, own_trail, long_partner, age_cap, disturbance, finished_count, cut_halt, key_false_match, table_capacity and tiny losses. Its full-width constants remain fixed. These source observations and mocked wrapper controls are not an independent proof of discretization direction, numerical rounding, success probability or the fixed-target assumption.

## Failure modes

- Stored instruction count is not per-trial executed work; include loop control and message permutation.
- This main-round loop is not B4F’s packed-recovery loop.
- Do not carry a nonzero output mask from an unrolled edition into this q=0 program.
- The 1,827 used registers and 1,856 declared registers have different roles in the ledger.
- The supplied-budget numerator is not a default, optimized or success-certified price.
- Reject negative record fields and isolate caches when varying omitted parameters.
- Finite Python equivalence does not establish embedded C/wasm equivalence or universal generator correctness.
- A historical source comment or another package’s adjudication does not establish this edition’s status.
- Do not mistake the kappa=13 fixture for this source’s kappa=14 default, or transfer B8r6 probability conclusions to the revised helper.
