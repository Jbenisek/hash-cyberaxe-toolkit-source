# BLAKE3 b3r3lc: price prefix selection, advice and endpoint storage

Source: `research/blake3_r3/b3r3lc/pkg/blake3/experiments/rho.py`

Public SHA-256: `90e3ddb5882413e7022cf54b4dccc29d50cb12337c8c51678fb4651584dd4e8e`

## Reviewed usage contract

This edition retains the 128-byte fixed-prefix family and 593-instruction kernel, but explicitly charges the prefix-selection formula, reserves 32 bytes for nonuniform advice and rounds the endpoint table to whole storage words. These are inspectable accounting corrections. The finite audit checks their arithmetic and interfaces, not historical scan execution, minimality, a success law or complete instruction-level pricing.

## Source inspection and available execution evidence

static-source-review; copied finite helper, independent two-block digests, one known prefix candidate, synthetic scan/walk controls and mocked experiment routing; no original search campaign.

The first example computes one prefix chaining value at import, builds a finite circuit, runs 10 seven-lane batches and 70 scalar checks, then checks two local columns. The second performs finite layout/parameter arithmetic, including numerical threshold selection. Neither executes the 10,768,619,077-candidate historical scan or a cryptographic walk.

## Declared inputs

**Exact two-block message**: M(x) is a fixed 64-byte prefix P, 32 zero bytes and a little-endian 256-bit x. The first block uses the standard IV, counter 0, length 64 and flags 1; the last block uses its chaining value, counter 0, length 64 and flags 10. Both use three rounds. Do not hash only the last block or substitute single-block flags 11.

**Retained prefix and independent check**: PREFIX_I=10768619076; P has words [PREFIX_I mod 2^32, PREFIX_I >> 32, 0, ..., 0]. The independent reference reproduces its chaining value and A1+B2=0 mod 2^32 in the final block's first-round zero-message columns. Seven complete 128-byte digests agree; 14 controls that omit or mutate the prefix differ. This verifies one selected prefix, not first-hit minimality.

**Default and named events**: Missing or unknown experiment_id selects the default 22-bit route with up to 60 attempts. rho-n32-a/b/c use the 32m profile and numeric trial ID <24; rho-n40-a/b/c/d use 40m and numeric trial ID <2. Eligible named trials get one attempt. These gates are not list-position or unique-ID limits: negative and duplicate eligible IDs run. String IDs raise TypeError. Target metadata is not validated.

**Keep profile and price together**: Mixed 32m/40m profiles use U=16, W=4, Tp=12 and s1=8/12. Their L values are 1024/3 and 16384/3. ledger(32) and ledger(40) accept no mixed key and price default profiles, not the named experiments. The full-width profile uses s1=32, W=90, Tp=401 and 26,836 table entries.

**Scan bounds**: scan_prefix(k,start,limit) checks consecutive candidates and treats limit as exclusive. A hit counts the successful candidate; exhaustion counts every candidate examined. Five synthetic fixtures cover empty ranges, first/last included hits, a hit exactly at the excluded limit, and no hit. The only real candidate checked was the already-retained PREFIX_I with limit=PREFIX_I+1.

**Safe example versus search commands**: Imported selftest() checks 70 fixed inputs; --layout performs finite numerical layout work. CLI --scan defaults to an unbounded reduced-condition search at k=16. CLI --selftest also runs 48 original search calls; --h1 runs 66 mixed-width attempts. None of those three campaigns was run. Do not use them as cheap documentation smoke tests.

## Outputs and interpretation

**Explicit preprocessing formula**: SCAN_PER=5+16+638+56+2=717 declared operations per candidate, with one final store. scan_ops() defaults to PREFIX_I+1 candidates, so its exact formula is 10,768,619,077 x 717 + 1 = 7,721,099,878,210 word operations. That term appears in every checked ledger, including reduced widths. This is exact arithmetic of stated allowances, not an independent proof of each allowance, an execution receipt or proof that no earlier candidate works.

**Advice and rounded storage**: ADVICE=32 bytes is subtracted before choosing full-width table capacity. The 26,836 entries use 670,900 logical bytes, rounded to 20,966 whole 256-bit words or 670,912 bytes: 12 padding bytes. Code, counters, register file, advice and rounded table total exactly 1,048,576 bytes. total_in_words misleadingly contains bytes. This is the abstract instruction-model layout, not Python object memory or process RSS.

**Concrete memory map**: The finite audit checks contiguous main regions, nonoverlapping table arrays, aligned key storage and counter labels covering words 0 through 63 exactly once. Table arrays allocate 8 bytes per key, 2 per trail and 15 per length. These address and coverage checks do not establish that all live program state has a valid semantic register allocation.

**Kernel versus full-loop accounting**: The independently compared finite kernel has 593 instructions and 25 live kernel values, or 34 with saved group inputs and the filter accumulator. Kernel spill-model outputs at R=64,32,24,20,16 are 0,0,3,16,39. Zero kernel spills at 32 registers is not a complete-loop allocation proof. Exact rational ledger terms follow floating-point parameter selection; loss estimates are not interval-certified probabilities.

**Skipped, halted and completed observations**: Skipped IDs return attempts=0. A named attempt halted after work returns attempts=1 and halted=1 but resets batches, stage2, finished and replays to zero. Normal attempts copy those counters but omit cut. Default run_trial omits halted-attempt batches too. All seven named routes and these outcomes were checked with mocked searches; zero counters do not mean zero work.

**Synthetic flow controls are not collisions**: Eight constant-map fixtures check grouped versus per-batch control flow at small caps; their synthetic pairs are not BLAKE3 collision witnesses. Reported batches can omit speculative and recovery calls. Neither these controls nor independent digest agreement establishes full-width success or validates the program's statistical extrapolation.

## Failure modes

- A working prefix does not prove it was found by the declared scan or that earlier candidates fail.
- Exact multiplication of a declared 717-operation allowance is not an instruction-by-instruction proof of that allowance.
- The full scan charge appears even in reduced-width ledgers; do not interpret it as measured setup work for one reduced trial.
- Do not omit the 32-byte advice word or the 12 padding bytes when quoting this edition's abstract memory use.
- Do not equate a gap-free layout or complete counter-label coverage with semantic register allocation.
- Do not price mixed experiments using default-key ledger(n), or treat numeric-ID skips as failed attempts.
- Zeroed halted counters and normal batch counts are not complete physical-work measurements.
- CLI --scan, --h1 and --selftest launch searches; use the explicit finite commands documented here.
- A reduced-width pair is not a full-output collision; independently verify exact messages and the selected target.
