# BLAKE3 B4B/B4C: save endpoint space, recompute trail lengths

Source: `research/blake3_r4/b4c/pkg/blake3/experiments/bsrho.py`

Public SHA-256: `9cc4c43839337a10ac5beae5d8ca907ee16496d028741f97ff652f7dae627013`

## Reviewed usage contract

B4B trades recovery work for table space: save the start’s trail ID but not its length, then walk both trails again when an endpoint key repeats. B4C contains the same distributed source bytes. These are implementation contracts for two exact copies, not two separate discoveries. The source retains credit to jungjipdo’s 6ae36351 for the pivot adder and masked walk and to 0a9640ed / 3356413f for the surrounding implementation.

## Source inspection and available execution evidence

static-source-review; Fresh finite digest/allocation, field packing, artificial search/recovery and explicit-Tp ledger; no original campaign or retained-generator execution..

One finite circuit construction and allocation, checked with a ten-second subprocess limit. No planner optimization, loss allocation, original collision attempt or statistical campaign.

## Declared inputs

**Target and masked walk**: Four-round BLAKE3 on the complete block 32 zero bytes followed by little-endian x; standard IV, counter 0, length 64, flags 11, unit 846. The stored walk is g=f XOR q. Fixed q preserves the collision predicate, not a full-width probability law.

**Endpoint and register changes**: Each ten-byte entry stores a 64-bit key and a 16-bit trail ID. No length is stored. The declared register file drops from 1,024 to 800 words, while allocation still needs 771. Instructions remain 36 bytes each, not the later compact five-byte format.

**Two recovery passes**: First, trail_lengths follows both starts until each first reaches a distinguished point, recording its length; it halts if capr steps are insufficient. Second, recover aligns the longer trail and advances both to find a predecessor pair. The caller is responsible for the shared-endpoint premise. A repeated truncated key by itself is not a full collision.

**Execution boundaries**: The example only builds and allocates the circuit. Original --selftest and --stats routes launch real attempts and were not run. The reduced loss helper requests a billion-element structure; the audit guarded that boundary before allocation. --gen-c prints embedded C, not a newly built artifact.

**Two exact copies**: The b4b and b4c source downloads have the same SHA-256 and were compared byte-for-byte. Pure copied-source fixture results apply to those exact bytes; they do not certify different surrounding package manifests, environments or historical runs.

## Outputs and interpretation

**Arithmetic and allocation**: 256 independent full-message digest fixtures, two reference known answers, two masked steps, 18/20-bit fixtures and seven packed recovery values pass. Structural checks cover all 24,422 allocated instructions and reject two mutations. Register extent is 771; packed recovery has 836 operations; the full-width generated program has no shared/dead gates.

**Exact declared memory arithmetic**: Body=24,459, code=954,072 bytes and endpoint capacity=5,251. Declared setup/search phases are 1,042,104 and 1,048,566 bytes respectively. The latter is ten bytes below one MiB and respects the source’s eight-byte spare rule. The saved-length B4 predecessor had 1,744 endpoints. These are model quantities, not native process-memory measurements.

**Supplied-plan ledger**: Every integer part is recounted for the explicit fixture Tp=22, kappa=11 and 5,251 entries. Recovery is charged at 2 times capr times (836+64), plus 600. No default optimization, full-width loss or success-certified score is claimed. A larger table is not by itself evidence of a lower valid price.

**Fresh two-pass recovery evidence**: Six one-batch constant-map cases cover a returned artificial pair, a miss and four budget exits. Four finite graphs cover equal and unequal lengths, shared paths and a length cap. Their total oracle calls are 5, 7, 4 and 2 respectively, including rediscovery. The graph’s distinguished-point test is explicitly mocked; none is a BLAKE3 collision witness.

**Packed-field domain**: Four nonnegative roundtrips and two upper-overflow controls pass. Negative inputs are accepted and -1 decodes to the unsigned maximal key and trail fields. Internal IDs are nonnegative, so this does not prove a default failure; external callers should validate their own domain.

**Loss-allocation guard**: The reduced plan has cmax=1,000,000,000. The helper requests 1,000,000,001 terms; the test intercepts range and raises before materializing them. No enormous allocation or original numerical loss run took place.

**What this review does not transfer**: B4’s separate retained-wasm comparison was not rerun for these source editions. The unchanged arithmetic generator does not make every package artifact or price interchangeable. Organizer dispatch and projection meanings are source-reviewed, not freshly exercised in these tests.

## Failure modes

- A 64-bit key plus 16-bit trail ID is not the later 63/17-bit compact format.
- Do not transfer the stored-length predecessor’s one-pass recovery charge.
- The supplied parameter ledger is not an optimized or accepted price.
- Guard the reduced loss route before it requests a billion terms.
- Validate negative packed fields and preserve the recovery preconditions.
- Exact source-copy equality does not certify surrounding manifests or historical environments.
- Reference fixtures and artificial graphs do not prove full-width random-function behavior.
