# Check the small-field radix-3/radix-2 transform layout

Source: `research/poseidon/orchard/exec_r2c/src/pfa_check.py`

Public SHA-256: `bfe828a480c84fe49e416cda4212ab9942c34d0651c6732aa868a624487a53c6`

## Reviewed usage contract

A finite, self-contained diagnostic comparing a twiddle-free three-row layout against direct polynomial evaluation. It tests the indexing algebra used by the Poseidon transform work, not a Poseidon hash, collision, optimized transform kernel or production-field implementation.

## Source inspection and available execution evidence

static-source-review; small-field-seeded-and-complete-basis-replay-passed.

The fixed defaults contain exactly 3024 direct-evaluation summands, 1008 row-transform summands and 252 three-point-stage summands: 4284 inner summands in total, plus root selection, modular exponentiation, indexing and control work. Each root-selection loop is bounded by q-2 candidate iterations; the largest transform has N=48. These are source-derived iteration counts, not a complete primitive-operation price or runtime measurement. The optional test(q,a) function can become quadratic in N and is not a license to use production-size parameters here.

## Declared inputs

**Built-in field and size cases**: The script unconditionally calls test(q,a) at (73,2), (73,3) and (193,4). It sets n=2^a and N=3n, giving total transform sizes 12, 24 and 48. There is no argument parser, input file or IV. Command-line arguments do not select a different case.

**Random coefficient vector**: Each case draws one length-N vector using Python random.randrange(q). No seed is set in the script. A caller can seed the standard random module before importing it; importing executes all three cases. This samples three vectors, not all possible polynomials.

## Outputs and interpretation

**Three standard-output diagnostic lines**: Each line includes q, a, c0, a theta-order check and a layout-equality Boolean. The layout comparison checks every one of the N evaluation positions for the selected vector. The printed theta-order check alone is only theta^(N/2) != 1, not a complete independent order certificate.

**Filesystem/process effects**: The source performs no file reads or writes, launches no child processes and contacts no network service. It prints diagnostics and consumes the process random generator. Python may normally create an import bytecode cache; the examples use -B to suppress that interpreter side effect.

## Imports

- Python 3.8 or later: the modular inverse call pow(3,-1,n) requires this support.
- Python standard-library random module only; no project data, external constants or third-party package.

## Failure modes

- A layout mismatch prints False but does not raise or set a failing process exit code; exit status alone is insufficient.
- There is no --help mode or CLI parameter selection. Importing the module also runs the three tests.
- The original script checks only one random vector per case. The separate publication wrapper checks every basis vector in those three small fields; neither validates the Pallas-field or optimized C implementation.
- Custom test(q,a) calls require suitable prime q and N dividing q-1. The source does not comprehensively validate primality or arbitrary custom inputs.
- Do not use Python -O for verification: it disables the initial divisibility assertion.
- The printed theta-order Boolean tests only one divisor. Do not cite that single Boolean as a complete primitive-root proof.
